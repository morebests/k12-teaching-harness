## Required project reading

Before starting any project task — planning, research, implementation, review, or a scope change — read [README.md](README.md). It is the authoritative entry point for this repository's purpose, delivery scope, route, principles, and external responsibilities. Re-read it when those sections change.

Before analyzing, implementing, or reviewing a teaching capability, Context/LLM behavior, knowledge integration, or runtime mechanism, read the task-routing table in [.scratch/skills-harness/assets/index.md](.scratch/skills-harness/assets/index.md) and follow every applicable branch. Read the linked detailed flow and relevant upstream source; use the index to find evidence, not as a replacement for it.

## Work state and requirements

Before reading or editing tickets, specs, or wayfinder maps, read [docs/agents/issue-tracker.md](docs/agents/issue-tracker.md).

- During wayfinder, read [.scratch/skills-harness/map.md](.scratch/skills-harness/map.md), then the selected decision ticket and its relevant dependencies.
- Before implementation or review, read the feature's `spec.md`, the originating implementation ticket, and the decisions and evidence they reference. Keep candidate research distinct from accepted requirements.
- Apply README's route-deviation and evidence principles when a task conflicts with the agreed direction. Record explicit route changes in README and the affected decisions; keep ordinary work moving within existing authorization.
