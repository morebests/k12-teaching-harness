# 教学 Harness 的知识使用约定

状态：依据 [README](../../README.md) 的既定职责固化的数据消费与证据约定。适用于课程设计、四项教学能力、Context 装配和质量验证；具体工具接口与存储实现仍由对应执行规格确定。采用依据与范围见 [研究转用决定](../../.scratch/skills-harness/issues/13-reference-research-transfer.md)。

本地知识数据由外部项目提供。本文件规定 Harness 如何保持其身份、语义和证据边界，不规定下载、导入、数据库产品或外部服务的内部实现。

## 身份与版本必须随内容进入 Context

| 对象 | 使用约定 |
| --- | --- |
| 标准目标 | 按 README 固定使用 CCSS；数学采用 CCSS Mathematics。由 Harness 固定框架身份和所用数据版本，再解析具体标准；保留框架身份、图内标识、CASE 身份和代码，不将框架选择交给教师或模型，不以州版同代码条目替代 |
| 知识节点和关系 | 保留外部服务返回的稳定身份、来源和数据版本。图内 `identifier`、CASE UUID、出版者标识分别保存，不互相覆盖，也不靠标题或代码推断为同一个对象 |
| 课程与材料参考 | 保留来源课程／版次、对象、语言、受众、内容版本及载体的区别。同名课、同一页面的不同受众内容或页面与附件，不自动合并 |
| 本项目设计 | 使用自己的设计身份与版本，关联采用的来源和理由。原创任务、模型提出的联系、翻译和修改均保留派生身份，不写成图中已有事实或出版者原文 |
| 本次运行 | 能定位模型实际使用的目标、图路径、材料、规则与版本；来源更新时检查影响，不能换入新版内容后沿用旧版质量结论 |

官方标准定义区分框架与条目；标准代码只在其上下文中标识条目。[官方标准 schema](https://docs.learningcommons.org/knowledge-graph/schema-reference/standards) 本项目在数据接入时解析并固定 CCSS 框架；通用搜索若返回州框架的同代码条目，知识工具仅保留属于所固定 CCSS 框架的结果。若无法解析 CCSS，报告具体数据问题，不自动换用州框架，也不向教师发起框架选择。

当前研究样本中，`1.G.A.1` 的图内标识和 CASE UUID 是不同值。样本及查询见 [本地图研究](../../.scratch/skills-harness/assets/learning-commons-integration.md#k2-几何的本地实测) 与 [证据基线](reference-baseline.json)；这些样本标识不能成为生成其他课时的默认值。

## 按关系自己的含义查询和解释

| 关系及方向 | 教学使用约定 |
| --- | --- |
| `LearningComponent → supports → Standard` | 用细粒度技能／概念理解目标；标准所支持的 LC 通过入边取得。LC 不自动规定课程顺序 |
| `Standard → buildsTowards → Standard` | 基础到后续学习的支持联系；找基础查入边，找后续查出边。不是必须逐一通过的严格先修门槛 |
| `Standard → relatesTo → Standard` | 非顺序概念联系；可以提出整合或复习候选，不能改写成依赖。保留实际存储方向，检索双向不等于伪造反向来源边 |
| `Framework/Item → hasChild → Item` | 表达标准框架层级；分组节点与教学目标分开，不能从标准树直接生成课程树 |
| `Curriculum element → hasPart → constituent` | 表达组成；树上的位置不自动证明教学先修，也不能保证已取得正文、图形或附件 |
| `Curriculum element → hasDependency → prerequisite` | 该来源课程对前提元素的依赖，找前提查出边；与 `buildsTowards` 方向及含义分别处理。本项目课程安排另有自己的教学理由 |
| `hasReference` 与 `references` | 保留为不同关系；按实际对象查询跨层或跨课引用，不将引用误写成组成或必修先后。获取课程 Context 时按任务检查有用的非树关系 |
| `Curriculum element → hasEducationalAlignment → Standard` | 保留原始对齐角色；教授、使用先备、为后续准备、练习／评测的用途不压成一个布尔值。对齐本身不证明学习机会或理解已经发生 |
| `State standard → hasStandardAlignment → CCSS standard` | 上游存在的跨框架关系；本项目只使用 CCSS，不将州标准映射纳入查询、Context 或覆盖验收 |

语义依据：[学习进阶](https://docs.learningcommons.org/knowledge-graph/schema-reference/learning-progressions)、[课程关系](https://docs.learningcommons.org/knowledge-graph/schema-reference/curriculum)、[标准及 crosswalk](https://docs.learningcommons.org/knowledge-graph/schema-reference/standards)。当前物化实例与详细差异见 [本地研究](../../.scratch/skills-harness/assets/learning-commons-integration.md)。

多跳路径应保留中间节点、每条边和本次选用理由；遍历得到的间接联系不冒充来源中的直接边。模型提出的新联系可以参与设计，但必须标明推断并接受适用性检查。

## 数据可用、内容完整和教学适用分别判断

1. **按外部提供的版本与能力使用数据。** 文档模型、原始数据和本地规范化投影可能有不同物理字段。对缺列或空值先按该投影的元数据解释，不能直接写成上游没有该信息；Harness 不自行重建导入流程。
2. **按任务检查需要的具体内容。** 课程目录、对齐和正文各是不同依据。只取得结构元数据时不能宣称已读原任务；模型可以生成原创任务，但其来源身份必须明确。正文、图形、附件及其版本相容性在本次实际使用范围内检查，不要求先解决全库内容工程。
3. **用实际标准确定覆盖。** 使用所固定 CCSS 框架的目标原文与完整范围；州标准、相似度和样本关系不能代替它。本项目按课程层级分配目标，课时与适配保持分配到自己的数学工作；LC 查询与进阶遍历中的标准端点也限定为 CCSS。
4. **关系为空只说明该次查询的结果。** 它不证明学生无需前置支持，也不授权补造来源边。记录查询范围、数据版本和结果，教学推断另存；执行失败与成功空结果分别处理。
5. **参考用途与可见范围随对象保留。** 教师、学生、家庭和内部检查的内容按用途装配；本地可读不意味着可以向任意模型调用或用户展示。沿用外部明确提供的对象使用范围，本项目不代替外部系统建立权利或身份管理平台。

导入项目的数据库、爬虫、页面解析、发布流程和“禁止所有正文进入模型”的产品决定，不属于本项目的默认技术约束。我们按 README 的当前授权研究参考并比较固定候选，记录参考何时进入、用于何种工作及设计影响；独立课程组织不等于未接触参考，具体来源内容的使用范围仍随来源保留。

## 共同模型与个体状态

LC／LVN 的 `LearnerModel` 按学段和学科组织因素与策略，可以作为多个学生共用的建模基础；关联到具体学生并承载其个人状态，就可以形成个体 Learner Model。这里区分的是共同结构与个体实例，不要求另造一套互不相干的模型。LC／LVN 官方资料定义了研究因素、关系与策略；上述个体实例是本项目的建模解释，不据此声称上游已经提供学生状态存储或更新算法。[LC 官方定义](https://docs.learningcommons.org/knowledge-graph/schema-reference/instructional-practices)、[Digital Promise 模型说明](https://lvp.digitalpromiseglobal.org/model)

同一结构下，不同学生可以有不同状态；同一学生的状态也可随时间、任务条件和证据改变。LC／LVN 的因素涵盖学科、认知、社会情感和学习背景，并非都属于知识技能，因此不能一律表示为掌握度。[Digital Promise 模型说明](https://lvp.digitalpromiseglobal.org/model)

以下是消费语义示例，不是上游官方的学生状态 schema：

| 共同定义或依据 | 个体实例中使用的信息 |
| --- | --- |
| 数学知识与技能 | 对应目标的掌握／表现及证据，保留适用任务、支持条件与不确定性 |
| 注意、动机、学习环境等因素 | 相关观察、情境或状态；采用适合该因素的含义，不统一折算为掌握百分比 |
| 策略与因素的研究联系 | 选用理由、是否实际使用及观察到的结果；一般研究支持不能写成对该学生已经有效 |

例如，共同结构列出 working memory，允许个体实例引用这个维度，但不表示当前学生存在工作记忆困难。仅关联学生身份而没有观测时，个人状态可以未知。使用策略时关联实际输入证据、适用对象、选用理由与内容变化；设计假设保持为假设，不填造学生事实。

个体模型的建立、状态估计和更新由外部系统承担。Harness 按本次教学任务使用相关共同定义、个人状态及其证据，形成教学设计，并返回所依据的状态与设计理由；不在本仓库重新实现学生建模系统，也不把整份模型无差别装入每次 Context。

## 哪些固化为约定，哪些保留为证据

| 内容 | 固化方式 |
| --- | --- |
| 身份、关系语义、版本延续、来源与推断的区别 | 本文件；相关实现与评审通过材料索引读取 |
| 学习组件、共同研究模型与个体实例的关系 | [CONTEXT.md](../../CONTEXT.md)；只放领域定义 |
| 外部研究文件版本、数据快照元数据、具体 SQL 与观察结果 | [reference-baseline.json](reference-baseline.json)；文件 SHA-256 用于发现来源变化，查询只证明记录的样本 |
| 数学案例、范围计数、官方定义核查和来源差异 | [本地图研究](../../.scratch/skills-harness/assets/learning-commons-integration.md)；不将计数或某版本字段集合写成永久接口 |
| 模型实际获得的 Context、查询结果和产物检查 | 后续执行规格与实现记录；文档和基线清单不能代替运行行为 |

证据基线是定位清单，不包含外部全部文件或完整数据快照。原始研究继续留在来源仓库；在其他环境复核时，需要相应文件或来源，并核对内容摘要。没有相符来源时应明确证据尚未复核，不能只凭路径存在宣称一致。

## 应进入后续验证的反例

| 反例 | 应观察到的行为 |
| --- | --- |
| 搜索返回 CCSS 与州框架的同代码条目 | 按已固定的 CCSS 框架身份过滤；州版不进入设计 Context，CCSS 缺失时报告数据问题，不让教师选择替代框架 |
| 把 `buildsTowards` 当作全部强制先修，或倒着查询课程依赖 | 关系解释与路径检查能指出错误；不通过补更多练习掩盖目标漂移 |
| 只沿 `hasPart` 取课程内容 | 需要关联任务时能按非树引用取回；不会把未遍历到的活动判为不存在 |
| 把 `assess/practicing` 擅自改成工具示例中的枚举拼写 | 保留源值与明确映射；未知值不静默改写为已有类别 |
| 模型编写新任务或图形说明后标为 IM 原内容 | 保留原创／派生身份与所用参考，校验失败的来源声明不得沿用 |
| 仅关联学生到 LVN 模型，就给全部因素填入已观测状态或掌握度 | 允许建立个体实例，但无证据的状态保留未知；因素采用各自适合的状态含义 |
| 两名学生共用同一模型结构，却忽略各自不同的学习证据 | 依据与当前目标有关的个人状态选择支持与任务；共同结构不要求产出相同，也不要求所有差异都触发修改 |

本文件提供后续验收依据；本轮完成来源核查及有限只读查询，未实现接口或运行模型质量测试。
