补齐前先读 [全年课程到实际教学的交互方案](teaching-workspace.shape.md)：以课程内容组织导航，展开全年、单元／课段与课时三类视图，并保留各能力自己的参与方式。该 Shape 已获准构建，并落实到同一 HTML；[本轮走查](prototype-build-walkthrough.md) 与下文旧版局部记录分别保留。本次定稿依据用户指令，不将开发 Agent 走查记录改写为真实教师使用证据。

本轮定稿按 [文件化内容与 Agent Server dev](content-system-design.md) 的范围实施：当前稿、教学任务、实时进度、修改、检查与必要 HITL。原型中的内容历史浏览／回退属于后续参考，不要求首阶段实现；也不再以本轮规划确认作为重复审批点。

用户已明确 IM 链接的用途：只参考页面交互与布局，作为生成后内容呈现的参考；本项目仍须按规格覆盖输入条件、局部修改、进度、版本、HITL 与检查。具体功能在页面中的落点见 Shape 方案，不扩展为 IM 教学内容研究。

## 用户指出的旧版缺口及本轮补齐

用户指出页面看起来像单个 Lesson 的设计工具，无法找到全年课程体系设计。当时核对源码确认：旧版“课程体系设计”只展示三课时课段；全年蓝图、单元展开、层级导航及下层问题回到上层的路径均未呈现。此前 16 项浏览器观察只证明预置局部动作与预期相符，不能证明整体产品交互覆盖完整。此前请求直接采用旧版整体交互基准的确认不适用。本轮已补齐下面三层视图；具体观察以本轮记录为准。

目标用户继续包含课程负责人和教师。课程负责人设计课程体系，教师围绕具体教学内容工作；可以是同一个人承担两种工作，但不能用单课页面代表课程负责人的全年设计工作。首张工程票的有限课段是实现切片，不是整体原型的范围。

已补入现行原型的结构：

| 视图 | 主要用户与工作 | 应呈现的对象与操作 |
| --- | --- | --- |
| 年级／全年课程设计 | 课程负责人建立、审查与修订完整年级方案 | 全年目标、CCSS 内容与实践覆盖、单元职责和进程、时间分配、年级 Narrative、关键任务构想、检查与未决问题；从方案进入具体单元 |
| 单元与课段设计 | 课程负责人把上层目标落实为连续教学 | 单元目标、先备与后续、Narrative、Section／Lesson 职责、任务与评测关系；按需展开课时材料，并清楚区分计划与实际材料 |
| 课时与教学工作 | 教师设计、审阅、适配、备课和检查理解 | 当前课时任务、师生材料、实际课程位置与输入版本；各能力保留自己的交互条件；发现上层问题时能带着具体依据返回对应单元或全年方案 |

这些是同一课程对象不同层级的视图，不规定一层一个固定 LLM 阶段，也不需要按全部 ticket 创建独立页面。共享的是内容身份、版本、需求与回应表达、进度和结果语义；不能把“一致”解释为所有层级都挤进同一个内容面板。桌面与窄窗口布局已进行有限走查，实际学校使用尚未验证。

保留独立单课创建、外部原课备课和从标准发起理解度检查的入口，不强迫所有教学工作先生成全年课程。课程设计主线应能双向走通“全年 → 单元／课段 → 课时与材料 → 问题及修订回到上层”。这项补齐落实已有规格，不扩大仓库到完整学校 Web 产品。

## 本原型回答的问题

课程负责人和教师是否可以在同一个任务工作区中，表达教学需求、查看足以判断的实际内容、完成有目的的回应、取得结果并提出修改，而无需记住内部场景或操作执行节点？五项能力的参与目的不同，共享界面不能抹掉这些差异。

[教学工作区交互样本](prototypes/teaching-workspace.prototype.html) 用八年级数学的少量预置内容回答这个问题。它是外部 Web 消费者的交互参考，不将 Web 产品建设纳入本仓库。不预设学校导航、登录、学生主页、课程管理或发布工作流。

原型不调用模型、LC、后端或存储；刷新丢失状态。预置需求和回应可走通相应示例，任意自由输入只展示原文，不伪装成已被模型理解。材料是简短的交互样本，不能作为完整课程、真实质量验证、真实教师贡献或运行恢复证据；正式原创运行不加载这些示例作为课程答案。

| [持久运行探针](../skills-harness/assets/cfu-durable-prototype-results.md) | 固定事件与有限真实回应的运行证据 | 指导运行测试，不让教师操作故障、锁或恢复按钮 |
| 本次教学工作区 | 五项能力的用户可见交互候选 | 作为唯一现行交互样本；行为改变时同步调整，不按 ticket 再建一套页面 |

宽窗口的设计制作工作区使用可折叠课程树，当前对象在树中高亮并定位；任务面板按需打开。窄窗口通过抽屉查看同一层级，不常驻三栏。教师／学生材料是这里可预览的产物，不能把作者工作区当作最终受众页面。

## 保持简单、一致的约定

1. 一个任务工作区，保持“需求与已知条件、当前内容、需要你的回应、结果与修改”这几种稳定表达。只显示当前相关动作，不常驻几十项场景按钮。
2. 自然语言是主要输入，少量有明确含义的快捷动作辅助表达。模型理解需求、解释修改、判断教学工作；程序核对权限、对象、版本和有效提交。原型的固定分支不移植为语言解析器。
3. 内容优先于状态：草稿有真实任务，取舍有代价，学生材料可打开，教师指南与学生页分开。用户不需要读 JSON、Prompt 或图节点；开发映射放在独立折叠说明中。
4. 已有决定与授权继续使用。仅修改草稿不等于放行生成；明确“改好直接生成”不再同义确认。等待时保存工作，不占着模型反复计算。
5. 结果范围、检查状况和人类参与分别说明。生成完成不意味着教师已审、课程已发布或学生已掌握。取消保留历史，不能把迟到结果变为当前交付。
6. 新增界面步骤必须说明它解决哪个真实教学需要，现有自然语言入口为何不足。不能因为新增一张运行保障票就增加一个用户按钮。

## 五项能力各自保留的交互

| 能力与样本 | 人需要做什么 | 后续实际技术行为 | 对应票 |
| --- | --- | --- | --- |
| 课程设计：输入全年条件，浏览全部单元，深入课段与实际材料 | 已授权范围内无需批准每步；压缩课时等要求先由模型判断可行性，确有授权外取舍才问人 | 装配范围与图依据，设计／检查；修改形成新版本并重查影响。原型展示全年载入、局部时间调整与表征衔接修订，预置结果不证明真实生成 | 01、15、17、06、07 |
| 课时材料：先看真实草稿，再修改或生成 | 可以只改草稿，也可以明确改后直接生成；完成材料不等待满意才能结束 | 回应关联草稿，保留原任务及指定修改，生成师生材料并检查；直接生成路径复用已有授权 | 03、02、16 |
| 教学适配：查看有原课依据的支持与拓展样本 | 正常协作需审阅本次整套；局部满意只覆盖局部；可以明确结束而不宣称满意 | 保留材料包与接受范围，修改后检查共享任务及受影响的接受 | 08、02 |
| 教师备课：给出实际原题，先由教师尝试和分析近似正确回应 | 贡献影响后续便签；先示范、拒答、短时及结束保留各自例外，不统一成批准 | 模型先内部试做；正常路径等待教师贡献再揭示分析，按贡献组织便签。原型只演示正常路径和明确请求示范 | 09、02 |
| 理解度检查：先确认可检查焦点 | 缺少决定时选定或明确改向；已有适用焦点直接使用；交付后可要求修改 | 焦点采纳后构建学生页／教师指南，对实物完成两道验证再交付。界面不让教师手动触发这些检查 | 10、02 |

## 映射到调用接口

用户看到的一个动作不等于一次 LLM 调用或一个图节点。

| 外部界面行为 | Harness 入口及责任 |
| --- | --- |
| 提交需求 | `POST /v1/tasks`，带可信身份与实际 Context 引用；模型在当前范围内自主推进 |
| 查看进度、重回任务 | `GET /v1/tasks/{task_id}`，查询权威快照；流用于及时显示，查询不触发模型 |
| 回答当前具体问题 | `POST /v1/tasks/{task_id}/replies`，绑定请求和展示快照，先保存原文，再解释与采纳；收到回执不等于已理解并完成 |
| 对已生成内容提出修改 | `POST /v1/tasks/{task_id}/revisions`，带对象与基线；模型处理内容和影响，程序保护有效提交 |
| 取消、在有效停止条件下续作 | 对应 `cancellations`／`continuations`，遵守各自边界；取消不能用普通继续自动重开 |

详细语义以规格和 [主执行设计](../skills-harness/assets/main-execution-design.md) 为准。原型只示意这些映射，不提供可调用接口。

## 实现期间怎么维护

- 开始第一张实现票前，由项目负责人走查这份具体候选，确认交互方向或给出修改；这是本次用户明确要求的实施顺序。浏览器通过不冒充项目负责人已确认。
- 此后每张票开工时读取本页及其相关能力样本。每票验收核对用户意图、实际内容、等待与结果是否一致，不重复请用户批准已经确认的基准。
- 内部观察、故障处理、部署和权限实现用接口与运行测试验证。只有用户可见语义确实变化，才修改本原型与对应规格；重大交互偏离再提出具体差异供判断。
- 实际 API 和材料逐步出现后，用一个最小消费者逐项验证同样的交互。避免让固定示例页长成第二套 Harness；真实消费者足以覆盖时，将本原型冻结为历史证据，留下替代入口。
- 原型没有课堂质量或生产验收权；五项能力自己的详细规则及测试持续存在。原型未展示的异常与例外不因此退出规格。
