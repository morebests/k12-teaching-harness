# 首票范围、实际消耗与 Skills 对照复核

日期：2026-09-16。回应用户对缓存、失败续作、课程层级和原 Skills 对照的质疑。本次核查以 `ccdf3c8` 的实现和保存的真实调用为据，没有新运行教学生成模型。本文纠正交付口径，落实既有主线，不新增课程层级或改写历史运行结果。

## 当前产物证明了什么

首票接通了模型、知识、工具、保存、检查和修订；后续修复证明当前阅读稿的公式可以正常渲染。它们没有证明正式课程体系或完整 Lesson 材料已经交付。此前“材料已可用”的表达超过实际证据，应限定为所查桌面阅读稿通过格式走查。

当前 [`TaskRequest`](../../src/teaching_harness/contracts.py) 只支持 `curriculum_design`、八年级和 `scope="section"`；`Curriculum` 固定为 Section，包含简化的 `LessonIntent` 和集中存放的 `KeyTask`。没有正式 Grade／Unit 内容及父级交接，也没有独立 Lesson 全套材料。扁平页面呈现是这项内容结构缺口的表现，仅折叠题目不能解决它。

此前有全年蓝图的离线实验，但它没有成为当前生产调用的正式全年能力，也没有作为本次课段的有效上层交接。首票原定工程范围可以解释先接通有限任务的顺序，不能证明当前形态满足 README 的产品承诺。

## 应落实的职责

下表来自现有 [领域定义](../../CONTEXT.md) 和 [课程设计详细职责](../skills-harness/assets/curriculum-design-capability.md)，不是本轮临时发明的解释。

| 层级 | 教师／课程负责人应看到什么 | 具体任务放在哪里 |
| --- | --- | --- |
| Grade：全年 | 全年目标覆盖、单元安排、时间分配和前后年级联系 | 代表任务可验证计划可行性；不要求先写完全年每一课 |
| Unit：单元 | 核心理解、入口与出口、课段组织、评测依据 | 代表任务和评测构想与各课职责关联 |
| Section：课段 | 单元内部一组课怎样推进理解、表征怎样变化、哪里检查 | 少量代表例子与 Lesson 引用；不承载各课全部题面和答案 |
| Lesson：课时 | 实际题目、图表、解法、课堂组织、追问、观察和退出检查 | 教师材料与学生材料分开，可独立打开、打印和使用 |

当前报告对课程负责人缺少全年定位；对明天要授课的教师，还需要自行拆分课时、学生页和教师引导。这是依据任务要求作出的可用性判断，尚无真实教师试用，不能声称教师已经觉得有用。

课段在正式单元中规划或局部修订有价值。本阶段不应继续把孤立课段报告作为独立交付主线。沿既定 [全年蓝图票](issues/15-full-year-blueprint.md)、[单课材料票](issues/03-continuous-lessons-and-materials.md) 和 [跨层交接票](issues/17-curriculum-lesson-handoff.md) 补齐实际能力。已有充分外部课程上下文时，单课能力仍可独立调用；不新增“必须先生成全年所有课时”的限制。

## 失败之后怎样接续、缓存是否生效

两次修订用 `examples/live_curriculum.py --source` 将上一稿 JSON 放入 `external_content`，分别新建 thread／run。复用了设计成果，没有恢复旧 Agent 消息或旧 run 的 checkpoint。工具查询、图件创建、保存和审阅在新任务中重新发生。

自动缓存确实命中。当前 LangChain 适配器走 `generateContent`，尚未接入 Interactions 或创建显式缓存；应用摘要也没有汇总 adapter 已返回的缓存和思考分项。官方接口状态与源码见 [Gemini 核查](../skills-harness/assets/gemini-api-and-caching-audit.md)。缓存属于输入用量，不能直接从总 token 扣去后称为账单；本轮未核对账单。

410,455 是沿用草稿的较窄修复任务，调用从 30 次降到 8 次，缓存占输入比例反而下降。它不能证明从零生成更省。旧设计被保留下来，所以此前消耗并非全部作废；自设停止和修复缺陷导致的重复工作也确有额外成本，没有同条件反事实，无法精确拆出可避免数量。三个 run 累计 2,599,630 tokens，不能作为完整 Lesson 或全年高质量交付的消耗基线。

## 怎样取得有意义的 Skills 对照

固定上游只有教案创建、教学适配、教师备课和理解度检查，没有全年或 Section 生成 Skill。当前 Section 和完整单课材料不能直接排名。

先使用 [共同单课任务书](comparisons/lesson-creation-01/brief.md)，按 [实际执行方法](../skills-harness/assets/skills-comparison-runbook.md) 在独立会话中运行固定原版教案创建，取得真实教师、学生及观察材料；完整 LC 连接案例须遵守现有参考隔离顺序，无 KG 样本使用上游正式退路并明确标名。当前本产品对应的 Lesson 执行端应记为“尚未实现／未运行”，不能以手工重排 Section 代替。

原版加 Claude 与产品加 Gemini 可以比较两套实际系统交付；要判断 Harness 机制的作用，还需固定同一 Gemini、输入和知识范围，完整执行原 Skill 资源与工具，并记录宿主适配。上游 `evals/` 提供 rubric，没有现成 runner；评价须打开全部真实文件，分别记录数学正确性、课堂可用性、材料完整性与真实交互证据。一次样本不能证明稳定优劣。

本轮完成的是审计、范围纠偏和对照准备。尚未产生原 Skill 基线产物、正式 Lesson A/B 或教师评价；也没有迁移模型接口或进行新的预算优化实验。
