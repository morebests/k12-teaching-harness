## 按教学价值推进

当前 AI 运行时采用 [LangGraph＋Agent Server dev](content-system-design.md#运行时也从简)：直接复用会话、运行、流式、取消、状态保存和 HITL 恢复，不自建队列、SSE 或文件运行状态机。首票接入原生 API／SDK 并验收真实流式进度；教学内容文件化，业务数据库与生产部署后置，框架本地 checkpoint 保留。

当前先按 [文件化内容格式](content-system-design.md) 完成教学内容闭环：自行定义 JSON 工作源，正文允许 Markdown／LaTeX，图件单独保存；不上业务数据库，不做内容版本历史，不再评估外部 authoring。首票前只收口最小格式与读写渲染。内容与检查用文件记录，运行与待答由框架管理，保留真实 HITL、内容指纹及必要质量要求；完整生产部署与恢复后置。现有 22 票保留完整交付范围和硬依赖，当前执行遵守 [规格的阶段约定](spec.md#当前阶段文件化教学内容闭环)，不因旧票标为 ready 就把已后置工作重新带入首阶段。

首个教学交付里程碑保持为 **完整全年蓝图→连续三课→实际师生材料**，并取得必要 HITL、检查修订和恢复证据。工程先用一个有限真实课程任务接通模型、知识、任务与内容，再扩大范围；不能把首票课段当作完整全年或单元。

| 交付里程碑 | 需要的完整行为 | 当前不能省略的门槛 |
| --- | --- | --- |
| 首条教学链 | 全年蓝图、单课生成、连续交接、草稿／真实回应和检查修订；当前使用文件承载，完整故障恢复后续验证 | 必要材料实际检查和走查；真实参与不能由合成用例替代；观察随切片接入 |
| 完整课程对象 | 全部课段／课时／材料／评测及 Narrative，跨层修订与局部支持范围成立 | 三课不能代表整单元；具体工程和内容审查规模在三课出现后收口 |
| 五项能力 | 创建、适配、prep、CFU 各有自己的规则、Context、参与、产物与检查，加上课程体系设计 | 技术上可独立推进；prep 可读外部实际原课，CFU 不要求教案 |
| 对照与产品交付 | Skills 实际对照、冻结后 IM 评阅和 B、部署／权限／升级与消费者契约 | 各条证据合并审查；单票完成不等于课程可发布或学校使用通过 |

优先安排首票，其后把全年与单课放在主线上；实际材料出现即可开始创建对照，不等四项能力全部完成。真实回应、观察和运行保障按共享交接可用程度加入。prep 等即使技术上较早可启动，也不因“无硬阻塞”而自动抢占课程主线。

## 共享交接与验证责任

| 对象 | 首次提供／主责 | 后续如何复用 |
| --- | --- | --- |
| 任务、内容快照、基本可信访问与源记录 | 有限真实课程任务 | 支持规范化外部原课；后续票不能各自另造任务和材料身份 |
| 展示、原文、采纳事务和受控等待恢复 | 真实回应票 | 各能力解释自己的参与语义；自动硬退出由故障恢复验收 |
| 师生源内容、渲染和实际检查 | 一课材料票 | 草稿、适配、CFU 和连续课时复用；CFU 自己实现两道教学验证 |
| 取消、有效停止与续作 | 取消续作票 | 跨层修订复用旧提交失效，自动故障恢复扩大故障面 |
| 离线案例、参考执行和评价记录 | 创建对照票 | 四能力及 IM 采用自己的 rubric；LangSmith 只关联观察与评价 |
| 业务并发与公共基线条件采纳 | 跨层修订票 | 生产验收复验，不在部署票中另实现外部课程所有权 |
| 持久环境及同版本备份恢复 | 部署恢复票 | 动态权限和跨版本升级分别验证，不能用“包可构建”替代 |

共享代码变化是协调风险，不自动构成新增产品模块。提供方交付可运行契约和行为验证后，消费者再接入；可提前准备规则和用例，但不把准备当成依赖已完成。每张能力票维护自己的服务外调用示例，最终消费者票只做汇总及漂移检查。

## 质量与发布的外部条件

| 门槛 | 必需证据／条件 | 不能据什么宣称通过 |
| --- | --- | --- |
| 完整单元质量 | 完整材料、全范围检查与修订、数学教育评阅校准 | 代表三课或零解析错误 |
| 四项能力达到目标水平 | 各自实际对照、真实交互证据、人工校准和适用样本范围 | 单次模型自评、删弱上游规则或仅准备评阅包 |
| 原创与参考对照 | A 先冻结，R 后读取，实际匿名首轮意见及 B 重查 | 三课冻结、待评包或更像 IM |
| 生产运行 | 实际持久环境、许可／身份／存储条件、故障与升级证据、观察故障隔离 | dev 重启、配置文件或部署包可构建 |
| 产品受控试用 | 五项消费者契约、内容与生产门槛、真实 Web 接入和教师使用条件 | 测试客户端或合成教师回应 |

当前暂无合作学校；实际参与者、评阅者、目标环境和升级版本分别在需要时落实，不让后端工程替它们伪造事实。发布是上述条件的合取，故它们不应全部写成某张早期消费者票的硬依赖。缺失外部条件保持未通过，不阻止独立的前置开发。

## 执行约定

1. 每票先读规格、对应决定、详细流程和原文。产品模型必须实际取得运行资源与版本，不能以开发文档可找到代替装配。
   同时核对用户交互原型基准及相关能力样本；共用一个现行交互参考，不按 ticket 扩展场景菜单。内部运行变化优先以接口和运行验证覆盖，用户可见语义改变才同步调整原型。
2. 按公开任务入口验证输入到实际结果；基本授权、来源、有效引用与该能力必要检查随行为交付。不能把 CFU 两道验证或适配整套一致性后置以缩小票面。
3. 实现报告分别记录工程行为、当次质量和覆盖局限。没有实际首轮意见就不关闭首轮评阅，没有实际部署／恢复就不关闭部署票。
4. 原创冻结前，早期 Skills 对照只用不需要目标 IM 且可完整复现的案例；需要目标资料的案例延期，参考输出不回灌原创。
5. 先质量、随正常任务记录消耗，再优化；不根据票数拍调用预算。独立制图平台、多模型扩展等按实际需求进入，不抢占主线。
6. 在票的 Comments 保存实际交付与验证证据；需求转移必须有明确承接票。接口假设被运行反证时回到相关规格修正，不静默改目标。
