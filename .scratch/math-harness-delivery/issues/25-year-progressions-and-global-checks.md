# 补足所有单元的规划进程并核查全年连贯性

Status: needs-triage

## 为什么做

对应 [规格 Y2／Y3／Y4／Y5](../spec.md#问题价值与验证依据)。布局回答“安排在哪里”，还不能回答“学生怎样走到那里”。各单元分别写得合理，也可能出现先用后教、评价过早、回访落空或时间重复。因此需要先形成每单元规划深度的学习进程，再核对组合后的全年承诺。

这一深度服务年度安排与调整。只有标题会掩盖学习跨度，直接堆 Lesson 题解又会遮住单元职责；本票用关键理解变化及代表经历解释进程，实际探查只解决会影响全年决定的疑点。

## 就绪条件

取得 24 的有效 A／B、实际接口、检查局限及运行证据后，列出全部单元和综合核查范围，确定可复用实现与剩余工作。若规模过大，按可独立验收的进程闭环和综合核查进一步拆票，并明确承接，不按每个单元或每条标准机械分票。收口后改为 `ready-for-agent`；不需重新讨论产品目标。

## 输入与交付

读取实际目标依据、全年布局、单元职责及邻接承诺。交付全部单元规划 C、全年综合核查 D、可阅读的完整全年候选及精确单元交接；后续 17 从这里取得有效年度依据，旧 15 样本只作历史对照。

## 验收条件

- [ ] 所有单元写明入口／出口、关键理解变化、代表学习经历、表征与语言用途、练习回访、评价响应及时间资源；能按目标追查实质安排，不以标签或空泛叙述代替。
- [ ] 单元工作使用同一有效布局和相关前后承诺，始终保留全局职责／日历视图；需要判断其他单元内容时按对象回取精确正文，不独立生成若干单元后机械拼接。
- [ ] 关键疑点有必要的真实题面、数据／图、求解和解释检查；独立试做先只看到题面及必要材料，再比较作者解法。记录探查为何必要、改变了哪项全年决定；不局限线性函数或固定 Unit 2／3。
- [ ] D 覆盖全部目标、单元、主要数学主线、已声明和实际发现的依赖、回访、评价及时间资源。分块后核对完整覆盖；确定性检查与语义判断分开，未查到不能记通过。
- [ ] 问题带对象版本、原文、判据、反例、严重度及复查方式；局部回 C，职责布局回 B，目标条件回 A。程序不把每种教学问题硬编码为专门节点，模型的修订建议不自行宣布检查完成。
- [ ] 回修核对修改前后的依赖与实际内容，排除受影响的旧成果／检查；保留无关有效内容。验证先用后教、评价提前、删掉回访、时间重复及合法调整，不能仅测图上已登记边。
- [ ] 不通过删除目标、降低理解要求、伪造资源或学习效果来消除问题；误报可被原文或计算驳回，有进展的格式和内容修复继续执行。
- [ ] 教师阅读稿分层呈现年度主线、单元职责、进程及调整理由；完整题解留在明确关联的探查材料，规划页可定位而不冒充 Lesson。源与阅读稿一致，实际渲染走查完成。
- [ ] 带指纹的单元交接含目标、进程、理由、时间、先备／后续、适用检查和未决假设，消费者可精确读取；不把旧 Section 补父 ID 当作完成交接。
- [ ] 至少完成一次从明确年度任务经 A→B→C→D 的真实全年生成及必要修订，保存输入、来源、调用、阶段、检查覆盖、失败、实际用量和未解决项。修订旧稿是回归证据，不能单独代替从头规划。
- [ ] 分别报告工程行为、当次规划质量和未覆盖范围；未通过项保存为候选。本票不因模型自评通过宣布达到 IM，也不依赖生成全年 Lesson 才验收规划。
