# 在崩溃和调度结果不明后自动恢复任务

Status: ready-for-agent
Blocked by: [取消教学任务并续作明确停止的工作](05-stop-cancel-and-recovery.md)
Size: L — 沿一个持久业务动作贯通存储、调度和副作用，主要风险是故障窗口而非场景数量。

## What to build

对已有真实任务与人类回应，运行进程硬退出或调度响应丢失后自动核对状态并继续原授权工作。既不重复采纳和提交，也不重新解释已生效的教师决定。

## Acceptance criteria

- [ ] 覆盖原文保存→采纳、采纳→待调度、调度响应不明、worker 执行、产物写入→引用提交的实际故障窗口；不用固定答案代替业务内容。
- [ ] 恢复交接读取持久动作和待执行记录，先核对已有 run 再补送；并发重启不会生成两个有效提交。
- [ ] 模型计算重复及其消耗可以如实发生，业务采纳和有效产物提交不可重复；检验实际持久数据与副作用。
- [ ] 文件写入成功但业务提交失败、反向失败、缺失对象等不产生已交付的悬空引用，旧有效版本仍可用。
- [ ] 恢复前复核取消、版本和访问条件；旧工作在取消或替代后不能提交。无需教师重新点击批准或补一段假回应。
- [ ] 进度流丢失／乱序／断连后，通过权威查询恢复正确视图；订阅不能绕过可信访问限制。
- [ ] 固定同一应用版本在本地持久进程上实际注入并恢复，保存证据；部署存储与跨版本语义分别由后续票验证。
