# 核实全年目标依据并形成可检查的单元布局

Status: ready-for-agent
实施状态：待实现。
Blocked by: [生成覆盖完整八年级 CCSS 的全年蓝图](15-full-year-blueprint.md)、[建立全年规划的证据评价与检查校准闭环](23-year-evaluation-and-check-calibration.md)
Size: L — 两个相连的阶段成果及其必要交接机制；不包含各单元完整进程。

## 为什么做

对应 [规格 Y1／Y2／Y3／Y5](../spec.md#问题价值与验证依据)。目标含义和学校条件没有核实，就开始安排全年单元，容易把误读、隐含假设和时间冲突传播到整份方案。布局没有单独的责任说明，后面写得再细也难判断每单元究竟新增什么。

本票先让“本年要完成什么、为什么如此组织”形成可检查依据。两阶段的价值在于让后续设计依靠有效成果，能在错误扩散前修正；节点增多和上下文变短本身不算成功。

## 输入与交付

输入为完整八年级 CCSS、本地 LC 及学校条件；事实、合成研究条件和未知项分开。复用 15 的知识与运行接口，以及 23 的证据和反馈契约。

从原生任务入口交付 A 目标与条件依据、B 全年主线与单元布局、教师可读的理由说明、实际检查及修订、调用与 Context 清单。输出明确是全年阶段成果，C／D 未完成时不能沿用旧 API 的全年完成声明。

## 验收条件

- [ ] 完整遍历实际年级范围及必要分页，保留标准原文、父子层级、数学实践和来源版本；不硬编码旧节点数，缺页与成功空集区分。
- [ ] A 解释目标含义、年末表现与前后年级边界，保留已知日历／资源／学习证据及假设；关键解读存在分歧时补查依据。允许的假设明确标注，缺失关键真实条件不能默默补造。
- [ ] B 使用当前有效 A，形成自有数学主线、全部单元的新增职责、目标分担、依赖理由、初步时间及重大取舍。学习支持关系不自动升级为强依赖，不按 IM 编号生成目录。
- [ ] A 与 B 各有相应程序核验和定向语义审查；使用 23 的问题对象、证据、严重度及复查方式。A 的阻断问题未解决不能接受依赖它的 B；B 可按问题回修 A，不能只在全文末尾附警告。
- [ ] 阶段成果保存当前内容、稳定身份、输入与内容指纹、设计理由、适用检查和未决项；同名文件被修改后不能复用旧通过结论。只有必要工作状态，不建设用户内容历史。
- [ ] 按当前问题重装 Context，记录实际原文、规则、成果及允许工具；下一阶段不直接继承作者原始消息流。摘要能定位原文，模型作判断时所需内容实际可读，容量不足有分块／续读记录而非静默截断。
- [ ] 固定的获取范围、确定读取、身份、保存、渲染、结构和时间检查由程序处理；工具错误返回具体位置和值。固定内容类型由程序保证，公式以实际保存／渲染结果校验，错误可返回修复。
- [ ] 对确需未知取证的目标或布局疑点，阶段内调用局部 Agent，提供问题、已有依据、工具范围和返回条件；其证据返回发起阶段。没有疑点不为演示 Agent 强制调用，结构化设计／审查也不强制长程 Agent。
- [ ] 固定反例验证遗漏目标、条件冲突、过期检查、上游改动及已有有效依据复用；检查者不能仅复述作者理由。记录哪些由程序保证、哪些仍需模型或专业判断。
- [ ] 用真实 Gemini 与 LC 从明确任务形成完整 A／B，保存至少一次有实际内容变化的检查反馈闭环；若自然运行未暴露问题，另设明确标注的缺陷副本验证修复，不伪造自然发现。
- [ ] 普通调用取得教学进度、阶段草稿与未完范围；有权限维护者能追查模型／工具的实际输入、返回、错误、用量和成果关联。沿用 Agent Server dev 与现有 adapter，无新增累计 token 预算。

## 取舍与尚待验证

成果交接及检查由 Graph 保证，因为这些是下一步可否信任依据的运行事实；教学组织理由由模型提出并接受检查。新增交接会带来输入遗漏和失效判定错误的风险，必须用全局目标视图、精确回取和反例检验。若某项额外细分没有减少遗漏或返工，应合并，不为固定节点数维护流程。

当前授权完整且条件明确的任务可自动前进；真正缺条件或越权取舍遵守既有 HITL 支持范围，不新增每阶段审批。公开取消／续作与生产故障矩阵仍由原票承担。
