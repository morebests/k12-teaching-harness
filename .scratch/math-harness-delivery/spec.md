# 数学课程与教学设计 Harness：交付规格

Status: ready-for-agent

## 为什么要建设这项能力

课程负责人需要知道：完整年级目标分别在哪里得到学习机会，学生如何从已有理解走向更高要求，练习、评价和时间能否支持这条进程，以及条件变化时应调整哪里。教师随后需要据此形成可教的课时、材料、支持和教学回应。只有目录、标准标签和流畅叙述，无法支撑这些决定。

Harness 的价值是帮助完成并检验这些教学工作。LangGraph、Agent、Prompt、检索和检查器都是手段；选择它们时须说明要消除的具体缺口、最小充分做法、代价及验证依据。新增节点、角色、调用次数或文档数量均不构成教学质量证据。

**当前先把全年规划做扎实。** 01 已验证有限工程链，15 已生成全年稿并经历修订；[原始报告](evidence/15-full-year-blueprint/README.md)仍记录初稿审阅漏检及质量局限。[会话审计](comparisons/year-review-session-audit.md)确认审阅没有继承作者对话，但输入集中包含整稿、解答及知识；这只能证明输入情况，不能单独证明漏检由 Context 大小或 Agent 造成。先在全年层验证结构化方法，再迁移到其他生成能力。当前暂停向 03／17／06 推进。

### 问题、价值与验证依据

下列 Y1–Y6 是本轮问题索引，用于贯通设计、工单和评估，不是运行节点或新增评分维度。

| 问题 | 为什么必须解决 | 应看到的改善 | 验证与承接 |
| --- | --- | --- | --- |
| Y1 目标有标签，责任和深度仍可能不清楚 | 漏掉或误读年度要求会使后续单元建立在错误基础上 | 完整原文、目标含义、年末表现及条件成为布局依据；缺口能被指出 | Q1；24 目标依据，25 全年回查 |
| Y2 单元描述不能充分解释学习怎样累积 | 教师无法判断先后理由、必要经历、复习位置及评价是否过早 | 全年主线与每单元理解变化连到表征、学习经历、练习、评价和时间 | Q2–Q7；24 布局，25 进程与综合核查 |
| Y3 跨调用缺少有效成果交接和针对性 Context | 未解决的上游问题会扩散，旧结论和无关内容会干扰当前判断 | 每次工作有明确问题和现行依据，能回取原文；改动只重查真实受影响范围 | 输入清单、失效及遗漏反例；24／25，26 方法证据 |
| Y4 审阅通过未能排除实质错误 | 只增加审阅提示或角色，仍可能把错误方案交给教师 | 检查能定位问题、接受反驳、驱动修复，并记录漏报、误报和修订回归 | 23 校准；24／25 反馈闭环；26 独立复评 |
| Y5 固定机械操作仍占用模型判断且容易出错 | 标识、格式、分页或保存错误打断教学工作，重复取整稿增加干扰 | 程序承担已知操作，工具提供精确读写与可操作错误；探索聚焦真正的未知 | schema／原文回取／保存渲染反例及真实调用；24／25 |
| Y6 缺少能清楚比较优劣的共同证据 | 模型自信、不同材料深度或加权总分可能遮住差距 | 固定候选与 IM 按同尺度逐维判断，公开依据、分歧、不可比项及修订效果 | Q1–Q8；23 评价契约，26 比较与复评 |

Q1–Q8 的定义、锚点和裁定仅在 [全年评估协议](year-planning-evaluation.md)与 [规则数据](year-planning-rubric.json)维护；不把程序通过、模型评分、专业评阅和课堂效果混为一层证据。

## 交付范围与能力边界

完整目标保持五项数学能力。标准固定 CCSS，本地 Learning Commons 与学习者上下文由外部提供；本仓库交付教学执行，Web 产品、学习证据采集、Learner Model 构建及发布治理由外部承担。

| 能力 | 为什么需要它 | 本能力完成什么 |
| --- | --- | --- |
| 课程体系设计 | 让学习在年内与跨层持续推进，能解释和调整设计 | Grade／Unit／Section／Lesson 各自的目标、进程、Narrative 与证据；全年规划可单独验收，完整单元另需全部课时和材料 |
| 课时与材料设计 | 把规划意图落实为学生实际承担的数学工作 | 真实题目、解法、教师组织、学生材料和学习检查；支持直接生成、草稿协作、仅修改及改后生成，延续已采用内容 |
| 教学适配 | 根据相关学习证据提供支持，同时保持数学目标 | 协调的教师与学生材料；正常协作记录整套接受，部分接受、供后审、停止和退出分别处理 |
| 教师备课 | 帮助教师理解任务、辨认学生思考并作教学应对 | 模型先试做，正常路径保留教师自己的分析贡献与讨论，再形成便签；概念解释、示范、拒答、短时和结束按自身规则处理 |
| 理解度检查 | 让学生回应能支持具体后续教学决定 | 焦点、实际学生页和教师指南；分别验证可辩护答案及错误解释能否产生相应作答，不要求先有教案 |

四项原 Skills 的详细流程仍是设计和比较起点，重要变化说明原教学目的、替代方法和效果证据。全年工作的阶段名和检查方法不直接复制给其他能力；迁移时按其目标、真实参与和产物重新验收。既有 Section 工程样本的 Lesson 内容混杂由 03／17 修正，不能当成正式课段沿用。

### 当前阶段：文件化教学内容闭环

当前用 JSON 保存实际工作源与检查，正文允许 Markdown／LaTeX，图件另存，维护稳定身份、内容指纹、格式及规则／来源版本。运行由 LangGraph＋Agent Server dev 承载，复用原生 thread／run、checkpoint、流式、取消和真实中断恢复。同一 thread 串行演进，服务注入 checkpointer，不另建任务状态机、队列或 SSE。

选择文件化是为了先验证教学内容与修订方法，降低当前非必要建设负担。暂不上业务数据库，不建设内容历史、回滚、协同编辑，不再评估其他项目的 authoring；同目录写完整再替换不等于跨文件事务。固定实验候选、评语和原始证据另存用于复核，不扩展为面向用户的历史产品。详见 [内容与运行约定](content-system-design.md)。

[交互原型](prototype-baseline.md)沿用既有授权，按实际已支持能力落实；原型不证明生产或教学质量。完整持久部署、事件事务、故障恢复、动态撤权及跨部署兼容仍在后续交付范围，不能让它们提前替代全年教学工作，也不能以 dev 通过代替生产验收。

## 全年规划的成果与前进条件

阶段按教学依赖划分。目标解读决定布局，布局限定各单元职责，单元进程提供综合核查的实际内容；因此先夯实可复用成果，再集中处理下一项问题。每阶段保留简明设计理由、来源、假设和未决问题。检查通过才允许依赖它的工作推进；后续反证可以回修，不等于每阶段都要人类批准。

| 阶段 | 要形成的教学成果 | 为什么此时需要 | 前进条件及回修责任 |
| --- | --- | --- | --- |
| A 目标与条件依据 | 全年标准原文与层级、目标含义和年末表现、前后年级边界、数学实践、已知条件与假设 | 先明确本年到底承担什么，避免布局后才发现漏项或条件冲突 | 完整范围可核对、关键解读有依据；影响全局的未知不能默默假定。错误回 A |
| B 全年主线与布局 | 单元职责、数学联系、依赖理由、初步时间及重大取舍 | 先确定每单元贡献，避免分别写稿后才拼接职责 | 全目标有责任范围、单元有新增数学工作、依赖和总容量相容。职责问题回 B，目标问题回 A |
| C 各单元规划进程 | 关键理解变化、代表学习经历、表征和语言、练习回访、评价与响应、时间资源 | 检验主线能否落实成学习机会，暴露空泛承诺 | 所有单元达到规划深度，目标—机会—证据可追查；高风险跨度有实际探查。局部回 C，上游冲突回 B／A |
| D 全年综合核查 | 跨单元联系、回访迁移、评价先后、日历和资源的全范围核对及修订 | 各单元分别合理仍可能整体冲突 | 结构与语义检查覆盖完整；阻断问题解决；相关检查绑定当前成果。按问题回 A／B／C |
| E 固定候选与比较 | 教师阅读稿、当前源、证据包和与 IM 的逐维比较、改进复评 | 让课程负责人判断优劣与调整依据，检验生成方法 | 源与阅读稿一致；比较有可复核依据；弱项回责任阶段，保留原稿与原评分 |

C 的深度足以说明进程和判断可行性，不能只剩标题；全年阅读稿也不应堆满逐课题面、答案及教师话语。为检验重要设计疑点而产生的真实题目、数据、图和解答保存在探查证据中，正文说明它支持或推翻哪项年度决定。完整 Lesson、全套练习和试卷由后续能力交付。

每次 Context 由当前问题、全局约束、相关成果与原文、有效发现、适用规则和工具组成；摘要供导航，判断依赖的正文须可回取。单元工作仍能看到全年职责及相关前后承诺；分块检查必须记录全范围覆盖。上游修改核对旧、新依赖与实际内容，排除过期产物和检查，保留无关有效成果。

实现设计、工具缺口与反例见 [全年工作流](curriculum-progression-workflow-design.md)。本规格规定教学责任和可观察行为，具体节点数、函数名和单次调用组合由实现选择并验证。

## 使用者需要解决的问题

1. 作为课程负责人，我希望系统使用完整、版本明确的本年级 CCSS 内容与实践标准，以免只围绕一个热门单元规划全年。
2. 作为课程负责人，我希望设计自己的单元组织与位置，以便依据教学目标和实际条件形成课程，而不复制 IM 的目录。
3. 作为课程负责人，我希望每层 Narrative 解释学习如何推进、为什么这样安排，以便审查设计理由而不只阅读摘要。
4. 作为课程负责人，我希望能够追查目标对应的学习机会和证据，以便发现漏教、未练就考及无目的重复。
5. 作为课程负责人，我希望在关键任务试做暴露问题时修订上层安排，以免漂亮的蓝图掩盖无法实施的课堂任务。
6. 作为课程负责人，我希望完整单元包含所有课时和必要材料，以便知道哪些已经可审阅、哪些仍只有计划。
7. 作为课程负责人，我希望压缩课时后重新核对目标、练习、时间及后续依赖，以免仅修改课时数。
8. 作为教师，我希望教案包含真实题目、解法、表征、讨论与学习检查，以便在课堂中实际使用。
9. 作为教师，我希望已有有效的目标、条件和生成授权直接被使用，以免反复回答相同问题。
10. 作为教师，我希望先审草稿时看到真实任务，以便提出有对象的修改。
11. 作为教师，我希望“只改草稿”和“改好直接生成”产生不同的后续动作，以便保持我的实际意图。
12. 作为教师，我希望课时材料延续已采用的任务和条件，以免成套输出时换成另一套内容。
13. 作为教师，我希望学生页、教师答案、图形与可编辑源保持一致，以便修订后不会使用旧答案或坏图。
14. 作为教师，我希望课堂时间估算包含学生工作、讨论、转换及资源准备，以便识别实际不可实施的安排。
15. 作为教师，我希望必要的函数图能够清楚表达数学信息，以便学生无需猜测坐标、单位或标签。
16. 作为教师，我希望适配建立在真实原课和相关证据上，以便支持变化有据可查。
17. 作为教师，我希望获得支持的学生仍进行目标数学思考，以免适配变成低水平替代任务或直接泄露答案。
18. 作为教师，我希望持续性支持与可逐渐撤除的支架分别处理，以免系统自动撤去学生需要的支持。
19. 作为教师，我希望班级或个人适配保持自己的范围，以免意外改动公共课程基线。
20. 作为教师，我希望系统区分对部分材料的接受与整套接受，以便准确表达尚需修改的部分。
21. 作为教师，我希望备课围绕本课关键任务和真实难点展开，以免只收到泛泛教法建议。
22. 作为教师，我希望自己先分析看似正确但有关键缺口的回应，以便练习识别学生思考，而不是阅读系统事先给出的答案。
23. 作为教师，我希望实际贡献影响后续讨论和便签，以便备课过程有意义。
24. 作为教师，我希望先问概念、要求示范或结束讨论时得到相应处理，以便系统尊重当下需要而不机械追问。
25. 作为教师，我希望能仅从标准和教学目标发起理解度检查，以便不必先生成整份教案。
26. 作为教师，我希望检查题不仅判断答对，还能揭示错误方法及部分理解，以便选择具体后续教学。
27. 作为教师，我希望答案、干扰项和解释均来自实际题目验证，以免根据无法产生该作答的“误区”作判断。
28. 作为学生，我希望只看到适合我的任务、图形、说明和作答空间，以免材料泄露答案、教师分析或能力标签。
29. 作为产品后端开发者，我希望用任务级接口传入真实上下文并接收结果，以便 Web 用户不依赖交互式 Agent 客户端。
30. 作为产品后端开发者，我希望取得可直接展示的待答内容及其版本，以便无需让教师理解内部场景表或状态机。
31. 作为产品后端开发者，我希望网络重送同一事件不会重复创建任务或采纳回应，以便可靠地恢复请求。
32. 作为产品后端开发者，我希望新修改意图不会因旧请求已答而丢失，以便保留用户改变决定的权利。
33. 作为产品后端开发者，我希望重连后查询到权威快照，以免用丢失或乱序的流事件拼出错误状态。
34. 作为产品后端开发者，我希望取消后迟到的模型结果不能提交，以免已经取消的工作覆盖有效版本。
35. 作为产品后端开发者，我希望跨进程和部署恢复保持原任务行为或明确要求迁移，以免新代码默默改变等待中的教学流程。
36. 作为审核者，我希望每份交付关联来源、实际输入、人类决定、检查与修订版本，以便核对归因及尚未解决的问题。
37. 作为审核者，我希望不同检查能说明证据和适用范围，以免把程序通过、模型判断或教师满意当成同一种质量保证。
38. 作为维护者，我希望使用相同案例比较改动前后的教学质量，以便知道新机制是否比原 Skills 更有效。
39. 作为维护者，我希望用固定版本、同尺度证据和明确的参考接触记录比较 IM，以便知道方案的实际强弱，而不把参考影响藏在“原创”声明里。
40. 作为维护者，我希望持续记录不同任务的质量和实际消耗，以便以后有依据地优化，而不先删减必要检查。
41. 作为学校系统负责人，我希望任务和材料遵守可信身份、权限及数据范围，以便不同学校、班级和受众的信息保持隔离。
42. 作为学校系统负责人，我希望观察服务故障不破坏教学任务，以便运维工具不可用时仍可取得已保存结果。

## 执行与接口要求

### 1. 实现范围与教学资源

五项能力分别拥有适用规则、Context、工具、HITL 和完成条件，共享运行承载。初期仅启用已经实现并验证的能力和格式；未实现请求明确返回不支持，不转成另一项能力并冒称完成。数学先行，当前先验证八年级完整全年规划；后续课时与完整单元首先沿线性函数及相关先备展开；其他数学主题的通用入口不代表已验证全部 K–12 数学。

每项能力使用版本化的规则资源，标明上游来源、采用／调整／不适用及理由。教案创建继承已有全部 39 条 rubric 取用映射；适配、备课与 CFU 在各自实现票内逐条落实自己的规则，不能套用教案 rubric 代替。框架调用者实际装配资源并记录清单，不能只把一个开发文档路径交给模型。

既有适配数学规则允许某些数值变化，而共享材料规范强调共同任务。首批实现先完整支持保留核心任务、目标与情境的支持和拓展；涉及核心题目变体的请求必须显式识别、保留与原题的关系并独立验算，不能让共同内容引用覆盖变体。是否已有对应实现要在能力范围中如实返回。这是有范围的实现顺序，不把“永不允许变体”写为教学原则。

### 2. Context 与知识

Context 包含本次适用规则、任务及授权范围、学校条件、相关 Learner Model／学习证据、实际课程和产物版本、真实决定、已完成动作与待修问题。规则和输入有来源及版本；超出容量时按任务拆分和按需读取，不能静默截断关键要求。

全年蓝图先取得本年级完整 CCSS 内容与数学实践视图，按需深入知识节点；单元和课时取得上层目标分配、Narrative、入口／出口、时间与前后依赖，并保留实际任务交接。允许模型使用内置知识进行数学推理、教学创作和合理设计推断；标准原文、图关系、学校事实和学生状态必须有相应真实输入，不由模型补造。

本地 LC 只读接入优先使用 `browse` 能力。完整遍历必要的分页与层级，读取实际 Learning Components 和相关前后关系；“注册了工具但未使用”不计为已取得依据。严格遵守知识使用约定：`supports` 从 LC 指向标准；`buildsTowards` 区分前驱和后继；`relatesTo` 不当先修；层级、组成、课程依赖和对齐角色不互换。保留实体身份、框架身份、版本、来源、原关系方向及用途。查询的完整、部分、空集、排除与失败分别记录。

LVN 研究因素和策略可在适用时补充，但不是所有任务的必需数据源，也不代表某学生的实测状态。已完成的数据本地化和 API 服务由外部提供。

当前全年工作已获准研究对应 IM，并记录已接触的来源、版本、用途及对设计的影响。独立课程组织仍须有自己的目标和条件依据，不以 IM 目录作答案。运行输入清单区分设计依据、参考材料与评估保留样本；独立评阅不读取作者对话或另一评阅者结论。今后若专门开展未接触参考的实验，另固定其隔离条件，不把该条件追溯套用到本轮，也不承诺消除预训练记忆。

### 3. 模型循环与工具

当前 Gemini 与既有 LangChain Adapter 继续复用，模型、配置及依赖版本记录在运行证据中。全年工作按下述阶段成果组织：图保证依据、检查与交接成立，模型负责数学及教学判断；需要动态取证时在阶段内调用 Agent。充分输入的设计／审查可直接结构化调用模型，不要求作者与审阅各是一个长期 `create_agent`。不按 Grade／Unit／Section／Lesson 建自治 Agent 树，也不按每条 rubric 建节点。

这一选择要解决的是整稿生成与整稿审阅难以定位基础缺口、局部修改仍混入无关历史的问题。新图本身不证明质量提高：先验证集中 Context 和具体反馈是否有效，再区分显式阶段控制的增量作用。保留充分资源的简洁循环作可比基线；暂不同时更换 Gemini 传输 API、模型或增设通用框架。Claude、OpenAI 与开源模型接入仍属后续范围，自动选模及多模型投票不作为当前前置。

工具至少支持范围受控的知识读取、实际产物读取与版本化写入、数学核验、必要图形／文档渲染、检查记录与真实待答。模型提交内容或提出动作建议；程序验证权限、状态、资源和版本。模型不能自行设置“人工同意”“检查通过”或交付事实。数学执行限制表达式、时间和资源；不把模型任意 shell、代码或 URL 直接交给服务执行。

### 4. 任务级调用约定

调用方是受信 Web 后端；身份与授权来自服务认证上下文，不信任正文中自称的教师、管理员或租户角色。未启用能力、格式和不合法范围返回明确错误。传入外部材料应可解析为有权限的本次实际内容及指纹，不能只保存一个会变化的“最新”链接。

**采用 Agent Server 原生 API／SDK 承载任务操作。** [运行说明](../../docs/runtime.md)及 [实际契约](../../docs/contracts/)说明已支持范围；下面规定教学语义，新增行为随对应票实现，不另建 `/v1/tasks` 服务或空接口。

| 操作 | 需要保证的教学语义 | 交付位置 |
| --- | --- | --- |
| 发起／查询／订阅 | 保存实际范围与输入；读取已有进度、草稿和结果不触发生成；重连查询权威状态 | 01 已有有限实现；各能力扩展 |
| 回应 | 保存真实原话及所回应对象；接收、采纳和续作是不同事实；重送去重，新意图不能被旧回执吞掉 | 02／16 及各能力 HITL |
| 修订 | 对明确的当前基线和对象工作；阻止迟到结果覆盖新稿；返回具体影响与重查 | 当前全年内部回修由 24／25；公开跨层修改由 07 |
| 续作／取消 | 依据保存成果和明确条件续作；不能越过真实待答或重开已取消工作；取消先禁止旧提交 | 05；自动故障恢复由 18 |

`capability` 区分 `curriculum_design`、`lesson_creation`、`lesson_adaptation`、`lesson_prep`、`check_for_understanding`。`scope` 明确数学学段、请求层级或焦点、内容范围与所需交付，CCSS 框架由服务固定。`context_refs` 指向实际课程、学校条件、学习证据等快照；具体个体字段按用途读取，不要求上传完整学生档案。

快照最少返回 `task_id`、`view_revision`、实际请求范围、运行状态、候选／已交付产物引用、当前待答、检查及未解决项、已采纳决定和累计消耗。运行状态区分排队、执行、待人、停止、失败、取消和完成；检查结论、人类参与及交付范围分别表达。完成只指该任务请求的工作及其能力退出条件成立，不等于课程已发布或学生已学会。

待答对象包含自然语言问题、必要的实际内容展示、目的、作用对象与版本、允许的回应形式。可提供少量有意义选项，同时接受自然语言；无需用户认识内部场景名。请求展示快照与产物版本分开，后台进度改变不自动使一个仍有效的回答失效。

变更操作返回持久事件回执，分别可查询接收、解释／采纳及续作状态。相同 `event_id` 在同一身份／客户端与操作范围内去重；相同身份事件却正文不同返回冲突。发起操作在尚无任务 ID 时也能去重。新的事件代表新的回应或意图，不能仅因旧请求已处理而丢弃。过期或冲突回应保留原文并解释适用范围，必要时请求澄清。

进度订阅只传受权限约束的业务信息，断流后重新查询权威快照；不向 Web 暴露原始模型消息或以 trace 当数据库。产物通过受控引用读取，校验访问范围及内容指纹。第一票交付发起／查询并发布由实际类型生成的 OpenAPI；其余操作随行为票加入，禁止空接口假实现。

**维护者诊断：**上述限制针对普通教学调用。初始开发阶段提供原生模型消息、工具请求／返回及运行状态的诊断读取，须同时满足服务端启用诊断、身份有维护者资格及原有任务访问权限。生产默认关闭详细诊断，保留管理员显式开启的路径；不能将有权限的追踪需求永久写死为拒绝。关闭后新订阅、重连和内部状态读取都按当前权限核验；已经交付给维护者的数据无法收回。基础执行结果与累计消耗继续记录。LangSmith 尊重服务端显式配置，不因普通前端不开放消息流而强制关闭；原生流可由维护者消费者保存以便复核，平台关联与故障验收仍由观察票承担。

已有首票作者／审阅子图及检查点诊断是运行基线；全年新阶段不能取消维护者对实际输入、模型请求、工具请求／返回和错误的追查能力。生产默认关闭详细诊断，授权开启路径保留；LangSmith 是否发送由独立的服务配置决定。阶段内续接证据不等于公开续作入口或生产恢复通过。

服务外调用例和基本可信访问边界从首票开始，后续能力随行为更新；最后的五能力消费者票只做汇总与兼容核对。初始内容引用支持调用方已规范化的真实文本／结构内容和明确版本，不以任意上传格式解析作为备课前置，也不要求原课必须由本仓库生成。

### 5. 存储、调度与恢复

本节描述完整运行目标；当前文件化阶段以文首约定为准。JSON 工作文件不承担 Agent Server checkpoint 的替代实现，数据库支持的部署与事务恢复暂不作为内容切片前置。

一个教学任务对应一个 Agent Server thread，可有多个 run；同一任务串行演进。业务存储保留任务、原始事件、展示快照、采纳决定、待续作动作、产物版本与检查引用；框架 checkpoint 保存执行续接状态，两者职责分明。

原始事件先持久接收。解释完成后，以条件更新将“动作采纳”与“待续作标记”在业务事务内一并保存，再交给 Server 调度。调度结果不明时先核对已存在 run／操作，再重试；执行前复查动作、取消和基线条件。模型调用可能因故障重复计费，但不得重复采纳人类决定、提交相同副作用或出现相互覆盖的有效版本。复用 Server 队列，不另造通用调度平台。

产物先写不可变内容并核验可读，再以引用提交版本；不能把数据库已提交但文件不存在的内容宣布交付。新检查绑定实际输入内容指纹和规则版本，旧检查不因文件同名而沿用。跨层修订保留修改前的依赖，并检查新产生的依赖，不能只遍历更新后的图。

Harness 提交本任务工作版本；跨任务共同课程基线由其所有者按预期旧版本进行条件采纳。外部未确认采纳不宣称公共基线已更新。个人支持变更保持自己的范围。

可恢复运行保存模型、规则、工具与状态语义版本。等待跨部署时保留兼容执行路径，或显式迁移并记录差异；仅写一个版本字段而没有可执行旧路径不合格。生产方向采用 Standalone Agent Server；冻结部署版本后核对许可、PostgreSQL／Redis、持久产物、备份与恢复。dev 重启证据不替代生产验收。

### 6. HITL 的教学语义

可自行检索的资料先检索，已有本次有效事实和决定直接使用。只有缺失且影响设计的真实条件、超出授权的重要取舍、能力要求的真实贡献或明确请求审阅才等待。等待跨越进程；定时器、模型回答或测试脚本不能冒充真实人类。

各能力遵守“交付范围与能力边界”中的独立流程：课程取舍不强加每层审批；创建不重复索取同一授权；适配整套接受与部分接受分开；备课先呈现原任务，正常路径在教师贡献前不泄露待其提出的 near-miss；CFU 明确改向后直接按新焦点构建，除非还有真实歧义。自然语言解释必须覆盖否定、条件、简短答复和改变意图，不依赖固定关键词选项路由。

教师的数学判断也可有误，应给出有据纠正；记录“参与者说过”不能将其提升为已验证数学事实。退出、取消、仅生成待后审和正常完成分别记录，不能用沉默补出满意或贡献。

### 7. 内容、检查与修订

共同任务使用同一实际内容源生成师生视图，按受众控制说明、答案和元数据。首批交付 Web 可展示、可打印的 HTML／SVG 与可编辑源；必要函数图必须实际绘制、检查和可读。Word 等显式要求仅在相应适配可用时承诺；不能默默改格式。独立的多轮精细制图平台后置，不影响当前必要图形的质量要求。

内容格式需覆盖公式、含公式的表格、精确数学图和一般图片的保存、读取、修改与重渲染。当前采用 JSON 工作源及独立图件，检查绑定实际内容指纹，前后端遵循同一约定。最小形状与往返验证见 [文件化内容格式](content-system-design.md)；不引入另一项目的 authoring，也不将编辑器、数据库或内容历史作为此前置。

内容检查包括适用数学、解法、表征、学生推理、课堂条件、任务与目标、实际材料及跨层一致性。确定性计算、模型审阅、真实文件渲染和人工评阅分别保留证据与局限。程序检查不把教学判断写成大量硬编码情境；模型评分也不自授交付权。

CFU 在学生页与教师指南实际写入后执行两道检查：独立读者只收到学生可见内容，判断所有可辩护回答；另一路按实际数量检验每条错误／回应解释能否产生相应作答。单选、多选、开放题各按题型判断，不强制开放题“只有一个答案”。隔离读者不能接触答案、生成历史或缓存，也不能遗漏学生能看到的图题、描述和格式泄题。

问题返回生成模型核实与修订，保存具体对象、证据和变化；允许反驳检查误报。改动后重查受影响实际版本。必要范围未完、严重数学问题、关键学习机会缺失、必要材料坏损、伪造来源／人类或受众泄题阻止相应交付，不由总分抵消。停止保留草稿和未解决项，不降低要求宣布完成。

### 8. 观察、评价与消耗

从首条真实路径记录调用、工具、产物、检查、修订、实际 Context 清单及消耗，关联业务身份与版本。LangSmith 用于 trace、数据集与评阅，不充当人类决定、发布状态或主记录。真实服务连通先用独立合成数据验证，发送内容按身份和数据政策筛选；Key 不进入内容或日志。观察发送失败不使业务任务失败。

正常任务积累能力、范围、复杂度条件、质量、token、重试、工具、修订和耗时；活动与人类等待分开，跨恢复累计，未知值如实标记。保留失败和触限样本。先保障质量，再用同类任务比较优化；探索中的 12／24 次不成为默认上限。仍尊重明确资源限制、可配置防失控边界、取消及保存续作。

默认不设累计 token 预算，只记录实际消耗；不能用自设额度或消息字节数预留截断有进展的工作。兼容的调用方显式 token 阈值按实际已用量停止后续调用，不承诺单次调用内的硬上限。格式错误须提供具体定位，作者修复源、重渲染并重查，不能以“草稿已保留”结束可修复的材料问题。

评价从能力实现开始。当前全年按 [评估协议](year-planning-evaluation.md)及固定的八维判据运行；23 提供可执行证据与检查校准，24／25 在生成中使用适用检查，26 对固定候选和 IM 独立比较、修订复评。规划证据按目标和数学职责对齐，不按单元编号或是否像 IM 打分；不可观察不能计零，重大失败不能被总分抵消。规则先固定，改规则时重评双方，保留原始记录。

四项既有能力继续与固定上游规则、完整输入和真实流程比较，原规则与本项目采用规则分别报告；优先同模型、可比工具／资料，原宿主体验对照另列混杂因素。11／19 承担这些能力的对照，12／20 承担后续完整单元比较和修订，均不替代本轮全年评价。当前已接触 IM 的事实随全年及后续内容保留。

离线评价不依赖 LangSmith 在线。专业评阅校准、相关条件下的重复运行和明确取样范围是质量声明的依据；暂无相应参与者时如实交付模型辅助初评及待复核项，不冒充专家或课堂证据。判断新结果更好、判断 Graph 导致改善、判断已达到 IM 的可观察水平，分别需要证据。

| 方法是否有效 | 不把换 Prompt／资料或模型造成的变化归给 Graph | 同模型、可比资料／规则／工具的阶段性对照；质量、遗漏、失效结果、返工和消耗分开报告；保留失败 |
| 后续教学能力 | 防止把全年方法直接套用后就宣称迁移成功 | 各能力实际任务、原规则取用、HITL、材料与修订；03／17／06 及 11／19／12／20 各自验收 |
| 运行与外部接入 | 让真实决定、访问边界和成果在故障下仍可信 | 02／05／18 的事件与恢复；13／21／22 的部署、撤权和升级；14 消费者契约，04 观察隔离 |

**三个结论分别报告。**

- **工程完成：**某票所承诺的接口、检查和运行证据齐备；不能推出全年质量通过。
- **全年规划质量：**全范围检查完整、无已确认重大问题、阶段与阅读稿一致，八维有有效结论。相对 IM 仍有影响目标、进程、练习、评价或可行性的关键差距时，在全年层继续回修；证据不足或待专业复核保持未通过，不靠总分或工单关闭恢复 03／17／06。
- **方法和水平声明：**达到 IM 的可观察规划水平须有完整可比证据、独立复核和无未决关键差距；Graph 的增益须有控制其他因素的比较。对当前样本的结论不外推所有年级，也不冒充课堂学习效果。

阶段性可交付候选、比较报告及具体不足，不降低要求冒称最终目标完成。专业评阅外部条件尚缺时，独立前置工作继续，人工门槛保留未通过。用于广泛非劣结论的样本和界限，在正式结果出现前依据试运行确定；不事后调标准。
