# 年级课程评价与检查校准：实现与真实运行证据

日期：2026-09-17。对应 [ticket 23](../../issues/23-year-evaluation-and-check-calibration.md)，实现前基点 `e28c3d3721e304782c7f167f1fda3ddf14a8c6c1`。本报告的所有评分、裁定与检出统计都是**模型辅助结果**，没有数学或课程专业评阅者参与校准，不能当作检查器可靠或课程质量通过的证明。

## 结论

**已经可用的部分。** 本地命令能冻结评价配置，登记本项目与 IM 的规划材料，按原文位置和指纹回取证据。它执行程序检查和两次独立的模型评阅，把评分收敛为维度结论，未决时不出总分；也能做模型辅助裁定、比较与敏感性计算，把发现交回模型修订或驳回，最后生成可重算的结果表。

**检查器能发现什么，漏了什么。** r1、r2 是同一 Gemini 模型、同一冻结规则的两次独立调用，下表是人工逐条核对后的检出数（自动匹配数见[结果表](results/report-tables.md)）：

| 样本类别 | 程序检查 | r1 | r2 |
| --- | --- | --- | --- |
| 调试集：结构性注入（评价早于教学、课时合计超出、目标只剩空泛分配） | 2／2（第三项不归程序判断） | 3／3 | 3／3 |
| 调试集：15 初稿已知漏检（7 项） | 不负责 | 3／7 | 3／7 |
| 调试集：15 修订稿已知漏检（4 项） | 不负责 | 0／4 | 0／4 |
| 保留集：注入问题（5 项） | 0／0（均为语义问题） | 4／5 | 4／5 |
| 合法对照（调试 2 个，保留 3 个） | 0 个误报 | 0 个误报候选 | 0 个误报候选 |

- **检出较稳定的**：结构性和明显的年度安排问题。包括评价早于教学、依赖顺序反转、目标只剩空泛描述、课时合计矛盾、核心活动依赖条件外器材。
- **系统性漏检的**：
  - 探查题中的数学与统计细节，即模型适用范围、恒等式与无解、“任意两点”缺条件、统计样本范围与截距外推、虚构取样过程。
  - “回访被删而全年叙述仍承诺”，两位评阅者都漏了。部分原因在检查设计本身：Q5 的回访对象取自候选里的 `apply／revisit` 分配，分配一删，这个对象就不在应查清单中了，只剩全年叙述里的一句话。叙述中的承诺没有结构化，程序与清单都无从追查。
- **严重度偏低**：“机动课时重复计算”被判为局部或关键缺口，而非重大失败；“目标只剩空泛描述”都判为关键缺口。
- **评分明显偏宽**：15 终稿两位评阅者八维完全一致，加权 95 分。但 [IM 对照](../../comparisons/im-grade8-blueprint-comparison.md)已指出实质差距；r1 还在两个保留样本的**未改动内容**里指出了终稿自身的问题（交接称 8.F.B.4 在第 4 单元应用却没有对应分配；第 6 单元回访证据写在“全年中期诊断”，而该单元在第二学期），评阅终稿时却都没有报告。因此同模型两次一致不能说明可靠，当前分数不作任何质量声明。

**回修闭环已走通，但复查同样偏宽。** r1 在终稿上的发现 `model:r1:b-final:q8:1` 指出“单元课时压缩时各单元内部的内容优先级和裁剪预案未作说明”（r2 给出同类发现，并明确是第 3 单元以外的单元）。交回模型后，模型核实该发现成立，只修改了交接说明一个字段，程序确认其余内容完全不变。修订只补了第 3 单元的压缩取舍，复查却不再报告该问题、Q8 给 4 分，程序据此把发现记为已解决；人工核对认为只解决了一部分。同一次复查中，未改动的 Q2 也从 3 分变为 4 分，属运行间波动。另一条人工构造的陈旧误报（把初稿已修复的沙水器材问题套到终稿）被模型用三处可核实原文驳回。

**交给 24／25 的具体弱点。** 语义审阅不能独立承担探查题的数学与统计核查。24／25 应把关键探查的独立求解与数据范围核算做成单独的检查工作（必要时由程序计算表格数据的取值范围），并把“承诺—实际位置”的回访与评价对应关系落到结构中，交给程序核对。不能靠提高评阅提示的严厉程度来弥补。

## 怎样设计，为什么

**尺度只有一份。** 维度、权重、锚点与裁定规则从 [规则数据](../../year-planning-rubric.json)读取；读取时与 [评估协议](../../year-planning-evaluation.md)第 4 节的权重表互相核对，任一改动不一致即拒绝。评分记录类型覆盖规则数据要求的全部字段。

**冻结在先。** 2026-09-17 冻结 [配置](config.json)：规则、协议、评价条件、评阅与修订规则、调试样本与答案、保留集目录、抽取清单和 IM 来源各有指纹。评阅保留样本前核对这些指纹，任何改动都拒绝运行。配置同时记录证据范围、参考接触清单、评阅者的输入与排除项，以及局限。

**证据分层。** 每条证据保存来源文件指纹、JSON Pointer 或字符区间、原文片段和不补写的提取；判断写在对象结论或发现里。核验时分别报告快照缺失、文件改变、位置失效与原文不符。模型引用只保存原文片段，提取统一标明“判断见所属结论”。

**对象级核查。** 每维有应查对象清单。Q1 按完整来源范围列出 36 项目标与 8 项实践，不按候选自报。Q7 在调试后改为按每个单元、每个探查和教师准备逐项核对资源。对象结论分为有依据、局部缺口、关键缺口、重大失败、未核实、不适用。以下情况都进入汇总状态，不计零也不算通过：分数与对象结论矛盾、覆盖未完、引用失效、只有一位评阅、不可观察、不可比、评分不一致。

**独立评阅的输入。** 每次评阅只装配以下内容：按稳定身份呈现的候选、15 初稿请求中的原始任务与合成学校条件、年级标准与数学实践原文、公开判据和应查对象。不含作者对话、15 的 `checks.json` 与 `context.json`、修订请求与旧稿、另一评阅者结论、样本改动与答案、IM 材料。每次调用前程序核对输入中不含任何答案说明（`assert_isolated`），修订调用同样核对。

**按身份定位。** 冒烟运行中模型按数组下标数错了目标位置，引文真实却指错了地方。评阅与修订输入于是改为以单元编号、目标代码、探查编号和“单元:角色”为键，由程序换算回下标。此后 Q1 的 44 个对象引用全部核实。

**引用失效与漏交维度时补交一次。** 程序在同一会话中列出失效引用或缺失维度及原因，要求重交一次，与格式错误的处理方式相同。冻结后 r1 有 26 个维度组发生补交，首次作答的失效引用 39 条、补交后剩 2 条；r2 分别为 24 组、42 条、3 条。剩余失效引用使相应维度判为“引用失效”，不采用。

**程序与模型分工。** 程序只核对结构事实：覆盖、首次教学前的评价或回访分配、声明依赖顺序、课时合计、知识条目是否来自实际查询。它与生成阶段的 `check_year` 覆盖同类事实，但逐对象定位；`check_year` 仍是 15 生成图的放行规则，二者在 24 定型新契约时统一。统计程序检出时，只计答案标明程序应能发现的问题。

## 校准样本

所有注入与对照都在 15 终稿副本上按记录的改动生成，改动后仍须是合法的年级课程；答案写明位置、可接受的维度、对象、严重度、应由程序还是模型发现，以及用于区分同位置不同问题的关键词。

| 集合 | 样本 | 内容 |
| --- | --- | --- |
| 基准 | `b-final` | 15 终稿，作为评分、裁定与回修对象 |
| 调试 | `d-known-initial`、`d-known-revision` | 15 初稿与修订稿，11 项人工核读发现（已写入 15 生成期审阅规则，只能调试） |
| 调试 | `d-assess-early`、`d-time-sum`、`d-opportunity-empty` | 首次教学前的评价分配、课时合计超出、非线性函数目标只剩空泛描述 |
| 调试 | `d-control-renumber`、`d-control-resource` | 全部单元改编号；勾股证明评价改用方格纸面积拼合图 |
| 保留 | `h-opportunity-empty` | 双向表目标只剩空泛描述，相关叙述、完成表现和评价被删 |
| 保留 | `h-assess-before-learning` | 函数单元的单元末评价加入尚未学习的消元法（结构分配不变） |
| 保留 | `h-reserve-double-count` | 机动计划称 8 节用于单元末测试，同时说明单元课时已含测试 |
| 保留 | `h-revisit-dropped` | 删去体积单元的开方应用及相关表述，全年叙述仍承诺 |
| 保留 | `h-order-dependency` | 方程组单元移到函数单元前并删去其先备声明 |
| 保留 | `h-control-swap`、`h-control-revisit`、`h-control-resource` | 无依赖单元互换并同步叙述；方程组单元新增有目的的函数回访；动态演示改为静态分步图解 |

保留集的问题类别来自公开协议第 7 节，评阅规则含这些类别的一般说明；保留变体在对象、位置和表述上没有参与调试。

但保留变体不是盲设的：它们由规则作者在写完 v1 规则之后设计。v1 已含“评价要求之前是否已有学习机会，包括单元评价安排文字中描述的评价内容”“总结性承诺没有对应安排属于缺口”“机动时间重复计算”等句，与部分保留变体的构造方式直接对应。v1 原文已按指纹 `6927f1f0f433` 还原并核实，见 [rules-history](rules-history/grade-review-v1.md)。因此保留集的检出数可能偏乐观；更可信的检验需要由不接触规则的人设计变体。

两位评阅者在 16 个样本上的 128 对维度分中：97 对相同，27 对差 1 分，4 对差至少 2 分，3 对重大失败结论不一致。Q2 和 Q8 的差异最集中（各 7 对差 1 分）。

## 独立评分、裁定与比较

- **15 终稿**：八维两位评阅者一致，全部定分，加权 95、等权 93.75。这个结果本身就是上文所说的宽松证据。
- **15 初稿**：Q7 两位都判重大失败（0 分），Q4 都给 2 分。Q2、Q3、Q5、Q6、Q8 各差 1 分，汇总时未取平均，只给区间并暂不出总分。随后 r3 读取双方原始评分与引用逐维裁定，定为 3、3、4、3、4。Q3 的依据第一次有失效引文，补交一次后全部核实；失效依据会保留在裁定里，使该维判为引用失效，与评阅的处理一致。裁定后加权 71.25、等权 71.875，并带重大失败标记。成对比较中的“评阅者优劣方向相反”目前只使该维判为未定，专门复核由 26 的正式比较承担。
- **比较（终稿对初稿）**：初稿有已确认重大失败，裁定为“对应范围不合格”；加权与等权方向都偏向终稿，各权重上下浮动 20% 方向不翻转。Q8 初稿得分更高，这也说明维度分并不稳定。

## 怎样重跑与核对

需要 `uv sync --frozen`，并在 `.env` 中配置 `GEMINI_API_KEY`。程序检查、索引、汇总、核验与报告不调用模型；`review`、`adjudicate`、`revise` 调用 Gemini 并产生费用。LangSmith 不需要在线。

```bash
uv run python .scratch/math-harness-delivery/evidence/23-grade-evaluation/im_snapshot.py
uv run python scripts/evaluate_grade.py materialize
uv run python scripts/evaluate_grade.py program
uv run python scripts/evaluate_grade.py index
uv run python scripts/evaluate_grade.py freeze
uv run python scripts/evaluate_grade.py review --reviewer r1 --split all
uv run python scripts/evaluate_grade.py review --reviewer r2 --split all
uv run python scripts/evaluate_grade.py calibrate
uv run python scripts/evaluate_grade.py adjudicate --candidate d-known-initial
uv run python scripts/evaluate_grade.py summarize --candidates b-final,d-known-initial
uv run python scripts/evaluate_grade.py revise --candidate b-final --reviewer r1 --finding model:r1:b-final:q8:1
uv run python scripts/evaluate_grade.py revise --candidate b-final --reviewer constructed --finding human:constructed:b-final:q7:stale-resource --finding-file .scratch/math-harness-delivery/evidence/23-grade-evaluation/results/revision/constructed-stale-resource.json
uv run python scripts/evaluate_grade.py verify
uv run python scripts/evaluate_grade.py usage
uv run python scripts/evaluate_grade.py report
```

说明：

- `freeze` 会重写冻结配置，只在建立新配置版本时运行；现有配置冻结于 2026-09-17，之后规则、样本和答案都没有改动。
- 已有评阅结果会被跳过。`revise` 已有结果时不再调用模型，只按保存的复查结果重算发现状态；加 `--force` 才重新调用。
- 冻结内容改变后，保留样本评阅、汇总、裁定和修订都会被拒绝，必须另建配置版本。
- 新冻结的配置还会记录评阅装配与应查清单代码（`review.py`、`checks.py`）的指纹。现有配置冻结时没有包含这两个文件；冻结后它们只在代码审查中做了不改变装配内容的调整：位置换算的失败标记、评分记录中的规则指纹、用量完整性。逐条核对一次评阅：

```bash
uv run python scripts/evaluate_grade.py show --reviewer r1 --sample d-known-initial
```

它列出每维分数与理由、非“有依据”的对象、每条发现及其原文位置、失效引用，并与答案对照；加 `--all` 同时列出“有依据”的对象，加 `--round round-1` 查看第 1 轮调试。模型实际收到的输入和原样返回在本机 `work/grade-evaluation/transcripts/<评阅者>/<规则指纹前 12 位>/<样本>-<维度组>.json`。

所有已保存证据重新核验：r1 1,946 条、r2 1,908 条、索引 25 条、裁定 17 条，全部通过（[verification.json](results/verification.json)）。

## 局限

- 没有专业评阅校准；同一模型的两次调用既无法互相证明可靠，也可能共享盲点。
- 注入样本、答案、关键词和对照都由实施者构造；自动匹配会出现一条发现命中多个答案或关键词误命中，报告中的检出数以人工核对为准。
- 保留集只有 5 个注入问题、3 个对照，比例和数量不足以估计一般检出率。
- 学校条件是合成条件；课时与资源判断不代表真实学校。
- 评分与复查存在运行间波动，未做重复运行的方差估计。
