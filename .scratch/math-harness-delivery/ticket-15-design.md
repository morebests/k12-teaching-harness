# 全年蓝图实施设计

依据 [ticket 15](issues/15-full-year-blueprint.md)、[交付规格](spec.md) 与 [整体推进路径](delivery-path-audit.md)。本票沿用首票任务运行机制，将内容推进到正式全年蓝图；随后由 ticket 03 展开实际 Lesson，再由 ticket 17 验证连续三课与上层交接。

## 契约与图

- 原生 Agent Server 任务入口增加 `scope=year`。全年范围由固定 CCSS 年级投影产生，调用方不传局部目标冒充全年。现有课段入口保持原范围。
- 年级内容 `kind=grade`，单独表达单元顺序、课时、Narrative、进入／完成条件、练习评价、各目标分工、八项实践、知识采用与关键任务探查。探查不等于完整 Lesson；本票不生成全年逐课材料。
- 复用 `prepare_task → author → prepare_review → reviewer → record_review`。准备、范围与时间检查、实际版本固定由 Python 执行；生成和独立教学审阅使用静态 Agent；阻断问题反馈给作者修订。
- 保存同一 JSON 源并生成阅读稿。格式问题返回具体字段，继续修复；程序和模型检查均绑定实际稿件指纹。没有默认累计 token 阈值。单条模型输出容量从 16,000 调整至 32,768，以容纳完整蓝图工具参数；这不是整项工作的累计预算。

## 知识完整性

逐层遍历框架年级投影及所有页，核对来源返回的框架、年级、父项、动态子项数和动态总数；重复身份、循环、缺页、空根和服务错误都不能产生完整声明。不用旧快照节点数作为验收常量。

保留分组和父子原文；叶目标用于不重复计数，父标准整体要求仍需单独核对。通用数学实践及年级实践说明分别保留。其他年级子项只记本次投影排除，不声称读取全 K–12。全年视图准备后，作者按设计问题查询组件和支持联系；采用条目必须指向本次真实返回的关系身份，课程推断另存。

## 下层交接与验证

`GET /v1/threads/{task_id}/units/{unit_id}?expected_fingerprint=…` 返回当前实际单元、完整目标分配、相关标准原文、学校条件、前后单元、实践和探查，并带全年稿与交接内容指纹。旧指纹拒绝；没有实现任意历史版本读取。

沿公开知识 HTTP、内容保存读取、原生任务 API 和模型适配边界逐项验证。真实运行使用已有合成学校条件：180×50 分钟，160 常规课时与 20 机动课时、28 人；无真实学生诊断。真实数据和模型的证据另存，不能以合成测试代替教学质量结果。目标参考课程持续隔离。
