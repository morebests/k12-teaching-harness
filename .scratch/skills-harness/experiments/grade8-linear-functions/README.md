## 先把来源的职责分清

“SAP 进阶”在此前讨论中特指 Student Achievement Partners 的 **Math Coherence Map** 所提供的标准间学习联系。它帮助查某个目标依托什么、支持后续什么，不是另一套标准，也不是现成的 Grade／Unit／Lesson 顺序。[SAP 官方介绍](https://achievethecore.org/page/2801/learn-more-about-the-coherence-map)

在本地 LC 已验证的样本中，这类记录带 SAP 来源的 `buildsTowards` 边；方向为基础指向后续目标。它与某套教材自身的课时依赖不同。具体查询及语义见 [本地知识研究](../../assets/learning-commons-integration.md) 和 [知识使用约定](../../../../docs/references/knowledge-consumption-contract.md)。

| 输入 | 从哪里取得 | 本轮如何使用 |
| --- | --- | --- |
| 学什么 | CCSS；本地 LC 提供带身份和版本的投影 | 已取得完整八年级内容标准与数学实践；官方导言作独立补充 |
| 目标包含什么细节、前后有什么联系 | 本地 LC 的学习组件、SAP 等来源关系 | 由模型按具体设计问题查询；不在准备阶段算出唯一教学路线 |
| 如何支持有关学习困难 | 适用的 LVN 策略／因素研究及一般教学知识 | 有具体问题时查适合学段的依据；未核查的 Math 3–6 样本不直接外推给八年级 |
| 模型如何开展教学设计、产物怎样算有质量 | 原 Skills 流程／rubric、CCSS 及适用课程评价依据 | 已筛成共同规范和逐条取用表；原有依据保留，调整仍需效果验证 |
| 时间、资源、学习者条件和实验安排 | 真实学校／调用方；暂无时明确提出研究条件 | 本轮使用注明来源为“研究设定”的条件，不从 LC／LVN 推断某所学校或学生状态 |
| 如何评分、何时比较、失败怎样报告 | 组织者预先约定，依据上述质量责任 | 生成前留下可检查判据；LC／LVN 是依据的一部分，不能替组织者决定本次实验条件 |

因此，需要**有选择地组合来源**，但不需要把 LC／LVN 全库拼成一份巨大 Prompt。共同规范、当前任务、完整目标是起始输入；组件、关系、具体策略和已有工作按需要回取；课程顺序、Narrative、题目与教学判断由模型生成和检验。

## 已落实的输入与研究条件

固定本地 `lc/v1.11.0`，递归取得八年级投影 71 个唯一节点并与本地计数核对。它包含 **28 条编号内容标准、8 个字母子项、8 项数学实践的完整说明**，其余为分组及年级下的实践条目。通用 MP1–MP8 与 8.MP1–8.MP8 保留不同身份，不计为 16 项独立实践。标准代码范围另与五个官方领域页面核对；这不是对所有来源全文或 CASE 远端现值的全面审计。

学校研究条件的唯一详细定义在 [共同规范](inputs/common.md#已给条件)：180×50 分钟、160 个常规课时＋20 个机动课时、28 人普通纸笔课堂、英语材料，无实际学生诊断。数值由本轮准备提出，便于约束可行性；不是美国统一要求，也未标为用户已确认或真实学校情况。条件改变时更新版本并重新检查受影响设计。

用户选定的方向是八年级线性函数。任务以 8.F.B.4 定位重点展开单元，其他有关目标由模型在完整蓝图中分配；“Unit 4”沿用为讨论标记，不当作原创单元必须排第四的约束。既未读对应 IM 结构，也未为模型代写课程设计。

## 有界实测怎样展开

当前执行链为：**全年蓝图 A → 实际版本交接 → 单元骨架和连续三课 B → 独立读题／材料检查 → 问题反馈与实际修订 → 复查 → 跨层需求修订**。这里的三课是 wayfinder 取样深度，不降低完整单元的最终目标；原创全单元未完成并冻结前，不启动 IM 对照。

原型使用一个能读知识、生成与回取文件、调用必要数学工具并继续修订的简洁模型循环。工具可用范围、返回中的来源过滤、版本与真实待答由程序承载；不按规范编号建立十几个 Agent，也不先实现整个 Agent Server。此阶段产出的代码只为回答 Context、模型与控制机制的可行性，生产运行专项仍按 README 时点推进。

已经落实的运行边界与剩余检查：

1. 已把本地 browse 的 CCSS 标准、相关 LC 与 SAP 支持联系接入有限知识工具，核查框架、方向、来源和快照。没有把 browse 整个类别放行，不返回 IM 课程节点、材料、对齐及 UI `groups`。
2. 账户实际接通 `gemini-3.8-flash`。初始 12 次调用是未经工作量校准的探索上限；B 第一轮交付不全后，下一轮明确改为 24，实际用了 22 次。工具上限 40、活动时间上限 20 分钟保持，所有失败保留。24 也不代表生产推荐值。实际 token 与缓存信息已记录，账单费用未知。
3. 输入、源码、模型配置、评价约定和产物保留指纹。问题实际交回模型两轮，学生数学解析错误从 58 降至 22，再到 0；同时发现检查器自身缺陷并保留更正。后续像素读题包含有效发现和误报，分别核实。跨层修订的文件／算术检查部分通过，教学时间与效果保证仍未通过；详见 [按原评价约定复查的结果](quality-review.md)。

本阶段已取得模型、知识工具与真实产物的有限证据。**尚未通过的是完整课程质量、稳定的修订效果、真实人类参与及完整服务运行。** 没有合适的真实教师时继续做机制和内容初筛，但不能写成教师使用通过或学习效果得到证明。
