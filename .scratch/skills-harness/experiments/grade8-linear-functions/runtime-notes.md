# 首轮真实模型运行：证据与发现

日期：2026-09-15。用途：wayfinder 运行实验记录，供开发者读取；不装入原创设计 Context。当前不是生产实现或课堂效果报告。评价依据保持为生成前的 [评价与取用约定](evaluation-and-adoption.md)。

## 这次实现与运行了什么

[runner.prototype.py](runner.prototype.py) 使用 LangChain 的 Gemini 适配器执行有限模型／工具循环。模型可以读取已给标准与任务、查询知识、进行数学计算、保存／回读／修订产物、提出真实待答或交接候选。程序记录输入、工具、产物版本、预算与停止；没有按课程层级设立多个自治 Agent，也没有实现完整 Agent Server。

使用 Python 3.13.5、`langchain-google-genai 4.4.0`、`langchain-core 1.6.3`、`google-genai 2.23.0`、`sympy 1.14.0`；完整实际依赖见 [锁定清单](requirements.prototype.lock)。这是本次实验版本，不是生产技术栈定案。适配依据来自 [LangChain 官方集成](https://docs.langchain.com/oss/python/integrations/chat/google_generative_ai) 与 [Gemini 工具调用文档](https://ai.google.dev/gemini-api/docs/function-calling)，实际可用性由下方调用记录验证。

模型进程仅从项目 `.env` 取得 Gemini 密钥，密钥不进入模型 Context 或运行记录。此次只记本地轨迹，没有启用 LangSmith 外部 tracing。真实 Gemini 调用使用 `gemini-3.8-flash`，设计任务采用 high thinking、temperature 1.0、最多 32768 个输出 token／调用、禁用自动模型重试。初始上限为 12 次模型调用、40 次工具执行和 20 分钟活动运行；B 第二轮和材料修订明确改为 24 次调用，另两项上限不变，实际配置逐次保存在 state 中。缓存读取与实际 token 使用按返回元数据记录，未取得费用的地方不推算为实际账单。

## 知识和输入如何进入模型

- 起始 Context 包含共同规范、本次任务、71 个实际 CCSS 来源条目的紧凑视图、完整 notes 和标准层级，以及官方年级导言。保留来源身份，提醒两套实践节点不是 16 项独立实践；没有只给代码摘要。A 的起始用户消息为 80,976 个字符，实际 token 数以每次调用记录为准。
- [知识工具](knowledge_prototype.py) 只提供标准、组件、前向／后向支持联系，不开放 browse 任意 URL。CCSS 使用固定框架及快照；组件与 supports 暂限已核查的 Achievement Network 来源，进阶边限 Student Achievement Partners，未知来源单独计数并排除。进一步证据见 [API 核查](knowledge-api-probe.md)。
- 前后年级标准端点核查真实根路径；API 的 `frameworkName=null` 不能代替框架身份。关系方向按 source→target 还原，原身份与来源继续保留。只有经过过滤的字段进入工具消息，原 UI groups 和课程节点不会回传。
- 当前模型没有 shell、任意文件读取、网页搜索或 IM 课程工具。只能读当前产物和明确交接的父产物。父产物按实际字节指纹核对；写入生成新版本，并保留历史内容。
- 已完成候选 A、B 的实际查询选择是 CCSS 标准和 SAP 前后联系；它们没有调用 `components`。LC 组件读取虽已通过独立工具样本，尚未证明在这两份生成结果中使用或带来增益，不能把“工具可用”写成“生成已利用全部组件”。
- `messages.json` 是实际发出的消息和收到的模型／工具内容；`state.json` 记录状态、配置、来源和产物；`events.jsonl` 记录 HTTP 与执行摘要。程序保留供应商所需的 opaque thought signature，没有请求输出私有思维链。源码与输入指纹用于复核，不能单凭关键词扫描声称完全排除了模型预训练影响。

## 先保留失败，再调整最少机制

[第一轮全年设计](runs/20260915T021611Z-overall/state.json) 用了 12 次模型调用和 12 次工具执行，60.277 秒后因调用预算耗尽停止。知识与数学工具无报错，**没有保存任何课程产物**。已保存原始消息和准确源码，不能把工具工作量或模型内部规划算作已交付蓝图。

下一轮只为预算增加可见反馈：每次工具消息附剩余调用／工具次数与时间，剩余三个模型调用时提醒优先保存可用成果并如实交接。教学输入、模型配置、知识范围和 12／40／20 分钟预算保持不变。这个变化没有指定课程答案或固定教学阶段。两轮各只有一次运行，表现差异还受到采样影响，不能据此宣称已证明稳定的因果改进。

[第二轮全年设计](runs/20260915T021738Z-overall/state.json) 在 12 次模型调用、17 次工具执行和 165.531 秒内保存了全年蓝图、三项探针说明和两张 SVG。蓝图自行安排九个单元，线性函数为 Unit 5、18 课时。程序核对 28 条编号标准与 8 个子项均出现，九个单元合计 160 常规课时；这只是覆盖位置与算术检查，不能证明全部目标有充分学习机会，见 [静态审计](overall-static-audit.json)。

修正一项初步判断：原检查一律拒绝 SVG 的 `url(#arrow)`，确实过于宽泛；但重查首次失败图发现它也没有定义 `id="arrow"`。因此该次拒绝不能简单归为误报。现在允许有真实目标的图内 marker，并分别检查两张已保存图、一个合法 marker 与三个非法样本。模型原先自行改成直接画箭头，轨迹完整保留；此检查不是生产 SVG 安全审计。

几何检查还发现两张探针图的线段斜率实际约为 2.0652 和 3.04348，与题目要求的 2 和 3 不一致；探针 1 图上直接给出了待求斜率。保存成功及算式求解正确，不能代替实际表征检查。

## 调用预算的依据与调整

**12 次没有经验校准依据，是组织者先行提出的探索上限。** 它控制一次试验消耗，不是模型能力、教学工作量或生产运行规则的结论。A 与 B 的任务大小不同，不能以共同调用上限判断它们应当同样完成。用户追问后，此处明确记录这个不足。

[B 第一轮](runs/20260915T022426Z-unit/state.json) 接收实际 A 与 [交接反馈](inputs/handoff-review.md)，在 12 次调用内只保存了修订说明和三张图，没有教案或学生题面；状态为预算耗尽，没有借结束工具冒充完成。预算提示仍不足以保证交付。

[B 第二轮](runs/20260915T022559Z-unit/state.json) 保持相同教学输入、A 版本、反馈、模型及工具，仅把模型调用上限明确放宽到 24。实际在 **22 次调用、22 次工具执行、179.740 秒**交接单元骨架、连续第 6—8 课的学生／教师材料、两张图及设计报告。24 也不是已证明的最优值；它使本轮不再被最初过窄的调用次数提前截断。两轮不是重复统计试验，不能据此给出稳定成功率或因果效果量。

后续生产预算应结合任务范围、实际消耗、交付进度和未解决问题确定。达到资源上限与教学验收不通过分别记录；恢复或扩大预算需要明确新的运行记录，不覆盖失败。当前没有通过增加固定教学节点来解决这次问题。

## 检查发现如何交回模型

首次交接已提供组织者反馈，但模型的修订说明未消除所有下游问题：教师表仍有“完全掌握”、学生图给出待求速率、实际字符图不准确、教师观察表混入字面 `\\n`，还有未兑现的支架与练习安排。

[独立读题](runs/20260915T022925Z-blind/artifacts/independent-solutions.md) 是一次全新 Gemini 运行，只取得实际学生 Markdown 和两张 SVG 源文，无教师答案、设计报告或组织者反馈。6 次调用、85.183 秒后，它给出逐题解答并发现缺图、网格措辞矛盾及图例泄题；未发现雪深字符图的位置矛盾。它检查的是图源与文本，没有收到渲染像素，不能称视觉评阅或独立专家结论。

组织者另进行了 SVG 几何核对、浏览器图形／页面走查和本地 KaTeX 0.18.7 渲染。修正渲染器对转义美元符号的解析后，学生页仍有 58 处 `\\text{______}` 解析失败，教师数学表达式零失败；这些有 [渲染清单](runs/20260915T022559Z-unit/review/render-manifest.json)，不能全归咎于模型或全归咎于渲染器。页面走查与数学审查分别提供证据。

[材料问题反馈](inputs/material-review-1.md) 按实际位置、问题与依据交回模型；[修订任务](inputs/repair-task.md) 要求核实问题、允许有依据地反驳误报、修改实际材料并列明未解决项。修订工作区把父产物按字节复制为 v0，后续写入保留新版本；父原稿不变。该循环未预先给出课程答案，也没有把每条发现写成固定执行分支。修订结果仍须外部复查，不能拿模型的修订报告作通过证据。

### 两轮修订实际发生了什么

- [第一次修订](runs/20260915T023107Z-repair/state.json)：22 次调用后交接，修正上层蓝图、实际图形及师生材料，新增两张图；学生解析错误剩 22 处。模型声称全文检查为零，与实际渲染不符，继续交回 [第二份反馈](inputs/material-review-2.md)。
- [第二次修订](runs/20260915T023658Z-repair/state.json)：增加 `check_rendering` 工具，直接检查当前文件。学生正文和探针说明中的剩余语法错误已修，CFU-6 改为可能解释与确认性追问。24 次调用用完时最后保存了报告，未调用完成交接工具，原状态保持 `budget_exhausted`；不能据此抹去已经保存的工作，也不伪造完整结束。
- 这轮同时暴露**原型渲染器的两个缺陷**：误读转义美元符号与结束定界符，误把 Markdown 行内代码中的公式示例作为数学渲染。修正已保存精确源码和 [变更记录](runs/20260915T023658Z-repair/renderer-change.json)、[行内代码修正记录](runs/20260915T023658Z-repair/renderer-inline-code-fix.json)。它们导致额外检查／改写，不能算模型的数学错误或把全部预算问题归给模型。
- 停止后，组织者用修正的渲染器重跑七份实际 Markdown，数学解析错误均为零，见 [最终渲染清单](runs/20260915T023658Z-repair/review/render-manifest.json)。图形、教学推断和版面仍按各自证据评价。第二次修订实际学生页已做浏览器走查；未进行纸张分页／打印验收。

有已保存成果但运行因预算停止时，后续检查或修订可显式使用该版本：`--allow-incomplete-parent` 记录原状态并核对字节指纹，不把父运行改成成功。它是明确的文件交接，不是恢复原模型会话、重启服务恢复或代替人类接受。

完整逐项质量发现及 Harness 启示见 [材料检查与修订证据](quality-review.md)。

### 像素读题与跨层修订的实际结束

独立 [视觉读题](runs/20260915T024257Z-blind/state.json) 使用实际学生正文和四张从原 SVG 渲染的 PNG；源码不进入模型消息，工具也不返回被隐去的 SVG 源文。10 次调用、10 次工具执行、120.997 秒后交接。它发现 TASK-8.1 的真实标注重叠，也误读了雪深图的网格；经同图查看与几何核对，后一项按误报记录。不能把“独立审阅”自动当正确裁决。

[跨层修订](runs/20260915T024257Z-revision/state.json) 沿实际修订 2 文件执行 18→14 课时压缩，用了 20 次调用、20 次工具执行、249.527 秒。A、B 课时表实际同步，全年为 156 已排常规＋4 未排常规＋20 机动；师生三课正文和所有图形保持，师生文件只改版本标题。这次主要改变尚未展开的后半单元，因此不能证明内容受到实质影响时的完整重修能力。

该轮有两次数学工具参数拒绝（尝试调用工具未允许的 `int`、`len`），模型继续完成；这不是基础数学计算失败。运行没有实际调用渲染工具，却在报告声称调用过。外部重跑七份新 Markdown 后均零解析失败，这个后续结果不能改写原工具轨迹。每课回顾与已排满 50 分钟的具体课表矛盾、压缩效果保证和图中文字重叠仍未通过，详见质量报告。

[运行汇总](run-index.json) 保留各轮实际调用、耗时、累计输入／输出 token 和缓存读取量。累计输入包含多次重传及缓存，不是唯一知识量，也不直接代表账单费用。局部修订仍装入全部 CCSS 与父材料，是明确的 Context 优化候选；尚未做较小 Context 的对照试验。最终 [有限审计](closeout-audit.json) 核对 59 条产物记录均匹配实际字节，保留父运行耗尽与子运行候选就绪的区别。

这次有界试验已完成 A→B→检查→两轮修订→复查→一次跨层修订的取样链，发现可行机制和未通过项。没有为得到“成功”而无限追加调用，也没有把预算上限调整成项目固定规则。

## 尚不能据此声称什么

此原型尚未实现跨进程恢复、已开始请求的严格取消、服务并发／认证／部署、长期状态迁移或完整人类回应恢复。`request_human` 可记录真实待答并停止计算；未出现实际请求与真实回应时，不算 HITL 路径验证通过。CLI 启动进程自身也不是完整 Web 后端。

### HITL 覆盖核对（2026-09-15）

[逐运行审计](hitl-coverage-audit.json) 读取了所有带 `state.json` 的 10 份运行记录，其中 1 份仅装配、9 份实际执行；逐条统计 `messages.json` 中的真实 `request_human` 工具调用，并核对状态。结果是 **0 次请求、0 份待答对象**。源码没有接收人类回应并恢复的入口，已有父产物交接不属于该入口。审计保留源文件与记录指纹，没有追加模型调用。

这里的工具只为这次已授权的课程生成实验提供“约束无法同时满足时提出取舍并停止”的候选出口；它没有落实五项能力各自的草稿审阅、适配接受、教师亲做和 CFU 焦点等待。两轮组织者问题反馈与一次模拟课时压缩检验的是内容修订，不能计为产品端人类回应；已有 HTML 原型的模拟按钮也不能填补服务器恢复证据。

因此当前结论分开记录：**HITL 教学位置已有设计基线；本次有限生成实验没有验证 HITL。** 具体位置见 [五项能力的 HITL 设计](../../assets/hitl-design.md)，运行落实见 [主执行与调用设计](../../assets/main-execution-design.md) 和 [运行架构专项](../../issues/11-agent-server-stack-research.md)。后续应验证一条真实待答、外部回应和持久恢复链，并另用故障注入检验恢复语义；模拟输入只能证明相应控制行为。

课程产物需要按本次范围逐项检查；`candidate_ready` 仅表示已保存候选及交接清单，不是数学正确、教师接受或教学完成的证明。单元只展开三课时，其他课时仍是骨架。原全单元与冻结后 IM 比较的目标保持不变，当前没有读取对应 IM 内容。

## 重跑方法

在仓库根目录运行：

```sh
uv venv --python 3.13 .scratch/skills-harness/experiments/grade8-linear-functions/.venv
uv pip install --python .scratch/skills-harness/experiments/grade8-linear-functions/.venv/bin/python -r .scratch/skills-harness/experiments/grade8-linear-functions/requirements.prototype.lock
.scratch/skills-harness/experiments/grade8-linear-functions/.venv/bin/python .scratch/skills-harness/experiments/grade8-linear-functions/runner.prototype.py overall --dry-run
```

去掉 `--dry-run` 会实际调用 Gemini 并产生新实验记录；`unit` 和 `revision` 必须用 `--parent` 指定实际候选运行。`blind` 必须用 `--include` 明确列出学生材料与必要图形，不能把教师答案一起交入。每次创建新的运行目录，不覆盖先前实验或自动追加已耗尽的预算。
