# 任务 A：八年级全年数学课程蓝图 v0.1

与 [共同工作规范](common.md) 一起使用。目标是形成独立、有理由、可以交给单元设计继续工作的全年方案。本次交付为蓝图，不生成全年所有教案，不声称全年教学材料已验证。

## 开始时取得什么

- 共同规范中的学校研究条件、工作方法和质量要求。
- [八年级标准](../resources/ccss-grade8.json) 的完整内容目标与层级、[官方年级导言](../resources/ccss-grade8-introduction.md)，以及 [数学实践](../resources/ccss-practices.json)。先读全年视图，不能只检索主题关键词。
- 可按需查询有关 CCSS 标准的完整文字、学习组件和来源可核对的学习支持联系。查前后年级是为解释本年级进入条件与后续用途，不扩展成整个 K–12 课程设计。
- 当前是新建课程，没有指定旧版课程、单元次序或实际学生诊断。

## 要完成的设计

组织完整 Grade 8 目标，提出自己的单元划分、顺序、时间与全年 Narrative；说明关键联系、跨单元的学习延续，以及复习和评价如何使用所留时间。依据目标的重要作用、学习跨度和工作量分配机会，不能把标准编号平均分成若干单元，也不能围绕一个验证主题遗漏其他领域。

本轮后续重点展开线性函数的单元设计。围绕 8.F.B.4 定位一个有内在联系的目标单元，并检查它与其余 8.F、有关 8.EE 及其他相关目标的职责和先备关系。这里指定的是关注主题与锚点，**没有规定把所有函数标准塞入同一单元，也没有规定其排第几个**。你要依据全年安排说明该单元实际承担什么，其余有关目标在哪里发展；不要把名称相近的内容自动合并。

遇到决定结构的数学跨度，可以先创作并求解少量关键任务作为可行性探查。探查的数量由实际问题决定，不能用孤立好题代替全年学习进程。其内容、结果和对方案的影响应留下，但不算已完成对应单元。

## 返回一份可交接的蓝图

用 Markdown、必要表格及真实探查材料表达，不需要先设计业务 API。内容应使接手者能够取得：

1. **全年方案及理由**：各单元自己的标识、目标、预计课时、进入条件、结束时期待的数学工作；全年 Narrative 解释安排及主要前后联系。
2. **目标覆盖视图**：每个内容标准及必要子项由哪里承担，角色是什么，如何发展并取得证据；八项数学实践如何在年内实际参与数学工作。标出尚待下层材料兑现的安排。一个父项和其子项不能重复计数为额外目标。
3. **时间与学习机会**：核算常规课时、练习与评价是否在总额内，说明已有学习如何继续使用；机动时间单列，不能同一课时重复计算。
4. **给线性函数单元的交接**：实际单元标识、范围、完整目标引用、Narrative、前后单元关系、进入／离开条件、课时预算、已采用的关键任务或表征（若有）、可改空间和未验证假设。不给空泛的“按前述要求生成”。
5. **版本与自查**：实际使用的资料与来源、设计推断、数学探查结果、发现并修订的问题、尚未证明的部分。蓝图可标为候选；不得写成教师已接受。

## 本次通过依据

全年目标有完整且有意义的承担位置，顺序和联系能解释，时间可行，目标单元有足够的实际交接信息。标准代码齐全只是覆盖检查的一部分，不能证明学生获得学习机会；这部分须由后续单元的实际任务验证。

可以在已给研究条件内自主设计。若认为这些条件无法支持目标，先给出具体证据与可行取舍；不要默默删除目标、挪用全部机动时间或补造先备掌握事实。
