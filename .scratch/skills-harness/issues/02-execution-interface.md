## Question

调用方如何启动课程体系、课时设计、教学适配、教师备课或理解度检查，提供设计范围、课程版本、学习者上下文与学校约束，回应具体请求并取得产物、检查和执行证据？

区分课程蓝图、可教学单元、实际材料等交付范围；设计长期任务的进度、暂停、修订与结果取得方式。课程基线与班级／个体调整分别关联，不能因一次个性化执行改变所有使用者的课程。

判断哪些运行操作可共用、哪些输入、交互与完成条件由具体能力定义。真实教师或课程设计者的已有决定可以作为本次输入，但必须关联其对象和版本；不能用模型推测代替。

外部提供 Web 界面、身份权限、学习证据、Learner Model、已本地化知识数据及最终治理，本票只定义教学 Harness 的对接方式。

## Comments

### Resolution：任务级调用、真实事件与有范围的结果（2026-09-15）

承接用户已明确的 Web 后端、自然语言输入、克制设计、五项能力独立及持续推进授权，依据既有流程与持久实测收敛调用语义。详细比较、操作约定、三段回应交接、示例与静态核对已补入 [主执行与调用设计](../assets/main-execution-design.md#调用方需要知道什么)。本次是技术收敛，不记为用户逐字段批准或生产验收。

1. **采用任务级 Interface。** 提供发起、查看／订阅、回应、修订、续作、取消六项语义；不直接把聊天消息／Server runs 作为完整教学接口，也不按场景或阶段新增操作。调用方提供需求和可信上下文，Harness 负责教学资源、模型／工具循环及恢复。补入续作是为明确预算停止出口，暂时故障仍自动处理。
2. **输入按来源和作用范围组织。** 原始需求与人类决定保留来源；课程、学校和相关学习者信息使用实际版本。CCSS、教学规则、模型配置与预算由可信后端和 Harness 提供，不转成教师表单。无原课的 prep 不自行造课；单元展开读取实际全年交接，不只传主题。
3. **真实回应分为接收、采纳、后续执行。** 先保存原文及请求快照，再解释并条件式采纳，最后可靠调度。每段均可查询；启动在取得 task 身份前也有稳定去重身份。已保存动作遇到故障由系统续作，不要求重答或重新解释为另一方案。生产持久待执行记录与 Server 队列的衔接仍需实现验证。
4. **返回业务快照与明确范围。** 当前工作、待答、回执、实际产物、逐项检查、人类参与、累计消耗和交付清单分别可取得。流与 trace 提供观察，不能代替权威记录；刷新是只读。蓝图完成不等于整年材料完成，材料可看不等于适配协作结束，质量通过不等于学校采用或发布。
5. **修订显式关联父版本和作用对象。** 等待中的修改可随回应提交；已结束任务的修订新建任务。独立班级／个人适配不覆盖共享课程；跨层问题带实际发现回查。共享基线由唯一权威写入方原子核对预期版本后采纳，不能靠同线程串行或生成前读取一次避免跨任务冲突。
6. **失败保留工作与可执行出口。** 回执丢失重送同一事件；身份相同正文不同报冲突；不同有效事件按新意图处理。预算耗尽与工具失败分开，取消先阻止旧结果成为当前交付，规则不兼容由维护者处理。既有各能力 HITL 和教学完成条件直接继承，不统一成批准按钮。

**证据和边界：**已复核关键上游条款及现有八类接口判别情况；这是静态设计。持久探针支持有限事件保存／恢复，不证明任意自然语言采纳、生产自动调度、跨任务课程提交或教学质量。正式路径、字段、事务适配及生产验收进入规格；无需为结束本票再建设一套服务。

后续进入 [模型、本地图查询和产物工具](04-runtime-adapters.md)，落实实际运行资源和工具职责；[质量验证](05-capability-validation.md) 保留未通过项及各能力不同的交互比较；[总体架构](06-architecture-conclusion.md) 汇总可行性与实现前条件。

### 持久运行证据对调用结果的约束（2026-09-15）

[运行原型](09-cfu-runtime-prototype.md) 已取得真实原型回应、13 项固定事件故障测试、Agent Server dev 重启及 LangSmith SDK 本地发送证据。机制支持主执行候选，具体结果见 [实测](../assets/cfu-durable-prototype-results.md)。

调用结果必须将“回应已持久采纳”与“恢复已调度／计算成功”分开。回复保存后进程可能退出，调用方不能因未收到成功返回就断言回应丢失；以同一事件身份重送或查询，应取得已记录动作的状态并继续同一工作。读取接口要结合图的实际中断、业务待答和取消状态：等待时原型 `state.phase` 仍为 `proposed`，不能直接把最后一个节点保存的字段当作教师可见状态。

实际内容引用、请求快照、产物指纹及检查版本分别返回和关联；请求快照不命名成产物版本，LangSmith trace 也不成为权威材料记录。CLI 文件锁与 Server 同线程调度只支持各自测试范围，生产跨任务的课程版本提交仍须落实。下一步收敛本票的少量操作、返回事实和错误语义，不继续展开新的场景菜单；本票保持 claimed，尚未形成正式规格。

### 主执行方案与 HITL 的具体交接（2026-09-15）

已形成 [主执行链、调用与运行承载](../assets/main-execution-design.md)：以自然语言需求和可信上下文启动，围绕发起、查看、回应、修订和取消定义调用方所需语义；内部装配实际规则与内容，执行模型／工具循环、检查和修复，按五项能力各自条件等待或交付。范围与能力决定语义，不将原型场景变成操作枚举。

HITL 不是一个只在约束冲突时偶尔调用的工具：已选草稿路径、适配整套接受、教师亲做和 CFU 焦点等已定参与条件，执行必须核对是否取得有效输入；模型另可提出新的必要取舍。真实请求、展示版本、原始回应与采纳动作需要可靠保存。现有 9 次 Gemini 执行没有发出真实请求，且没有回应／恢复入口；[覆盖审计](../experiments/grade8-linear-functions/hitl-coverage-audit.json) 已明确此缺口。

[完整运行专项](11-agent-server-stack-research.md) 将 LangGraph 的持久执行、Agent Server 的任务承载和 LangSmith 的观察评测一起校核。本文仍为候选：接口字段、恢复与并发的具体结果需锁定版本的小型运行切片验证后收敛。本票保持 claimed，不将设计文档或研究完成写成真实 HITL 已通过。

### 回到主执行方案收敛（2026-09-15）

用户纠正工作方法：新话题先评估价值与依赖，不自动成为下一项工作。当前优先以已有课程、流程、HITL 和真实生成／修订证据收敛本票，避免继续逐图或逐页优化。

下一份结果应把主链讲清楚并足以供实现前运行专项使用：任务怎样启动；全年／单元／课时的实际版本怎样交接；适用教学规则、知识、工作内容和反馈怎样装配；模型与工具怎样推进；检查、修订、真实待答和停止怎样返回；哪些职责由调用方提供、哪些由 Harness 保证。仍分别保留五项能力的教学语义，先收敛调用者必须知道的事实，不从场景编号或字段枚举开始。

本票取用实验发现而不将当前 CLI 原型提升为生产结构。内容修订已有有限证据，长期状态、真实恢复及并发等仍需 [完整运行时专项](11-agent-server-stack-research.md) 核对框架已有能力，再反馈具体实现。数学可视材料模块及局部 Context 消耗优化后置，除非出现足以阻塞主执行决定的证据。

### 数学可视材料的独立调用与修订候选（2026-09-15）

用户提出将图等非文字资料生成单列，早期表达意图、目的和形式建议，之后多次精细生成。已评估并记录 [数学图形与可视材料候选](../assets/math-visual-materials-design.md)：以自然语言教学请求、实际任务／图版本及必要约束调用，返回用途说明或实际图件、差异和检查；完成度随请求范围表达，不把意图说明当已交付图形。

建议先作为可独立调用的专业模块，复用现有运行与修订承载。教师可在课时中选图提出修改，不需知道图形参数或新的场景菜单。涉及题目成立与否的关键图需提前试做；精修可延后。候选尚未成为生产接口或用户已逐项批准的决定，外部产品界面仍由外部负责。

### 开始调用接口设计（2026-09-15）

用户要求继续下一步，按地图选择首个未阻塞问题。沿已确定的克制原则，先收敛调用方必须知道的输入、真实回应、进度／结果及停止语义，以自然语言教学需求和少量可信上下文贯通；不将原型场景映射为操作枚举。已有能力范围、HITL 与知识使用决定直接继承，本轮不重新询问已定方向，也不据纸面接口宣称运行和教学质量通过。

### 执行结构的接口输入（2026-09-14）

[执行结构决定](03-execution-structure.md) 要求分别表达本次运行状态、设计对象／修订、检查结果、人类请求与贡献、预算停止及交付清单；共享运行操作不统一各能力的教学终态。接口须能返回草稿／部分成果与未完成原因，关联课程基线和个人适配，并防止迟到结果覆盖当前版本。具体请求／回应语义承接 HITL 票。

### HITL 语义已具备（2026-09-14）

[人类参与决定](07-hitl-protocol.md) 与 [详细设计](../assets/hitl-design.md) 已明确已有授权、内容接受、备课贡献及五项能力的不同结束条件。接口应承载真实展示对象、原始回应、事件身份、解释／限制、有效决定范围、处理结果和外部最终决定规则；不把自由文本丢掉只留下一个 approved。

重复事件、同身份内容冲突、新事件改意、旧版适用及取消分别返回可理解的结果。生成适配材料供外部后审须在任务范围中明确，不由超时自动切换。已有决定可按范围复用，不伪造新点击或未看过材料的审阅。原型可以先于最终字段定案探索可见状态，接口收敛时读取其实际结论。

### 状态原型的具体输入（2026-09-14）

[课程状态原型记录](../assets/curriculum-state-prototype-notes.md) 已有顺序逻辑及实际浏览器走查证据；用户反馈场景含义和教师操作负担，已补充现实触发与参与者说明。接口设计尤其要保留检查所依据的补查证据、当前适用决定和原始展示快照；历史接受不能导致无期限重问，新事件中的反对不能因旧请求已处理而丢失。课程采用版本、候选版本、个人适配和交付历史分别可取得；这些是候选接口应能回答的问题，不直接采用原型字段作为正式协议。

接口不能把原型的场景编号、检查按钮和事件处理步骤变成教师的操作协议。调用方收到的应是可理解的教学问题、差异、进度与结果；内部按具体能力、内容与证据执行规则。各 Skill 的实质参与继续分别保留，不能用“隐藏内部复杂性”抹掉教师备课亲做等要求。

### 控制粒度的证据要求（2026-09-14）

[强模型下的控制粒度研究](../assets/harness-control-granularity-research.md) 补入具有同等 Context、工具和必要运行保障的简洁 Agent 基线。接口围绕真实任务、对象版本、待答请求、执行证据和结果设计，不将每个反例变成操作类型。检查的精细复用和多人决定累计是实现候选；应先比较较大范围重查、消费外部可信决定等简单方案。既定教学语义继续保留，具体字段与机制由证据收敛。
