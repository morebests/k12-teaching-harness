## Question

如何验证独立课程体系及教学产出的质量和执行可靠性？先定义本项目的教学目标和接受标准，再决定哪些上游 Skills 与 IM 指标值得采用、改写或舍弃；不以逐字遵守参考实现为成功条件。

四项既有能力建立固定上游规范的执行基线，以达到并争取超过其水平为目标。比较时记录模型、工具、课程目标、学习者条件、人类回应及产物范围，分别判断教学内容、执行过程与产品可用性；更换流程要证明原目的仍被满足，不通过删除失败指标宣称改善。IM 内容对照与 Skills 执行能力对照分别记录。

数学首阶段按所声明的年级／单元／课时范围检查目标覆盖、学习进程、数学正确性、表征与任务、学习机会和证据、学校可实施性与跨层一致性。课程层面的完整覆盖不强加给每一课；每课的具体职责仍须兑现。

分别验证执行流程和 HITL、真实产物可用性、教学内容质量；构造目标变化、课时重排、表征改变、学习者上下文更新与恢复等案例，检查失效范围和追溯。静态图检查、计算、模型评价及人工审阅各有职责，不能彼此冒充。

在固定原创版本后，使用目标与条件可比的 IM 材料做离线对照，记录初稿、参考和修订版本；评分采用独立质量标准，避免把 IM 的结构偏好当作优越性的证明。不同模型分别检验，结果只支持实际覆盖范围，不宣称证明学习效果。

外部 Learner Model 准确性、整校教学成效和完整治理平台不作为本仓库的建设任务；其他学科分别建立相应标准。

### Resolution：按范围交付、分层取证，完整单元后再做参考比较（2026-09-15）

本票的问题是“如何验证”，当前 Wayfinder 目标是架构与可行性结论。既有有限实验已提供机制选择所需反例，按用户要求停止把样例精修当主线，现收敛 [从架构可行到教学交付的验证路线](../assets/validation-and-release-route.md)。**resolved 表示验证方法与交接已明确，不表示教学质量通过，也不删除原失败。**

首个对象采用八年级线性函数方向：全年 CCSS 蓝图→完整单元的课段、实际课时／材料／评测→一次跨层改动与局部支持变化。连续三课只作首个实现连通切片；完整原创单元冻结前不读对应 IM，单元编号与课时安排由自有设计决定。现有研究条件保留来源，不升级成学校事实。

质量沿既有 E1–E10、教案 39 条取用及各能力自己的 rubric，分别取得数学内容、实际材料、课程联系、HITL、修订与运行证据。检查要读真实版本，数学错误、关键机会或材料缺失、伪造来源／参与等不能靠平均分抵消；未知、不适用与未执行分别记录。发现交回模型修复，也允许以证据反驳检查误报，预算和失败保留出口。

固定 Skills 原规则和本项目采用规则分别比较；同模型及可比资源条件用于判断机制变化，原宿主／不同模型对照另报，不混淆影响。其他能力分别覆盖其正常交互与必要例外，不能以 creation 或一次 CFU 代表全部。广泛“不逊于”的主张需教育评阅者校准和事先固定的取样／重复／非劣判据，当前无此结果。

IM 在原创 A 冻结后选择可比参考 R，匿名独立评阅后形成改进 B；来源映射不进入评阅输入，别人评论也不提前可见。模型预训练和结构线索不能排除，故不声称严格双盲。LangSmith 承载有版本的轨迹和评测，不替代产品人类决定、即时修复或学校发布。

实现验收继续取得：真实 Gemini 与原生循环／持久服务合并、原文保存到采纳、Server 自动调度与重送、真实文件／检查／取消、生产恢复与访问隔离、完整单元及教师使用。当前配置已有 LangSmith Key；后续合成样本实测平台，不批量上传历史内容。生产、质量和使用门槛按报告交给规格／实现，不能再留在本票靠无限扩张原型追求全部完成。

### 先验证更少控制是否足够（2026-09-14）

用户要求论证强模型下的过度设计风险，并明确从交互到实现均应克制。按 [控制粒度研究](../assets/harness-control-granularity-research.md)，先运行同一能力内具备充分教学规则、Context、工具和必要保障的简洁 Agent 循环；出现具体缺口后，再针对它增加控制并比较，不先建设两套完整架构。比较保持同一模型、适用教学规则、知识与任务、可用工具、实际人类输入和预算上限，均有必要的事件／版本／停止保护。简洁方案充分利用模型推理与内置知识，不能被故意剥掉 Context 和检查能力；教学正确性与规则遵守不因减少节点而豁免。

输入采用真实需求和实际课程，避免把“删课案例／描轮廓陷阱”标签或预设错误送给模型。既测必要干预，也测已有授权、无语义变化、可自主修复时能否继续；保留未见过的任务与改写，避免按演示脚本顺序评分。记录实际材料质量、遗漏与误报、不必要等待、修订保真、耗时／费用及维护成本；运行故障另做注入验证。没有与教育评阅者校准的评分，不能宣称达到 Skills 水平。

该比较是待执行的验证设计，不是本票已解决或模型已达标。精细检查复用、通用多人决定机制及额外检查调用的收益，需各自举证；不把所有演示边界一次实现后再统一比较。
