## Question

用可交互的轻量逻辑原型检验 [执行结构](../assets/execution-structure-design.md) 的状态表达：同一课程片段经历跨层修改后，当前内容、待重查范围、人类请求、产物与停止原因是否仍清楚一致？先让真实数学题面及变更可见，再展示执行状态，避免只用无教学含义的状态按钮演示。

至少包含：删除唯一学习机会并发现邻课容量不足；把自行构造改成描轮廓；只改作图区；更新某个学习者的支持；旧版／重复回应；检查后内容变化；预算耗尽。保留旧版本与未受影响内容，展示候选改变、受影响的检查与交付状态，区分课程基线和个人适配。

检查发现和人类事件可以显式模拟，不能冒充模型发现了语义错误或真实教师参与。图遍历只找到已记录依赖，原型需展示“依赖缺失／影响未知”时不能直接认定无影响。已有几何案例可作演示素材，不因此固定首个实施主题。

本票只回答状态表达与控制是否足以承载这些情况。真实模型的 Context 分解、教学判断和修订质量进入质量验证；跨进程持久化、并发、模型副作用及 Agent Server 运行语义进入相应专项。不要用浏览器内存状态证明服务器恢复可靠。
