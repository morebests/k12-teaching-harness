## Question

如何让课程负责人、教师等真实参与者对设计取舍和教学内容作出有意义的判断，并让外部 Web 系统可靠承载这些交互？参与者身份与权限由外部提供。

逐项明确课程体系、课时设计、适配、备课与理解度检查在什么情况下需要人，呈现哪些可审阅内容，接受哪些回应，如何继续或结束。重要的目标／节奏取舍、教师亲做任务、材料审阅各有不同目的，不合并成通用批准按钮。

原 Skills 的问法、固定选择轮次和满意结束条件仅供参考；根据当前能力的教学目的取舍。已明确授权的方案和可追溯的本次真实决定应直接使用，不能为复刻原对话重复询问；模型不能伪造人类回应。

保存审阅对象、版本和决定，处理重复与迟到提交、改意、取消及跨层变化。修改目标或课段结构时回查实际受影响的决定，版式调整不自动引发全课程复审。等待位置和恢复机制需使教师看到的版本与继续执行的版本一致。

本票提供交互执行与接口所需语义，不建设前端、权限或最终发布治理平台。

## Comments

### 设计基线与实际覆盖核对（2026-09-15）

用户追问 HITL 位置与实验覆盖。原决定继续有效：五项能力各有参与语义，不重新改成统一批准流程。[当前执行审计](../experiments/grade8-linear-functions/hitl-coverage-audit.json) 显示 9 次真实模型执行均未发出待答，原型也没有接收回应并恢复的入口。模型修订、组织者反馈和 HTML 模拟不作为真人参与证据。

已将语义落实位置与缺口接入 [主执行方案](../assets/main-execution-design.md#hitl-究竟介入哪里)，运行机制继续由 [完整运行专项](11-agent-server-stack-research.md) 与相应原型验证；LangSmith 人工标注和产品端教学决定分别处理。本票 resolved 仅表示教学语义已收敛，不表示实现或真实使用通过。

### 方法论中的真实参与与计划边界（2026-09-14）

[IM 方法论研究](../assets/im-design-methodology-transfer.md) 区分讨论预案审阅、教师亲做和真实课堂作品选择，并列出需要不同信息可见范围、修订循环或长期集体材料的互动方式。教学设计的批准不能登记成学生已作答；本轮未采集到的课堂事件不能用模拟数据替代。

本票按具体能力处理这些语义，不统一为批准按钮，不把原备课 Skill 的短轮互动扩成强制课堂报告。持续支持的改变须遵守外部已给安排及授权；临时支架是否减弱由相应教学依据判断。

### 执行结构的交接（2026-09-14）

[执行决定](03-execution-structure.md) 已确定等待位置与内容／运行／检查／参与分开记录，具体见 [执行结构与各能力交互](../assets/execution-structure-design.md#各能力保留自己的交互和结束方式)。本票接续逐项明确：有效的已有决定如何直接使用；精确修改加生成与仅修改的区别；CFU 明确改向；适配的全套满意机制何时适用；prep 的正常贡献、先示范、短时、拒答和结束。不要重新判断是否需要这些能力或重新索取已给授权。

用已经可审阅的删课修订轨迹具体定义请求对象、展示版本、回应范围、旧版适用与改意；重复回应不再触发第二次生成。自然语言回应可以由模型解释，实际事件来源、关联及后续动作仍须校验。预算／超时／沉默不是批准。结论同时供 [课程状态原型](14-curriculum-state-prototype.md) 和 [CFU 运行原型](09-cfu-runtime-prototype.md) 使用。

### Resolution：按教学目的解释真实回应，按对象与范围恢复（2026-09-14）

基于用户已明确的各能力独立、保留原流程、已有授权直接推进和真实人类参与要求，本轮收敛 [HITL 详细设计](../assets/hitl-design.md)。这是执行与接口的语义基线，不记为用户逐项批准，也不宣称自然语言理解、并发或恢复已通过运行验证。

1. **区分事实、执行授权、内容接受与备课贡献。** 已给事实直接使用；有范围的授权可支持后续自主设计，但不记为教师已审过未生成材料。内容接受关联实际对象及适用范围，教师贡献必须来自真实输入并影响备课。收到人类输入不等于其数学判断正确。相关词义补入 CONTEXT。
2. **五项能力保留不同请求和完成语义。** 课程围绕授权外取舍及明确审阅要求等待；课时创建使用已明确的交付路径，未明确才按自身规则提出选择；适配正常协作保留整套接受，局部接受可按有效范围累计；prep 保留教师自己提出 near-miss 的正常路径及其例外；CFU 保留焦点选择，明确改向后不再增加同义确认。共享承载不变成通用批准按钮。
3. **明确已有决定和复合指令的用法。** 对象、约束、作用范围及外部授权都仍有效时直接使用。仅修改草稿与修改后直接生成分别处理；后者覆盖指定的后继内容。当前唯一问题明确时，简短“可以”即可表达放行，不要求固定关键词。主题、Learner Model 或一个系统预选值不冒充具体决定；范围内明确委托保留委托身份，不虚构人工亲选。
4. **适配生成完成与协作完成分开。** 默认正常协作收到当前整套材料的有效接受才结束该协作；计算停止与材料可查看不取消这一条件。只有明确只生成供外部后审、退出审阅或取消时按其范围结束；未发生的满意保持未发生。累计局部接受与范围化复用属于 Web 适配，需要与固定上游四份满意路径分别比较。
5. **完整保留 prep 的正常与例外。** 教师自己产生 near-miss，模型不能先给错例替代；内容解释可以先回答教师所问，但不因此提前给出全部错误分析。明确请求先示范、拒答、三分钟、已有实质内容后结束以及立即取消分别处理。短时来自教师时间要求，不能由系统预算不足伪造；无原课也不能借拒答例外虚构原课。此次补回旧分析遗漏的 M2 content-explanation 分支。
6. **回应经过来源、对象、语义、有效范围及采纳校验。** 保存实际展示快照、真实输入、原始回应、解释与限制、采用动作和处理身份。相同事件重送返回已有处理结果，同一身份内容冲突不能静默覆盖。已记录的动作遇到工具失败时恢复该工作，不重新问教师或重解读后执行另一动作。模型可以解释意图，不能生成真实回应、权限或通过记录。
7. **版本和多人规则各按自己的含义。** 内容实质变化不能用旧接受放行；仅分页变化可在核对后复用仍适用的数学任务决定，但不伪称人看过新排版。多人请求需要确定的决定主体或外部规则；先消费等待点不自动赋予先到者权威，后到的不同有效事件仍需判断冲突／改意。未解决争议阻止其结果成为当前交付。取消、过期不因迟到回应自动重开或增加预算。
8. **退出与质量证据互不替代。** 等待释放计算，沉默不表示确认，取消不抹掉历史交付。教师满意也不能覆盖已经发现的数学错误。各项未完成条件如实返回；实际服务器取消、事务和工具副作用保证由后续专项核查。

**本轮证据：**对四项固定源码及参考作只读复核，修正 prep 内容解释漏项及草稿放行关键词的潜在误读；新增二十项静态场景。独立复审另纠正“分析一个 near-miss”可能误成模型先给例子、以及先到回应误获决定权的两处表达。没有真实教师参与、模型评测、状态原型或跨进程实验。

[调用接口](02-execution-interface.md) 现可依据本语义设计承载；[课程状态原型](14-curriculum-state-prototype.md) 与 [CFU 运行原型](09-cfu-runtime-prototype.md) 已具备交互语义前置，分别检验可见状态与真实框架恢复。若原型或质量评测否定具体机制，回到对应决定修订，不用本票状态替代证据。
