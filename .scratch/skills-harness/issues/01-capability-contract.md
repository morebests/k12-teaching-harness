## Comments

### 标准框架固定为 CCSS（2026-09-15）

用户澄清项目自始至终只使用 CCSS，并非本次八年级实验才作此选择。已写入 README：数学采用 CCSS Mathematics 的内容与实践标准，贯穿课程、课时及其他教学能力、知识查询、Context 和质量验证。州标准选择、州版替换与跨框架适配不在范围内。此前材料中一般化的“选择目标框架”在本项目指固定 CCSS 身份及记录数据版本，不能据此新增教师选项或多框架机制。

消费细节见 [知识使用约定](../../../docs/references/knowledge-consumption-contract.md)；原 Skills 的多框架查询流程及本地图的州标准观察保留为来源事实，不转为产品能力要求。本次落实既有方向的澄清，不改变五项能力与独立课程设计路线。

### 前提修正记录

此前按逐项保真移植上游 Skills 展开过执行方案。用户随后明确独立课程体系、IM 可取舍及本地 KG 可用的目标，以下 Resolution 取代旧前提。

用户仍要求各项能力和学科保持自身特点、数学优先、前置研究同步文档化。源码盘点与学科差异继续作为参考；具体流程、交互和检查仍有重要参考价值，但不自动成为项目约束。

### Resolution：独立课程体系与本地知识基础（2026-09-14）

用户明确本项目要形成独立的数学课程体系，上游 Skills 是可取舍的参考，并授权不采用 IM 结构、只借鉴思路或在原创内容完成后进行对照改进。新增课程体系设计覆盖 Grade／Unit／Section／Lesson 及各层 Narrative，属于核心能力，不是外部已提供的前提。

Learning Commons 已由其他项目本地化，本仓库消费可用数据，不再设计下载、认证、权限开通和本地化。当前已实际只读核查几何目标、LC、进阶和课程层级；图的使用按关系语义及本次教学目的判断，不能用 K–2 年段模板取代知识依据。

范围基线据此确定为：课程体系设计＋课时与材料设计＋教学适配＋教师备课＋理解度检查，数学优先，各能力和学科保持各自教学特点。Web、身份权限、学习证据与 Learner Model、全系统归因和最终治理仍由外部提供。

质量基线由本项目的数学与教学目的定义：数学正确、目标与证据对应、进程和先备适切、学校可实施、跨层一致、修订与人类决定可追溯。完整覆盖在所约定的年级／单元范围检查，单课承担其具体目标；原 Skills 与 IM 的专属格式、动作或固定数量不自动进入验收。保持教学质量目标，不再以原 rubric 逐字通过定义独立设计能力。

前轮两项异步确认（字面冲突适配、KG 材料缺口增加审阅）因前提改变撤回；此前 Web 表单选择也不再是独立待批准的产品前提，后续按真实事件及具体教学需要设计。用户已授权 IM 取舍，本轮采用独立设计后置内容对照的工作路线，记录在能力范围报告中。

本票解决范围与基线；新增课程体系契约由 [课程体系设计如何形成可教、可检验的学习进程](12-curriculum-design.md) 承接，执行结构、接口、依赖、HITL、评测和实现前运行时专项继续各自推进。这不表示具体架构、课程生成或教学效果已验证。

### 流程参考的保留与质量基线澄清（2026-09-14）

用户明确：在尚未证明找到效果更好的实现机制之前，上游 Skills 的流程分析必须作为重要参考保留，不能因不作项目约束而删掉后重新设计。此前过度清理已撤销，恢复详细流程、案例、学科与运行机制分析；新摘要不能替代原分析。

四项既有能力要借鉴并以达到、争取超过原 Skills 水平为目标。Context 体系、LLM 的使用方法及与外部产品的实际对接，从具体教学工作和已有流程出发设计。可比条件、替代机制与验证证据在对应设计票中展开，尚无已验证的更优替代方案。
