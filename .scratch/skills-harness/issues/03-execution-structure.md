## Question

如何执行独立课程体系设计，并将年级、单元、课段与课时的设计内容传递给各项教学能力？明确模型实际完成的设计判断、图查询、任务生成、试做检查、上层回查、修订、交付与结束。

在 LangChain／LangGraph 方向下，选择能保留教学工作与跨层迭代的结构；不把每个 Markdown 条款机械变成节点。课程布局、具体课时、教师备课和理解度检查各按自身目的组织，原 Skills 的详细流程作为首选设计起点，重要改变须说明其教学目的如何保留及所需验证；IM 的课程形式按本项目目标取舍。

从具体教学工作反推 Context 的内容、来源、阶段装配、可见范围和更新方式，确定 LLM 怎样读取规则、调用工具、形成和检查内容。教师亲做前的模型分析、隔离读题的答案访问等需按各 Skill 的目的处理。

进一步明确产品运行时各阶段实际加载哪些教学规则、数据、工作内容及验证资源，如何定位来源版本和执行装配、访问与一致性检查。开发 Agent 通过 AGENTS.md 读取项目资料，不等于运行时 LLM 已获得这些 Context；本票的结果需要进入后续执行规格、实现及验证。

说明哪些教学内容、图依据、设计选择、人类决定、产物和检查需要跨阶段保留；何时失效，如何恢复，怎样避免把旧版审阅和检查用于新内容。数据可用为既定前提，关系语义和选用理由仍需正确处理。

数学优先；其他学科保持独立设计空间。原 CFU 暂停恢复研究作为可复用的框架事实，不能预设全部能力都采用 CFU 的控制结构。

本票确定教学执行中的状态与人类参与位置，HITL 票进一步确定回应和恢复语义；完整 Agent Server 会话、任务和部署在实现前专项研究。

## 当前采用（2026-09-16）

目标解读、单元职责和学习进程分别支撑后续工作；未验证依据直接扩散会使回修难定位。因此全年采用有效阶段成果和针对性 Context，由图保证交接与检查适用，模型设计与判断，局部 Agent 解决未知取证。阶段不是每次一个调用，也不是每步人审；新增控制的收益仍需真实比较。 当前参考 IM 已获授权，记录来源和设计影响，不延续旧全单元冻结前禁读时点。现行行为及前进条件以 [规格](../../math-harness-delivery/spec.md)为准，方法理由见 [全年设计](../../math-harness-delivery/curriculum-progression-workflow-design.md)，拆分见 [重整记录](../../math-harness-delivery/year-planning-replan.md)。新机制、全年质量和正式比较尚未通过；下方旧讨论保留其日期与证据地位。

### Resolution：各能力流程内的模型行动与明确执行边界（2026-09-14）

承接用户已明确的独立数学课程、保留 Skills 流程、各能力不统一、真实 HITL、Context 与修订要求，本轮在授权范围内完成结构比较与技术收敛。以下是有待运行验证的设计基线，不记为用户逐项批准，也不把结构合理性当作质量达标证据。详细理由、资源路径、状态和反例见 [执行结构分析](../assets/execution-structure-design.md)。

1. **采用各能力自己的流程，阶段内保留有界的模型与工具行动循环。** 相比一个无限延长的通用 Agent 或每条规则一个节点，这一结构保留模型查依据、创作、试做和纠错的空间；程序承担真实事件、资源可见范围、对象版本、预算与交付条件。边界按信息／权限变化、需要人类事件、保存昂贵工作及检查版本设置，不按课程层级分配自治 Agent，不预定节点数或模型组合。
2. **课程设计采用可往返链路。** 任务与依据→进程／课时职责→关键任务试做→课时展开与材料→完整范围回查。局部问题回课时，进程和分配问题回上层；每次携带实际失败对象与理由。代表任务通过只支持展开，不代替整个单元的内容与检查。独立单课及四项能力继续各自启动和结束。
3. **运行资源按能力与阶段明确装配。** 以固定原 Skill 和参考文件为完整起点，建立采用／改动记录；本项目规则优先处理课程目标分配、IM 具体内容进入时点和数学适用性。每次调用可定位实际加载资源与内容版本。prep 不加载不存在的学科参考，CFU 继续以其特有时点开放完整验证资源；隔离读题不能从消息、读取工具或缓存获得答案。具体资源位置已列入分析，不只写“遵守 Skills”。
4. **分别保存运行、内容、检查、人类参与、操作预算及交付事实。** 采用可定位的内容修订和当前采用版本；检查、决定与实际材料绑定。停止计算、教师参与完成、内容检查通过和单元交付分别报告。共同运行承载不创建五项能力统一的教学终态。
5. **修订结合依赖遍历与内容判断。** 先保留旧关系并查影响，再读取新旧任务发现未记录依赖和认知要求变化；不能只按变更标签或已有边得出无影响。复用未受影响内容与仍适用的检查；数学改动、版式改动及个人支持各按实际范围处理。共享题面之外的教师叙述、观察和后续建议也要同步。
6. **人类参与围绕本次真实对象。** 已有有效决定直接使用；缺少必要选择、超出授权的课程取舍、已选草稿放行及真实教师亲做等按各能力等待。保存展示版本后等待，恢复时核对回应对象。教师取消、短时／先示范／拒答分别处理，不能由模型补出贡献。具体回应、迟到适用性和上游满意等待的产品条件继续由 HITL 票细化。
7. **失败与预算有明确出口。** 工具故障、内容检查失败、结果不确定、等待、取消和预算停止分别处理；已保存生成内容可供产物重试复用。修复无进展则换任务或回上层，仍不成立则保存未完成结果。预算跨重试／恢复累计；不降低标准、虚构工具成功或把部分成果称为完整单元。精确费用与次数参数待实际验证。
8. **用不同证据验证不同主张。** 源码审计确认 creation 与 CFU 对错误策略答对题目的判据不同，检查必须带本次证据目的。模型是否能发现教学问题、阶段 Context 是否损失信息需真实内容评测；状态表达及依赖失效由 [课程修订原型](14-curriculum-state-prototype.md) 检验；重启与产物副作用继续由 [CFU 运行原型](09-cfu-runtime-prototype.md) 检验。完整 Agent Server 专项维持实现前时点。

本票已完成源码复核、结构比较、具体资源与状态分析、一次删课修订的纸面轨迹及十三项静态反例。独立源码审查还纠正了盲读装配的一个风险：检查者必须看到学生版原样快照，不能剥除泄题图形说明后宣称原版通过。未运行课程生成、状态原型、材料渲染或生产框架。原型若否定关键结构，回到本票追加修订决定，不因本票 resolved 而忽略反证。

下一项可按地图顺序进入 [课程与教学设计中的人类参与、暂停和恢复如何设计](07-hitl-protocol.md)。接口、工具、质量及完整运行时各票已接入本结论；架构总体结论需综合必要原型的实际结果。

### 强模型下的控制粒度复核（2026-09-14）

用户质疑原型场景细分是否过度设计。复核发现原结构比较漏了“同样具备教学规则、Context、工具、持久化与真实事件保护的简洁 Agent 循环”，已在 [详细分析](../assets/execution-structure-design.md#先比较执行方式) 补入，论证见 [控制粒度研究](../assets/harness-control-granularity-research.md)。不能以无运行承载的聊天作为唯一简单对手，进而认定当前候选最佳。

本票的教学职责、各能力自身流程和必要边界继续作为设计基线；它没有确定节点数量、每种修改的处理器、检查缓存算法或多人审批引擎。这些实现选择不因原型走通而升级为要求。质量票比较在同等教学目标与必要运行保护下，更少程序控制是否已经足够；新增控制需说明实际失败、简单替代及增量收益。现有 Skills 详细流程不删减，尚未取得模型对照或更优替代证据。

### 采用克制设计与模型能力优先的推进原则（2026-09-14）

用户明确要求从交互到实现机制保持克制，充分使用 LLM 的推理与内置知识，避免先铺开再付出回收成本。已纳入 [README 的设计原则与实施路线](../../../README.md#设计与协作原则)，运行时知识使用方式进入 [Context 设计](../assets/context-and-llm-design.md#模型内置知识与任务证据怎样协作)。这是已明确的推进原则，不是候选研究或模型效果结论。

先运行具备充分教学资源和必要保障的简洁循环，再根据实际缺口逐项扩展；不预先穷举交互选项、程序分支和通用扩展机制，也不为对照先做两套完整架构。内置知识用于推理和创作，本次学校／学习者／人类决定仍以实际输入为据，具体标准和图关系使用来源。原 Skills 的教学目的、必要参与及质量要求继续保留，已分析场景留作参考；精细机制不据此默认纳入实现。
