## Question

设计执行需要怎样的模型、图查询、内容读取、数学计算与产物生成能力？明确各工具所完成的实际工作、输入输出、来源与版本，以及如何让模型正确使用返回的依据。

Learning Commons 已本地化且可用。围绕标准与 LC、方向不同的进阶和课程依赖、层级及对齐、目标到来源课程的追溯设计查询能力；不再从上游 MCP 工具名推定完整能力，不设计下载、认证或入库。

说明查询如何保留节点和关系身份、方向、来源、路径、对齐角色和适用理由，如何区分图中事实与本项目推断，以及如何处理结果存在但与任务无关或没有某类关系的情况。关系为空不是远程获取失败。

评估现有渲染代码的实际复用价值，但不让 Word 数量、单一 JSON 布局等参考实现限制课程产物。数学求解、图形、实际文件及跨层一致性检查需要独立证据；模型或生成工具故障不能伪装成教学成功。

## Comments

### 2026-09-15：当前内容工具采用文件化工作稿

用户明确现阶段不借鉴另一项目的 authoring，自行定义格式，暂不上数据库、不做内容版本历史。采用 [JSON 工作源、Markdown／LaTeX 正文与独立图件](../../math-harness-delivery/content-system-design.md)，只维护当前稿与当前检查；内容指纹用于核对检查和回应适用性，不保证旧指纹可回取历史内容。随后核查确认运行状态直接使用 LangGraph／Agent Server dev 的保存与恢复，不另建文件任务状态机。

这是当前阶段对原存储时点的调整，覆盖早期“首版不可变历史”表达；上游共享题面、各能力教学流程、实际数学与渲染检查继续保留。最小文件格式随真实切片落实，不再将 authoring 评估或完整编辑器／数据库设计作为前置。LangChain／LangGraph／Agent Server／LangSmith 方向和后续生产恢复要求保留，文件任务不冒称框架 checkpoint。

### Resolution：复用模型循环，以实际资源和工具结果落实教学执行（2026-09-15）

在已确定的技术方向与连续推进授权内，完成 [模型、知识与产物工具的实现选择](../assets/model-knowledge-artifact-design.md)。本票解决实现职责与接入路线，不将方案当作已经运行的生产能力。

采用 Python、LangChain 原生模型／工具循环及 LangGraph 的必要持久边界；当前以已实测 Gemini 为主。Claude、OpenAI 与开放权重模型已有可核查的 Adapter 路径，具体模型的工具、媒体、消息恢复与质量必须各自验证，不先做动态路由或统一供应商私有字段。真实 Gemini 与原生循环／服务的完整合并仍属首个实现切片。

Context 装配实际取得各能力自己的规则、适用参考、当前内容、知识和有效决定，记录采用变更与版本；不只传摘要或 README。标准／LC 及关系从本地 browse 取得，保留 CCSS 身份、方向、源值、完整范围和排除结果。原型固定快照及出版者是实验条件，不成为生产全局常量；未知或空关系不冒充缺少学习需要。适用 LC 的读取与使用要有证据，不以工具已注册替代。

模型可读取、查图、计算、保存设计、请求参与及提出检查／交接；执行端控制可见范围、真实人类事件、实际工具结果、预算与交付。确定性检查、受限模型检查及真实参与分别保留证明范围，失败交回修订并重查最终版本。已有原型中的请求工具只覆盖约束冲突，不能直接搬用为五项能力完整 HITL。

上游共享题面、师生分面与成套渲染值得复用；源码也有运行时安装、输出复制、隐式文字修复及缺失共享键返回空内容等行为，生产需固定依赖、验证引用并检查最终材料。首个 Web 切片采用可打印 HTML、图件和可修订源，Word 按所请求载体接入原渲染 Adapter；原格式数量不限制课程内容模型。函数图精修功能继续后置。

**新增证据：**只读复核本地 OpenAPI、知识／生成探针及上游渲染源码，并核查官方模型集成。没有运行新模型、下载权重或生成材料。模型／工具的详细行为、验收和引用见报告；[质量路线](../assets/validation-and-release-route.md)保留合并运行、完整单元、各能力比较与生产恢复门槛。

### 从调用约定继续收敛实现职责（2026-09-15）

[调用决定](02-execution-interface.md) 已解决前置；本轮继续按用户授权推进。本票需要给出实际模型循环、运行规则装配、知识查询、内容／产物与检查工具怎样落实小接口，避免把教学和恢复复杂性推回 Web。优先使用已有源码、数据实测和有限模型／持久探针；不再次扩展课程样例或图形精修。接收原文、语义采纳及调度交接分别处理，具体工具不能伪造人类回应。

### 图形能力保留为后置候选（2026-09-15）

按用户对工作优先级的纠正，数学可视材料的小型对照及专门模块暂不启动。先从主执行方案确定实际需要的模型、知识、内容和检查工具责任，并结合实现前运行时专项判断复用方式；进入相应材料实现或该问题成为主线阻塞时再取用下方候选。候选文档继续保留，不作为当前架构前置依赖。

### 数学图形生成与精修的模块候选（2026-09-15）

用户建议及 [详细评估](../assets/math-visual-materials-design.md) 提出将数学可视材料单列为可复用模块。由 LLM 解释教学用途、设计数学内容与信息呈现，精确函数图优先验证通过可编辑数学描述及可复现绘制生成，再根据具体反馈迭代；不要把纯文生图、函数绘图与几何构造预先统一成一种参数模型。

现有实验已发现点线不一致、遗漏图、泄题图例和标注重叠，可作为有限验证对象。保留上游同源材料、师生区分和实际附件交付的目的；具体绘制工具、模块 Interface 与复用方式尚未定案，不凭候选划分新增服务或多 Agent 编排。

### 固化的知识消费要求（2026-09-14）

模型工具与知识结果必须落实 [知识使用约定](../../../docs/references/knowledge-consumption-contract.md)。重点核对框架与 ID 消歧、不同方向的关系、非树引用、对齐角色原值、源身份及版本，按实际外部投影读取逻辑信息，不将本次 SQLite 列名或计数固定为生产接口。

[证据基线](../../../docs/references/reference-baseline.json) 保存本轮只读样本：不同的图内／CASE 身份、59 个树外活动及其引用、对齐角色、常量元数据等。用这些事实检验工具返回是否丢失教学所需信息；不在本票重建外部导入流程。

### 执行结构对模型与工具的要求（2026-09-14）

[执行结构分析](../assets/execution-structure-design.md#运行时-context-怎样真实进入调用) 已列出各阶段具体资源依据与装配责任。本票据此确定运行资源版本、实际读取记录、阶段允许动作及工具执行端校验；不要只在提示里隐藏工具名。隔离读题检查学生版原样材料，排除的是额外教师信息，不能净化有缺陷的学生版后宣称其通过。

检查故障类别与不确定结果，保存已完成生成工作供产物重试复用；预算跨重试／恢复累计。共享内容引用、自由叙述一致性和实际产物检查分别实现。具体载体与上游渲染复用在本票判断，不被固定 Word 数量代替。

### 回应解释与执行工具的责任（2026-09-14）

[HITL 设计](../assets/hitl-design.md#回应关联与实际处理) 将自然语言解释与实际事件采纳分开。模型处理完整请求和原始回应中的否定、条件、改意及所指对象；执行端核对外部主体／规则、版本和已处理事件。已保存动作的下游重试不重新询问或重新解释同一回应，工具也不能创建虚构教师贡献。
