## Question

综合课程体系设计、具体教学能力、调用接口、执行结构、本地知识与工具、人类参与和质量验证，采用哪套能够形成独立数学课程的 Harness 架构？说明取舍、成立条件与仍需运行验证的未知。

课程体系设计必须是核心能力，说明它如何向课时提供设计依据并接收反馈，以及跨层修改如何传播。原 Skills 和 IM 是参考，不将其结构和产物形式自动作为架构约束。

给出数学首阶段的实现与贯通验证范围；其他学科保留独立扩展空间，差异过大时分别实现。LangChain／LangGraph／Agent Server／LangSmith 专项应在实现前完成，已提供的本地 KG 与外部学习系统无需重新建设。

本票结束于架构、质量与可靠性验证路线明确；生产代码及完整 Web 系统另行推进。

用户明确先实现高质量能力，观察不同复杂度任务的消耗，再逐步优化预算。已同步 [README](../../../README.md#设计与协作原则)、[架构结论](../assets/architecture-conclusion.md#技术选用及部署条件) 与 [验证路线](../assets/validation-and-release-route.md#质量与消耗的推进顺序)。规格保留实际消耗记录及最小运行保障，预算压缩、预测和优化不设为首版前置；不削减必要 Context、检查和有进展的修订来满足探索次数。

架构与实施主线保持，继续交接规格和实现。本票维持 resolved，不新增预算专项或改写原型结果。

### Resolution：采用任务级教学 Harness，规划转入规格（2026-09-15）

前置的范围、课程、执行、HITL、调用、模型／知识／产物、运行研究、两类有限原型及验证路线均已形成结论。本轮按用户连续推进和既定路线收敛 [架构与可行性结论](../assets/architecture-conclusion.md)，不另设一轮抽象批准，不记为用户逐项批准技术字段。

采用 Python 教学后端，以 LangChain 原生循环、LangGraph 持久执行、Agent Server 任务承载和 LangSmith 观察评测实现。外部经任务级 Interface 提供真实上下文和回应；本仓库装配实际教学规则与内容、本地 CCSS／LC 知识、各能力的模型工具工作、检查修订、事件和版本化交付。共享运行机制，各能力保留自己的教学语义。

课程主线为全年目标与 Narrative→关键任务→单元实际课时／材料／评测→完整范围回查，支持带实际发现的双向修订。首个实现对象沿八年级线性函数，连续三课作为运行切片，完整单元作为课程交付验证对象；IM 具体内容只在原创全单元冻结后对照。原 Skills 详细流程保留，尚未证明更优替代机制。

采用真实事件接收／采纳／可靠续作的分段事实，当前内容、检查、人类参与与外部发布分别记录。产物／事件与 checkpoint 的一致性、跨任务预期基线提交、取消迟到结果及旧行为恢复由实现兑现。生产 Agent Server 的许可、持久化、容量与恢复须验收，dev 不代替生产；LangSmith Key 已具备配置，平台尚未验证。

**可行性判断：**源码与官方资料说明该职责划分可实现；真实 Gemini 和有限持久探针提供局部支持，没有发现足以要求推翻主线的反证。教学质量仍未达标，完整单元、Skills 比较和真实教师使用未完成；因此结论是有证据支持进入规格与实施，不是已证明最优、达到 Skills 或可直接发布。

**交接：**按结论中的顺序进入 `/to-spec`、`/to-tickets` 与实现。规格继承 README、各决策和详细读取路由，明确运行资源、正式 Interface、可靠提交和分能力验收。现有失败和生产验证是明确的验收工作，不再通过扩大 Wayfinder 原型来冒充推进。多年级与其他学科的完整质量、多模型广泛比较在相应交付阶段展开，不阻塞当前数学架构结论。
