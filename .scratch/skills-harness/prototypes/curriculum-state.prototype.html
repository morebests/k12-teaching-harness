课程修订：什么仍然有效？

删除一课、改变任务或更新个人支持后，能否保留有效内容，定位必须重查的部分，并在真正需要教学决定时停下来？用一个几何课程片段，检验这些状态能否同时说清。

这页供项目设计者走查。下方按钮模拟模型、系统和人类各自的动作。教师在实际产品中提出教学需求、回应必要取舍、查看和修改结果，不需要记住场景编号，也不需要手动运行检查或处理事件重传。

这是控制逻辑演示，所有课程、检查结论、权限和教师回应均为模拟。未接入模型、真实学生数据或 Agent 后端，状态只在浏览器内存中，刷新即重置。此页面不是课程生成器，也不证明教学质量。

这页位于哪一段流程？

初次课程设计与课时展开 → 已有课程 U1 → 收到修改需求 → 候选修改 ⇄ 检查／修复 → 必要的人类取舍 → 重新检查 → 交付。

本页从预设 U1 开始，演示加粗的修订控制。自然语言入口、Context 装配、LLM 设计、真实工具及后端持久化还没有接入。按钮用预设结果代替这些工作；一个按钮不等于一次模型调用，也不等于一个 LangGraph 节点。

展开：从“把两课压成一课”到模型与程序执行
  1. 人提出需求：“把这两课调整成一课，只有 20 分钟，辨认和自行构造图形的目标都保留。”也可以通过表单选择这些条件。
  2. Web 后端接收：连同所选课程、U1 版本、提交者和已授权范围传给 Harness。课程身份、权限与事件来源不靠模型猜。
  3. Harness 装配 Context：本能力与数学规则、原始需求、U1 的实际任务／评测／Narrative、相关知识依据、时间与支持条件，以及本阶段允许的工具。
  4. 调用 LLM：模型根据指令和具体内容设计重排，必要时提出读取、查图或计算的工具调用；程序执行并将结果返回，模型继续。模型产出的是候选修改与依据，尚不是正式交付。
  5. 检查与修订：教学判断需读取实际任务；程序核对对象、版本、引用和有依据的时间约束。发现问题后先在授权内修复，确需新取舍才保存请求并停止计算。
  6. 人回应后继续：自然语言可由模型解释，明确选项可直接解析；程序核对回应者、请求、版本与范围，再恢复修订、检查和交付。

“删去 L2”专门模拟一个可能不合格的候选，用来检验后续能否拦住它。真实系统并不规定收到“少一课”就删除 L2，也不规定压缩课时一定失败、一定要问人。

Prompt 示意（尚未执行，也不是完整提示资源）：“在保留 U1 两个目标的前提下，尝试把教学安排压缩到给定时间。读取实际任务和评测，优先调整冗余；对候选给出改动、学习机会及时间依据。目标或授权外时间必须改变时，提出具体取舍，不宣称已获批准。”模型还必须取得上一条中的实际内容和工具结果，不能只收到这段文字。
