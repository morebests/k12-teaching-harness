# 模型、知识与产物工具的实现选择

日期：2026-09-15。采用范围见 [模型、本地图查询和产物工具](../issues/04-runtime-adapters.md)。本文承接 [任务调用约定](main-execution-design.md#调用方需要知道什么)、[Context 设计](context-and-llm-design.md)和[知识使用约定](../../../docs/references/knowledge-consumption-contract.md)，记录实现选择及尚待验证的行为；不是生产代码。

## 先确定模块承担的工作

**当前阶段调整（2026-09-15）：**采用 [文件化内容格式与原生开发服务](../../math-harness-delivery/content-system-design.md)，不上业务数据库、不做内容历史、不再参考外部 authoring。运行使用 LangGraph＋Agent Server dev，直接复用 thread／run、checkpoint、流式和 HITL；教学内容与检查使用 JSON／图件及指纹，不另建文件任务状态机。下文完整内容历史和生产部署职责保留后续，不按早期“首版”措辞扩大当前切片。

首版采用一个 Python 教学执行后端，复用 LangChain／LangGraph／Agent Server。下列是内部职责划分，可以在同一进程和部署中实现，不分别建设服务，不先做插件市场或任意工作流配置器。

| 模块 | Interface 接收／返回什么 | 隐藏的实现工作 |
| --- | --- | --- |
| 教学执行 | 任务、真实输入和少量运行操作 → 任务视图与交付 | 能力流程、持久等待、检查修订、预算、可靠调度和任务级条件提交 |
| Context 装配 | 当前能力／工作、已采用输入与资源版本 → 模型实际消息、允许工具和装配清单 | 精确内容回取、原规则与采用变更、跨层依据、信息隔离及容量处理 |
| 知识读取 | 教学所需的标准／关系查询 → 有身份、版本和完整范围的依据 | 本地 browse 映射、分页、框架核验、源方向、内容筛选和错误分类 |
| 内容与材料 | 实际设计和版本化改动 → 可回读内容、渲染材料、检查对象与清单 | 父版本、受众内容、共享题面、实际文件、派生关系和重复写入核对 |

模型 Adapter 使用 LangChain 已有模型接口，检查工作使用上述实际内容及受限工具，不新增一个可以自行决定所有能力流程的“总控 Agent”。规则变动主要落在该能力的资源和少量执行条件，不能把十几种课堂情形都编为共享执行分支。

## 模型调用及三类接入

优先采用用户选择且已有真实工具往返和内容实验的 Gemini `gemini-3.8-flash`，经 `ChatGoogleGenerativeAI` 接入。工作段内用 `create_agent` 的模型／工具循环；外层 LangGraph 只安排需要保存、等待和切换可见信息的位置。现有两个探针分别验证了真实 Gemini 手写循环和固定模型 `create_agent`，**尚未验证两者合并后的完整教学路径**。合并是首个实现切片需要兑现的事，不能把两份独立通过记录相加成生产成功。

2026-09-15 核对官方集成说明后的接入判断：

| 模型类别 | 候选 Adapter 与证据 | 采用前还须验证 |
| --- | --- | --- |
| 当前 Gemini | [ChatGoogleGenerativeAI](https://docs.langchain.com/oss/python/integrations/chat/google_generative_ai)，已有本地真实工具及文本／图像实验 | 与所选 `create_agent`、中断恢复和实际教学资源合并；调用元数据、预算、工具错误和图像读取 |
| Claude | [ChatAnthropic／bind_tools](https://reference.langchain.com/python/langchain-anthropic/chat_models/ChatAnthropic/bind_tools) 提供原生工具绑定 | 实际模型的工具往返、消息延续及所需输入类型；未在本仓库调用 |
| OpenAI | [ChatOpenAI](https://docs.langchain.com/oss/python/integrations/chat/openai) 提供工具与结构化输出集成 | 实际模型、端点和配置的行为；未在本仓库调用，不能据接口兼容宣称教学质量相等 |
| 开源／开放权重候选 | [ChatOllama](https://docs.langchain.com/oss/python/integrations/chat/ollama) 是可核对的本地接入例子，官方要求选择支持工具调用的模型 | 具体权重与许可、服务版本、硬件、工具能力和课程质量；未下载或选定权重，不声称开源模型普遍具备相同能力 |

表中后两类集成能力是官方事实，适用本 Harness 的结论是条件性推论。`ChatOpenAI` 官方文档明确第三方扩展字段未必被保留，因此不将所有兼容服务强行塞进一个 OpenAI HTTP 包装。原生 Adapter 负责供应商特有消息结构和必须回传的 opaque 数据；应用保存可检查的答案与设计理由，不索取隐藏思维链。

首版使用一个主模型配置，不先做动态路由或模型投票。工作位置仍可分别配置生成和评价，但同一模型换一个调用仅证明信息隔离。切换模型时从实际任务内容重装配，不能把某供应商的私有消息当通用教学状态，也不能悄悄回退后仍记录原模型。

必要能力用具体往返验证：结构化工具参数、工具结果进入后续回答、错误返回后的修复、所需图像输入、异步／流式停止、使用量与未知结果记录。类型合法不等于教学正确；缺少某能力时缩小可运行范围或返回具体不支持原因，不用伪造文本工具调用掩盖。

## 运行规则怎样真正进入模型

现有研究报告是开发资料，产品模型不能以“请遵守 README”代替实际教学指导。规格需要交付版本化运行资源及采用清单：每项资源保留原文件、原目的、采用／调整理由和适用工作位置。已确定的 CCSS、独立课程、目标分配及 IM 隔离覆盖对应上游条款，其余重要教学细节保留。首版用本地文件及内容指纹，不要求先迁移 Prompt Hub。

| 能力／位置 | 装配起点 | 必须兑现的使用区别 |
| --- | --- | --- |
| 课程体系 | [四层职责与双向交接](curriculum-design-capability.md)、完整年级目标、适用数学规范及本次条件 | 年级先有完整目标视图；单元读取实际蓝图、Narrative、关键任务和前后关系。设计结构由模型形成，不提前填好答案 |
| 数学课时 | [creation 主规范](../../../k12-teacher-skills/plugin/skills/k12-lesson-plan-creation/SKILL.md)及其 math／KG／output | 沿实际草稿展开材料；试做、学生推理、解法与证据保留，不强加 IM 课堂阶段 |
| 数学适配 | [differentiation 主规范](../../../k12-teacher-skills/plugin/skills/k12-lesson-differentiation/SKILL.md)及其独立 math／KG／output | 原课、共同目标与学习条件决定支持；采用明确范围内的全套接受，不能偷用 creation 完成条件 |
| 教师备课 | [prep 主规范](../../../k12-teacher-skills/plugin/skills/k12-lesson-prep/SKILL.md)及 [rubric](../../../k12-teacher-skills/evals/k12-lesson-prep/rubrics/internalization.csv) | 真实原课和教师贡献；正常路径不提前向教师泄露模型 near-miss。没有不存在的 prep math 文件可加载 |
| CFU | [CFU 主规范](../../../k12-teacher-skills/plugin/skills/k12-check-for-understanding/SKILL.md)及其 math／KG／output／verification | 焦点先明确；完整验证资源在当前双材料齐备后开放，独立读题只取得原样学生材料 |

装配模块返回：当前工作目的、规则版本、实际内容与来源引用、允许工具、保留决定及未解决发现。跨轮恢复据这些记录回取精确内容；不让模型靠摘要重造已审过题目。每次规则并非全部重复发送，充分且可定位的必要内容先给，较大资源按当前问题读取；仍须记录实际读取范围。

原型知识工具已能取得 LC，但现有 A／B 生成没有实际调用 `components`。因此实现不能把工具存在当作已使用组件：本次能力确需完整组件审阅时，装配／取得相应结果，并在设计中留下使用或不适用判断；全年蓝图不因此预载全库 LC。一般数学创作和推理直接使用模型能力，不要求逐句检索出处。

独立读题使用新的受限调用上下文和工具可见集合；限制覆盖消息、文件、查询、缓存及日志回取，不能只隐藏一个工具名称。学生页本身的泄题图例仍属于检查对象，必须原样呈现。原创实验输入同样不能从 browse 的关系统计、课程引用或开发研究摘要间接取得对应 IM 内容。

## 本地 browse 的具体用法

已复核 [外部 OpenAPI](/Users/libo/Mathematics/k12-learning/apps/studio-server/contract/openapi.json) 的 browse 操作与本仓库 [知识探针](../experiments/grade8-linear-functions/knowledge_prototype.py)。这里只消费来源项目已经提供的 API，不调用其 authoring／generation／localization。

| 本次教学读取 | 对应已有 browse 能力 | Adapter 必须保留的条件 |
| --- | --- | --- |
| 全年 CCSS 目标视图 | frameworks directory、grade-levels／items、节点 children | 固定框架，递归及分页完整；父项／子项和实践不重复计数；完整性失败不能报全覆盖 |
| 具体标准及正文 | search、nodes detail、root-paths | 代码与真实框架身份一起核对；精确源值与翻译投影分开 |
| 支持 LC | 标准 learning-components 或节点 relationships | `supports` 的 LC → Standard，保留源实体、关系及实际取得范围 |
| 前后学习支持与概念联系 | relationships，必要时读取端点和路径 | `buildsTowards` 入向找基础、出向找后续；`relatesTo` 不当作先修；原始边与推断路径分开 |
| 允许时读取来源课程 | grouping outline、lesson reading、节点及引用关系 | 按实际资料范围开放；来源课程依赖与自有课程安排分开，原创冻结前不开放对应 IM 内容 |

模型使用少量教学语义查询，不能传任意 URL 或原始图查询语句绕过范围。Adapter 输出标准／实体及边的稳定身份、方向、来源版本、原角色值、查询范围、是否完整和被排除的部分；只返回实际需要的内容，不将浏览器响应全部灌进模型。

首版是本地 browse 的一个 Adapter，不预造多种知识后端。已有原型把框架 ID、快照、作者和来源白名单写成实验常量，生产应从核验后的配置／任务资料范围取得；项目固定 CCSS，固定的不是每次快照中的物理 ID 或首轮唯一出版者。

成功空集、分页未完、权限／可见范围排除、传输失败分别报告。空结果允许有标识的模型推断，不补造来源边；需要的证据尚未取得时不能静默降级。LVN 因素／策略和误解研究没有因 browse 能读标准就自动接入：按实际可用来源和教学适用性消费，经本次输入提供的研究也可有版本地使用，不为首个切片全量接入新库。

## 模型能调用什么，什么由执行端决定

| 工具职责 | 输入／实际输出 | 程序保证与判断边界 |
| --- | --- | --- |
| 读取 Context 和设计 | 允许引用、选择范围 → 原文／实际对象与版本 | 只能读取本工作可见内容；引用解析失败不能假装读过 |
| 查询知识 | 标准／关系目的与范围 → 上表的带来源结果 | 核对 CCSS、方向和实际分页；工具不替模型决定整个课程顺序 |
| 计算与核对数学 | 有限表达式／条件 → 实际计算与错误 | 复用已验证的有限 AST／SymPy 路径，补输入复杂度和执行时间限制；不能把任意模型代码直接放进 Web 服务进程，也不以计算正确代替题意正确 |
| 保存／修改设计 | 实际内容、父版本、作用范围 → 新引用与差异 | 保存有价值的模型输出；模型提出候选，不能写教师已批准或程序检查已通过 |
| 渲染材料 | 已保存设计、目标受众和所需载体 → 实际文件清单、变换记录与失败 | 文件存在及字节可读由工具确认，失败复用原内容；不让模型自报已渲染 |
| 请求必要的人类参与 | 实际问题、展示内容、影响 → 保存的待答对象 | 原流程已知参与点另由执行条件核对；不是只期待模型主动调用。工具不能代填回应 |
| 提出候选交接／检查发现 | 已存对象与简明理由 → 进入实际检查／修订 | 最终交付事实由执行端基于当前材料、检查和有效决定提交，不由 `finish_candidate` 自证 |

不同工作只取得适用工具；内部可以是普通函数与 middleware，不规定每行一个图节点。检查执行器形成自己的检查记录，模型可提交具体反例或对误报提出证据，再由检查路径裁定；不能用修改一个布尔值解除失败。

首版检查分三种依据：确定性检查负责身份、文件、精确共享内容与可计算条件；受限模型检查负责题意、数学解释和课程联系；真实人类输入负责选择、教师贡献和使用反馈。各自失败／未执行／不适用按真实范围保存，已知严重缺陷不能被总分抵消。

每次检查固定实际内容、适用判据、执行配置及证据位置。检查后修改内容需核对影响并重查，先采用较大范围重查保障正确；只有重复检查成本成为实测问题时才引入细粒度缓存。资源消耗跨工具、模型重试和 resume 累计，应用与 SDK 不各自无界重试。预算优化按 [先取得质量与消耗基线、再逐项改进](validation-and-release-route.md#质量与消耗的推进顺序) 后置，不为缩减调用而省略必要检查或修复。

## 上游渲染代码的复用取舍

源码复核对象：[render_all.sh](../../../k12-teacher-skills/plugin/skills/k12-lesson-plan-creation/scripts/render_all.sh)、[render_documents.py](../../../k12-teacher-skills/plugin/skills/k12-lesson-plan-creation/scripts/render_documents.py)、[lesson_common.py](../../../k12-teacher-skills/plugin/skills/k12-lesson-plan-creation/scripts/lesson_common.py)。这是静态判断，未重新运行 Word 渲染。

可复用的核心是 `shared`／`from_shared` 组织、按 teacher／student／stimulus 分面的材料及成套渲染；共享题面只写一次，教师脚本另有受众。`documents[]` 本身支持不同数量，不需要将固定四份文件写进全项目契约。

不能原样作为生产壳：脚本运行时安装依赖、按环境变量复制输出，源展开还会修复文本并补充符号定义；这些行为若发生在检查之后，会改变学生真正看到的内容。实现将依赖固定在构建环境，产物写入按版本核对，保存渲染变换并检查最终学生材料。共享键缺失在原 helper 中可返回空列表，生产要显式检查被引用内容，避免无声丢题；不同 doc ID 清理后冲突同样必须在输出前拒绝。

首个 Web 调用切片优先交付可打印 HTML、相关图件和可修订源内容，版式必须实际走查。课程结构、题面与依据不依附于某个 Word 布局；需要 Word 的任务可通过保留的渲染 Adapter 交付，缺失时如实失败，不偷换载体。HTML／SVG 作为生成内容使用受控渲染和受众读取，不能直接获得应用执行权限；这属于将生成材料放进 Web 的实现责任。

数学图形已有专门设计候选，当前只要求题目必需图件实际存在、数学正确、可读且与题面同版。函数精确绘图与一般插图按用途选择，暂不建设多轮精修产品或泛化所有学科的绘图 Schema。

## 从原型到首个实现切片

采用已有框架，重写薄的生产接入与业务提交机制；原型源码保留为证据，不直接搬运绝对路径、实验白名单、进程退出注入或固定模型到产品。

首个切片以实际全年蓝图向线性函数单元交接为主线，优先把连续课时的生成、实际检查／反馈和一个真实待答接入同一运行承载，再逐步覆盖整个请求单元。CFU 的既有恢复证据只复用其通用持久机制，不能把课程流程换成 CFU。最初这一小片贯通用于检验实现连通，不宣称完成整个单元。

实现验收包括：规则实际装配与来源范围；真实模型＋原生循环＋持久恢复；本地查询完整性；收到原文到语义采纳的失败恢复；候选和检查绑定最终文件；重复调度／取消不提升旧结果。后续完整单元、四项 Skills 同条件比较和生产服务验证由 [质量路线](../issues/05-capability-validation.md) 承接。

当前选择已有源码、官方集成和有限实验支持，足以进入规格；数学内容达标、所有模型效果、生产许可／部署和完整故障恢复仍是必须兑现的验证，不因本票解决而记为通过。
