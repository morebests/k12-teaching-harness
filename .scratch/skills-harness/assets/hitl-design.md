# 五项教学能力的人类参与、回应与恢复

初稿日期：2026-09-14；验证状态更新：2026-09-15。所属决定：[人类参与、暂停和恢复如何设计](../issues/07-hitl-protocol.md)。本文主体记录产品中的交互语义、源码依据、取舍及静态案例，采用范围由该票收敛；后续有限运行证据见文末，真实学校教师试用及任意自然语言对话质量仍待验证。

项目目的遵守 [README](../../../README.md)，承接 [执行结构决定](../issues/03-execution-structure.md)。固定上游为 `281eb8d41fe2837d911541c9bbb870b58add804c`；[四项原流程](execution-contract-draft.md)、[教案创建](lesson-creation-execution-design.md)、[CFU](cfu-execution-design.md) 继续完整保留。本文共享的只有请求与回应的承载要求，各能力自己的教学工作、回应解释和完成条件分别定义。

## 哪些情况下需要人

HITL 的起点是具体教学需要：有人要决定范围，有人要判断材料，有人要亲做任务。流程不能仅由“凡是生成内容都批准一次”或“事实信息齐全就永远不问”决定。

| 情况 | 处理原则 |
| --- | --- |
| 已提供本次所需事实、选择或适用执行授权 | 核对来源、对象、范围及有效性后直接使用；不为重演聊天问法索取同一个回答 |
| 信息可从已给材料或允许的本地查询取得 | 先读取并判断；查数据是 Harness 的工作，不转成教师问卷 |
| 缺少会改变教学结果的必要信息 | 只问实际缺项；沿各能力保留澄清数量、默认与第二轮的条件，不无故扩成表单 |
| 需要超出当前授权的目标、时间、资源或支持取舍 | 先完成能做的分析，给出具体冲突、可行方案和代价，然后等待有权作决定的人 |
| 教师选择先看草稿或外部明确要求本次审阅 | 展示真实草稿、任务及重要条件后等待，不能给空目录要求批准 |
| 教师备课的正常协作路径 | 真实任务上的教师尝试和判断是工作本身；Learner Model、模型代答或一个“同意”不能替代 |
| 计划含真实同伴或课堂观察事件，但外部未提供这些事件 | 可以交付活动预案和所需条件，不记录活动已发生；本仓库不借此建设课堂采集平台 |

授权执行与审过内容分别记录。例：“在这些目标和总课时内自行安排并生成材料”允许未来设计选择；“我接受这版课时任务”表达对实际内容的判断。前者不生成“教师已看过所有生成材料”的事实，后者也不自动授权改变目标和总课时。

本次适用的执行授权可以由可信的外部产品输入提供，注明来源和范围。系统默认、模型推测和真正的人类选择各保留身份；不能因为界面预选了一个按钮就记成已经提交。授权的管理与权限体系由外部提供，Harness 负责在本次动作上遵守它。

## 每次人类请求要呈现什么

以下是内容要求，不固定 Web 组件、API 字段或统一批准类型。面向用户的文字使用教学语言，内部协议记录由后端承载。

- **当前需要他完成的事。** 指向目标取舍、某份草稿、某个焦点或一道原任务，说明回应会决定什么。
- **足以判断的实际内容。** 草稿有任务和先备假设；删课方案有目标、任务、时间代价；备课给原题；材料审阅可以打开该版本的全部相关材料。摘要用于定位，不能替代影响决定的内容。
- **有意义的差异。** 修改审阅优先呈现改动及影响，附原版与当前版入口，不迫使教师逐份重读无关材料。
- **仍需关注的限制。** 给出影响决定的未解决问题；内部失败草稿可以因具体修订讨论而展示，并标明问题，不能作为检查通过的教学包交付。CFU 正常生成仍先完成实物验证再首次交付题目。
- **继续与退出的方法。** 能直接输入修改、给理由、要求先示范或结束；只在与本次交互有关时提供选项，不让每项 Skill 都展示同样的菜单。

发请求前保存实际展示的内容快照及相关依据。保存待答请求后结束当前计算；不让 LLM 反复轮询，不把教师等待时间当成模型工作。界面是否已展示、材料是否成功取回与人是否已回应是不同事实，外部产品应能返回真实提交所针对的对象。

## 课程体系设计

课程能力采用已确定的授权边界，按数学工作与学校条件提出取舍。不会仅因“第一次生成一个单元”新增全员批准或每课审批。

| 当前问题与展示对象 | 有效回应 | 后续工作 |
| --- | --- | --- |
| 目标、课时与资源互相冲突；展示实际任务支撑的方案及代价 | 选择一个方案，提出可执行调整，或在明确范围内授权模型选择 | 更新任务约束和对应版本，再修订受影响的课程、课时与检查；明确选择不再发一次同义确认 |
| 用户要求先审课程主方案；展示目标分配、进程、关键实际任务、Narrative 与条件 | 接受该方案并继续、具体修改、否决并给约束、结束 | 接受针对该方案；修改沿原审阅路径重呈。若明确“按这些修改直接展开”，在范围内继续，不追加批准 |
| 所请求范围的内容已形成；外部明确要求内容审阅 | 对本次材料范围的接受，或指向具体课时／任务的意见 | 保存审阅范围；检查仍按本版执行。只认可单元进程不能自动记为全部学生材料已审 |
| 个人支持与课程基线发生冲突 | 有权参与者明确允许何种目标／资源变化；或选择保持基线另做支持 | 生成相应适配或独立基线修订，不能将单个学生的需要默认为全体改变 |

“压缩一课时，目标保持”是设计约束，不是允许删除目标。若在授权内可通过合理调整实现，直接设计并检查；确认无法兼容后才把具体代价交给人。“你决定”在当前明确的选择范围内可以是授权，不扩成无限范围，也不记录为对尚未生成材料的审阅。

## 课时与材料设计

来源：[creation 主规范 Step 1、4、5](../../../k12-teacher-skills/plugin/skills/k12-lesson-plan-creation/SKILL.md)。原规范先问整套／草稿，再根据回复行动。当前产品保留这项选择的目的，并直接使用请求中已有的明确选择或适用授权。

| 输入或回应 | 解释与执行 |
| --- | --- |
| “直接生成完整材料”，或当前单元任务已授权展开其课时材料 | 交付路径已有依据，直接完成知识依据、教学构建、材料和检查；不在每个子课时重复问整套／草稿，不伪造一次教师点击 |
| 尚未确定整套／草稿，也无适用的执行授权 | 与真正需要澄清的问题合并提出选择；没有回应不按预选值自动执行 |
| “先看草稿” | 完成同等教学构建后展示实际任务、先备、流程和本次证据安排；等待其后动作 |
| 草稿后“讨论增加五分钟” | 在约束允许时修改并重呈草稿，继续等生成指令；不把修改理解为已放行 |
| 草稿后“讨论增加五分钟，改好直接生成” | 保存该复合指令，核查总时长及其他约束，修改、呈现变更并生成；不用再问一次是否同意相同修改 |
| “可以”明确回应当前唯一的“按这版生成吗” | 作为该对象的放行；短回复不因字数少自动视为含糊 |
| “可以”回应同时包含多个互斥方案、或说“行，不过还要……”且未明确修改 | 只澄清影响后续的歧义；不从一个词生成多项授权 |
| 成套交付后没有回复满意 | 本轮交付可完成，保留修改邀请；不转入适配的全套满意等待 |

复合指令允许未来按指定修改生成，它不同于“对旧草稿的无条件同意”。如果实施精确修改时又发现必须变更核心任务、目标或授权外的课时，说明新增差异并请求该项取舍；不借一次“小修改后生成”授权重造一节课。

## 教学适配

来源：[适配主规范 Step 1、4、5c、6](../../../k12-teacher-skills/plugin/skills/k12-lesson-differentiation/SKILL.md) 及 [数学／输出要求](execution-contract-draft.md#数学适配必须实际完成的教学工作)。先有实际原课和明确改动目标；来源候选未能消歧时，展示具体差异让教师选，不任意代选原课。

正常协作路径保留上游“确认本轮整套材料满意才完成协作”的独立要求；固定上游是四份 Word，本项目以本次明确的材料包为对象，格式与数量由能力和产物约定决定。**材料已经生成并可审阅，与协作已经结束分别报告。**等待满意时结束计算、保留请求，不阻止用户查看已经检查的材料。

| 输入或回应 | 解释与执行 |
| --- | --- |
| 层级、学习需要、原课和交付路径已明确 | 直接使用并落实到支持与任务；不重复问同一事实或把外部状态改写成模型诊断 |
| 选择草稿或修改草稿 | 保留各层实际任务、共同核心与重分组依据；仅修改与修改后直接生成按自己的草稿流程解释 |
| “整套都可以”针对当前完整材料包 | 记录本包的接受，正常协作可结束；仍不替代数学／教学检查 |
| 只说“B 组可以” | 仅记录 B 的接受，其他材料保持原状态；不能把局部评价升级为整套满意 |
| 分别接受各份材料 | 可累计各自仍有效的接受，覆盖当前整套时结束；不为重复一句“全部满意”再问一次。该累计语义属于 Web 适配，需与上游整体问法比较 |
| 修改其中一份，其他已接受 | 检查共享题目、教师说明与本次接受所依赖的条件；只保留未受影响且范围仍成立的接受。再次展示受影响部分与可回取整套，不重新询问无关内容 |
| “不再审阅，按这些修改直接交付”或“到这里结束” | 尊重明确指令，完成允许的修改／收尾或停止；记录退出审阅／结束，不写成教师已满意。未满足的整套接受条件如实保留 |

若调用方明确请求的是**只生成适配材料、交给外部稍后审阅**，可以按该范围完成生成并返回审阅所需内容；不冒充走完正常协作路径。此路径必须由可信任务范围或授权给出，不能在未收到满意、预算耗尽或用户沉默时自动启用。它继承质量检查，改变的是协作范围；原上游完成判据单独报告，不声称逐字等价。

没有明确的只生成范围或结束指令时，适配沿正常协作路径保留整套接受的待答状态。材料可交付、计算可停止，都不会自行取消该参与条件。

外部明确提供的持续支持是输入约束。教师提出的支持修改与课程目标变化分别解释，必要时核对适用授权；不能把“都可以”泛化为允许模型日后撤掉持续支持。没有真实学习证据时可以给有标识的默认支持，不能要求先做学生诊断才能继续。

## 教师备课

来源：[prep 主规范](../../../k12-teacher-skills/plugin/skills/k12-lesson-prep/SKILL.md) 与 [rubric M1–M6、R4、O1–O2](../../../k12-teacher-skills/evals/k12-lesson-prep/rubrics/internalization.csv)。教师参与首先是理解课时的工作，不以批准替代。材料已审、Learner Model 已给、教师回答很短都不能单独判断参与是否发生。

这里的 **near-miss（近似正确回应）** 是具体任务中看似接近正确、却在关键条件或推理上仍有缺口的回答；M6 的原意是辨认 nearly-right answer 在哪里不足。例：学生依据“三条直边”把一个尚未闭合的图形也认作三角形，已有属性判断但遗漏封闭性。备课时提出的这种可能回答是预测，不能登记成真实学生作品；也不把所有错误统称为 near-miss。术语见 [领域词汇](../../../CONTEXT.md)。正常流程让教师先亲做并提出自己的 near-miss，目的在于形成对原任务的判断，而不是让教师替模型挑错。

| 实际情形 | 呈现、等待与继续 | 需要留下的区别 |
| --- | --- | --- |
| 正常协作进入 | 取得真实课并按原课方法内部试做；交给教师原任务，请其亲做、提出自己的近似正确回应并指出不足，等其回应后再揭示模型相应发现 | near-miss 由教师先产生，不能在正常路径中先给模型错例再请教师分析；教师贡献要影响后续讨论与便签 |
| 教师提供了同一实际任务的已有尝试或分析 | 读取并用于本次备课，补充确实缺少的工作，不强迫重新做一遍 | 记录是谁提供、针对何任务；不声称验证了其心理过程或无辅助作答 |
| 教师只给正确答案，尚未提出自己的近似正确回应并指出不足 | 正常路径可给一个与该题有关的短追问；教师之后明确拒答／结束则走相应路径 | 正确答案本身不自动满足 near-miss 生成要求，也不以错误答案否认真实贡献 |
| 教师直接问任务中的具体概念／方法为什么成立 | 先按原任务方法回答所问内容，再接续必要的教师问题 | M2 明确允许 content-explanation 先答。它不自动允许预先给出整套 near-miss 或所有难点诊断；M6 的具体限制仍需满足 |
| 教师明确要求先给 near-miss 示例 | 提供其要求的模型示例并注明来源，随后按其需要继续 | 属于 M6 明列例外；模型示例不登记为教师提出 |
| 教师明确不能／不愿尝试，但仍希望获得帮助 | 尊重拒答，提供基于原课的帮助，不持续逼问 | 拒答可满足部分先后例外，但没有实际贡献时不能声称 M5 的正常协作条件已满足 |
| 教师明确只有三分钟 | 优先给本课最有用的单轮内容，允许无便签；不消耗时限展开常规问答 | 上游短时例外与正常协作的评价分别记录，不把所有 rubric 条款自动记通过 |
| 教师贡献含数学事实错误 | 区分其在举 near-miss 还是表达自己的判断；后者应具体纠正，便签采用准确内容 | 保留原贡献及修正，不把人类输入视为数学真值，也不抹掉教师确实参与的事实 |
| 教师已做实质讨论后说“够了” | 结束追问，按已有有用内容收束为简短便签；若明确不要便签则不生成 | 正常结束不要求再批准“是否结束”；便签沿原课实际阶段与贡献组织 |
| 教师说“立即取消，不要再生成” | 停止相应工作，保留已发生记录，不追加便签 | 操作取消不同于完成备课；已交付内容不能被说成从未发生 |

教师的任务预测、模型模拟和真实学生作品分别保存。教师在备课中提议改课时，可以记录具体发现并建议转入创建／适配；其明确要求实际改课时，另按该能力处理，不在 prep 内静默重排原课。单句可回答的事实查询仍按原 Skill 边界处理；复杂的原任务内容解释不因同含“问题”二字被排除。

短时例外来自教师实际给出的时间需求，不能由模型预算耗尽冒充。M6 对不能作答的豁免也不取消 M1 的真实原课要求；无原课时先取得材料，不能为满足请求而虚构一课。原 rubric 对短时／拒答与 M5、M6 的组合未完整统一，评测保留其差异，不改写为全部通过。

## 理解度检查

来源：[CFU Step 1–4、7](../../../k12-teacher-skills/plugin/skills/k12-check-for-understanding/SKILL.md)。先明确要观察的理解，再让题目与错误映射围绕该范围构建；不能仅凭年级／主题充足就省掉尚未作出的焦点决定。

| 输入或回应 | 解释与执行 |
| --- | --- |
| 尚无有效焦点决定 | 读取依据，提出学生要做什么、相关限制与理由，然后等待；此时不继续造题 |
| 外部已提供本次有效焦点决定 | 核对同一目标、任务用途、表征／范围限制和适用版本，补齐需要的依据，重述后直接构建；不制造一次新的提议与同意对话 |
| 只有“检查分数”或上层课程已批准 | 作为任务信息，仍需把可检查焦点说明白；不是本次具体焦点已被选定 |
| 对当前提议说“就这个” | 采用该焦点及其已说明限制，继续构建 |
| “换成单位分数”或明确选择多个组件 | 采用改向，核对标准与相关条件，重述后继续；不自动增加第二轮批准，不硬按一组件一题 |
| “你在这两个焦点里选更能区分理解的” | 记录有边界的真实委托，模型按依据选择并解释后继续；这是对决定权的明确委托，不记录为教师亲自选定某项。此产品适配须单独评测，不能用泛泛“你来做”替代缺失的范围 |
| “先出一题看看”回应焦点提议 | 明确延续当前焦点且无冲突时，可作为按该焦点构建的指令；照常完成实际产物检查，不给教师提前看未经验证的初稿题 |
| 修改涉及标准、数域、表征或诊断用途 | 区分明确改向与含糊要求；已明确可行则更新依据并继续，出现未解决的目标冲突才澄清。旧的焦点限制和检查不能静默沿用 |
| 交付后沉默、满意或要求修改 | 交付与修改邀请可结束本轮；修改进入相应版本的实物验证，不新增满意等待 |

使用已有决定或有限委托改变的是宿主中的重复问答，不削弱焦点明确、错误映射和材料验证。原 Skill 的真实提议／回应主路径继续作为比较基线；本产品记录实际采用了哪条路径，不伪造一次从未发生的暂停。

## 回应关联与实际处理

请求的教学内容按上述能力分别定义。可共用的承载部分只解决定位和恢复：哪个任务提出了什么待答对象，谁实际提交了什么，执行是否已经处理过。最终字段名、接口和存储事务由后续票确定。

每次至少保留以下信息：

- 待答请求的稳定身份、所属能力／任务、实际问题及展示快照；涉及哪些对象、内容版本和约束。
- 外部提供的参与者及本次可执行的决定范围；真实输入来源与模型生成内容分开。
- 原始回应、所指请求／版本、真实事件身份与接收顺序，以及结构化选择或自由文本。
- 回应的解释、引用其原文的依据、实际影响范围；尚未满足或冲突的部分。
- 该输入是否已采纳、已被后续决定替代、因条件不成立未生效，以及所产生的修订／执行结果引用。

采用以下处理顺序：

1. **确认来源和对象。** 按可信外部身份与输入上下文核对请求；文档正文、模型模拟或文本里自称“管理员”不产生权限。对明显指向旧请求的回答保留其原对象，不塞给任意当前等待点。
2. **识别重复与当前状态。** 同一事件重复提交返回已有处理结果，不再启动生成。同一事件身份携带不同内容属于冲突，不能任意采用后到内容；表达改意应是新的事件。
3. **解释本能力里的实际意思。** 结构化选择与自由文本一并处理；保留“同意，但是……”中的限制。模型可以提出解释和动作，不能自己创造实际回应或权限。只对会改变后续行为的歧义问一句具体问题，已明确的事实和决定继续保留。
4. **核对决定仍适用的范围。** 比较当前采用内容及相关约束，而非只比较一个全局版本号。决定改变范围、采用旧版或要求恢复旧版时，分别处理。
5. **一次采纳为明确的逻辑动作。** 在请求仍有效、对象条件未变化，且外部决定规则认定当前回应足以形成决定时，记录回应已处理及要继续的动作；如果其间发生变化，重新检查，不让两个回应同时都消费同一个等待点。消费等待点不自行决定多人的权限或优先级。
6. **按保存的动作恢复。** 模型或工具工作失败后从已记录动作继续，不重新解释同一回应然后选另一方案；真实恢复和物理副作用是否可重复，需锁定框架的原型验证。

这些是应用需要兑现的语义，不是对数据库事务、网络投递或模型服务恰好执行一次的现成保证。事件去重不等于任意工具副作用只能发生一次；结果不确定时按执行设计核对，不通过再问教师同一问题解决后端不确定性。

请求需要有可确定的最终决定主体或外部决策规则。单一负责人的请求按其有效回应处理；多人均可参与但未明确谁能决定时，将该规则缺项返回调用方，不自行选择先到者。请求已被消费后，另一个参与者的不同有效回应仍需按外部规则判断是否形成新意图或实质冲突，不能作为同一事件的重复或普通迟到一概忽略。出现尚未解决的冲突时，停止争议结果继续成为当前交付；已经发生的历史交付如实保留。

部分回应可分别处理。例如在同一轮给了年级但未选互斥草稿方案，保留年级，仅处理仍影响执行的选择；若该能力明确允许收到有效回复后采用整套默认，则按该规则执行，并记录默认而非人类亲选。教师对一道题的实质备课回应不因另一项信息未填而被丢弃。

## 旧版、改意和并发

决定的适用对象有时是一版具体材料，有时是某组设计约束与未来行动范围；不能把两者压成“版本不同就一律重问”，也不能一律跨版本继承。

| 变化或冲突 | 采用规则 |
| --- | --- |
| 重复提交同一“按这版生成” | 返回第一次的处理结果；后台失败可以恢复同一工作，不把重发当再次授权另造一套 |
| 旧草稿的同意到达，当前题目已实质变化 | 旧同意只登记其对象，不放行新题。判断用户是否明确要旧版、改动是否已在先前授权内；仍需新取舍时展示实际差异 |
| 仅改分页，旧决定针对数学任务选择 | 内容与相关条件核对后可继续沿用该任务决定，保留适用性依据；新版式检查仍需重做，不能把旧决定伪装成看过新排版 |
| 草稿中明确指定“按这些改动直接生成” | 这项授权覆盖指定改动后的后继内容；守住其范围并检查，不能因为版本改变机械失效 |
| 与该决定无关的个人状态或另一课更新 | 本次已采用输入没有变化时不影响等待；若决定采用新输入，先分析其与本决定的关系，不按外部全局版本变化全部重问 |
| 用户先同意，生成中又说“改成另一方案” | 新事件记录新意图；在可停止处停止旧工作并形成新修订。旧在途结果可留存，但不能再提升为当前结果或交付；已经交付的历史保持真实 |
| 两名参与者对同一有效请求给出冲突决定 | 依外部已经明确的决定权限与优先规则处理；无此规则则呈现具体冲突给有权参与者解决，不按角色名称猜谁更有权，不让模型投票 |
| 待答请求被替代、取消或过期后收到回复 | 记录迟到输入，不直接恢复已关闭执行。若当前仍有相同需要，可核对后作为当前输入引用；不得自动重开已取消任务、增加预算或假装原请求按时获答 |

重新关联旧输入时保存原输入、原对象、当前使用范围和理由；绝不重写它原先指向的版本或时间。来源可靠且语义清楚的真实决定可以复用，内容接受不能扩大为未看过对象的接受。

并行展开课程时，互不依赖的分支可继续；一个分支的人类请求只阻塞受其影响的工作。最终整套交付仍受其整体条件约束。共享目标变化导致其他请求的展示内容失效时，应向外部标出已替代请求和新的具体问题，不继续接受互相矛盾的批准。

## 等待、停止与恢复的边界

教师等待可以跨越多次后台运行。保存已展示内容、待答对象和继续位置后释放计算；到达回应时先执行上述校验，再恢复。教师不会因一次模型故障被要求重新回答已经记录的问题。

- **沉默与超时：**不生成满意、确认或教学贡献。按外部有效策略转为暂停保留或停止待续，保留原因；不循环催问。重新启动计算要有有效条件，预算不会因恢复自动清零。
- **结束讨论：**按具体能力收束已有工作。prep 有实质内容时形成便签；适配结束审阅可保留未接受项；creation／CFU 的正常交付不要求延长对话。
- **取消当前执行：**停止启动新工作，标明在途操作结果是否确定；已取消执行的迟到结果不得成为当前交付。取消不抹掉已经发生的交付，也不自动撤销外部发布。
- **数学错误与人类接受：**即使教师已说满意，确认存在的数学错误仍需纠正并使相关结果待重查；接受记录保留原对象，不能让它覆盖检查失败。
- **运行与参与证据：**生成完成、等待回应、教师退出、内容未通过分别报告。真实人的回应证明其作出过这一输入，不证明材料有效或学生已经学会。

完整持久化、服务取消和事务能力继续由 [运行时专项](../issues/11-agent-server-stack-research.md) 核查。Web 界面与权限体系由外部实现；Harness 返回够用的教学请求、当前进度、对象版本及处理结果，不自行建设学校审批平台。

## 变化怎样保留原 Skills 的价值

| 原机制及目的 | 本项目采用方式 | 后续必须比较或验证的行为 |
| --- | --- | --- |
| creation／适配先选整套或草稿，给教师控制生成路径 | 保留未定路径时的选择，直接使用已有真实选择或适用授权 | 是否少问已答问题且不误跳草稿；比较实际材料和修改保真，而不是仅统计问答减少 |
| 草稿修改后重呈，放行当轮生成 | 区分仅修改与明确修改后生成，后者覆盖指定后继版本 | 复合意图解释是否准确，是否遗失修改，是否因发现额外范围变化而正确停下 |
| 适配整套满意结束 | 正常协作保留；局部接受可按范围累计；明确只生成或退出审阅如实声明不同完成范围 | 不把 B 组接受当全部接受，不以超时自动省略满意条件；改动影响范围正确 |
| prep 正常教师先尝试、模型后揭示 | 保留正常路径及内容解释、先示范、拒答、短时与结束例外 | 教师贡献是否实际影响结果，是否误泄露 near-miss，是否尊重真实停止；正常与例外评分分别报告 |
| CFU 先提焦点并等待，明确改向后继续 | 正常主路径保留；已有有效焦点或有边界的明确委托直接使用 | 不用主题信息冒充决定，不制造重复确认；焦点与题目诊断价值仍需质量评测 |
| 宿主聊天中的真实回应 | Web 输入有来源、对象、展示版本、处理身份及实际动作 | 迟到、重复、并发、故障重试不造成错误恢复或重复生成 |

这些是依既定产品目标作出的适配，不是已证实优于上游的机制。保留原始规则和同条件对照，分别报告行为变化、教师负担、内容质量与运行结果。

## 原型和评测场景

下表是未执行的场景。程序原型可以显式模拟人类事件和语义解释；模拟结果不得被记作真实教师贡献或 LLM 已正确理解语言。

| 场景 | 应观察到的行为 |
| --- | --- |
| 单元任务已明确直接生成材料，进入下一课 | 使用适用授权，不重复草稿选择，也不记录虚构点击 |
| 草稿后“把讨论加五分钟” | 改稿并重呈；没有明确生成授权时保持草稿路径 |
| 草稿后“加五分钟，改完生成”，导致总课时超出不可变约束 | 先保留修改意图，呈现具体冲突；不悄悄删其他目标或误认授权范围无限 |
| 当前唯一请求是“按这版生成吗”，回答“好” | 使用指向明确的真实回应，不因短文本强迫复述 |
| 对两个互斥方案只说“都行，不过时间不能变” | 保留时间条件，判断是否是范围内委托；不能同时选择两案或忽略附带限制 |
| 适配只认可 B，A 与教师说明仍有意见 | B 的接受单独保留，协作尚未完成 |
| 适配随后改共享题干 | 找到所有受影响材料及接受范围；不能因其他文件本次没直接编辑就保留全部接受 |
| 只请求生成适配材料供外部后审 | 生成检查可结束；教师满意未发生，不记正常协作完成 |
| CFU 从一个组件明确改为两个 | 重述有效范围并继续，不增加同义确认，不机械增加题量 |
| CFU 初始只有泛泛主题 | 仍形成可判断焦点，不以“教师提供了主题”跳过尚缺决定 |
| prep 先问原题方法为什么成立 | 先解释所问内容，保留其后真实贡献；不顺便揭示完整 near-miss 分析 |
| prep 教师明确要求模型先给 near-miss | 按例外提供示例，来源仍是模型，不登记教师贡献 |
| prep 教师三分钟请求或明确拒答 | 按相应路径提供帮助并允许结束，不反复逼问，不把正常协作各项自动判通过 |
| 草稿旧版同意晚到，新版改变数学任务 | 原输入绑定旧对象；不直接解除新版等待 |
| 仅分页变化，旧决定针对数学任务 | 核对后复用任务决定，记录其范围；新排版仍待检查 |
| 同一回应网络重送，或同一身份带不同内容 | 前者取得已有处理结果，后者作为冲突；都不静默启动第二次生成 |
| 同意后生成中改意，旧调用稍后返回 | 新意图有效，旧结果不成为当前交付；保留真实已发生行为 |
| 两名有权参与者同时给出冲突选择 | 使用外部明确的解决规则；没有规则时保留冲突而不猜权威 |
| 等待跨进程恢复，或处理回应后下游工具失败 | 恢复同一展示对象／已采纳动作，复用记录；教师不重答。实际保证由框架实验检验 |
| 教师满意后数学检查发现错误 | 满意历史保留，当前结果进入修复与重查；不借人类认可通过失败内容 |

上述场景进入 [课程状态原型](../issues/14-curriculum-state-prototype.md)、[CFU 运行原型](../issues/09-cfu-runtime-prototype.md) 和 [质量验证](../issues/05-capability-validation.md)。自然语言中的否定、限定、纠正、短回复与混合意图需要真实模型样本；只对预先给出的动作枚举跑通不能证明理解能力。

## 后续交接

### 当前验证程度（2026-09-15）

上述介入位置已由关联决定收敛为教学语义基线；尚未在产品运行中兑现。[Gemini 实验的 HITL 审计](../experiments/grade8-linear-functions/hitl-coverage-audit.json) 核对 9 次实际执行，真实 `request_human` 调用和待答记录均为零；另有 1 次仅装配。实验只有约束冲突时记录并停止的工具，没有回应／恢复入口。检查反馈、模拟压缩需求及 HTML 模拟回应分别保留原证明范围，不算真实 HITL。

[主执行与调用设计](main-execution-design.md) 将本页各能力语义放回任务、Context、检查修订和真实等待链；[运行架构专项](../issues/11-agent-server-stack-research.md) 核对 LangGraph／Agent Server 的承载及 LangSmith 的观察与评测。LangSmith 人工标注用于质量评阅，不替代本页的教学决定或教师贡献；运行证据另按实际范围记录。

后续 [CFU 持久运行探针](cfu-durable-prototype-results.md) 已取得一次真实原型焦点选择，并实际验证回应保存后进程退出、新进程恢复和重送；固定事件另测改向、已有焦点、旧版与取消等控制。其材料和模型输出固定，真实回应来自当前项目评阅人，不是合作学校教师；这不改写此前 Gemini 实验无 HITL 的事实，也不证明其余四项能力或任意自然语言回应的质量。

[调用接口](../issues/02-execution-interface.md) 按这些语义设计启动、回应、修订、取消和结果获取；[模型与工具](../issues/04-runtime-adapters.md) 落实自然语言解释、上下文可见性和动作校验；[运行时](../issues/11-agent-server-stack-research.md) 核查持久化、并发与在途操作。具体字段、存储和框架版本不在本票提前锁定。

本轮收敛交互与恢复的教学语义，仍需原型和质量证据来判断实现是否兑现。独立课程体系、数学优先、外部 Learner Model 与知识本地化边界保持不变。
