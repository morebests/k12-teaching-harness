# Context 与 LLM 使用方法：设计起点

整理日期：2026-09-15。当前候选，未完成模型、运行时或教学质量验证。

执行结构已在 [执行流程和状态决定](../issues/03-execution-structure.md) 收敛设计基线；阶段边界、实际资源路径、装配记录、状态和停止规则见 [执行结构分析](execution-structure-design.md)。本文继续保留各阶段的教学输入与设计依据，不将候选细节全部升格为实现要求。

本项目从具体教学工作反推 Context 和 LLM 的使用方式。上游 Skills 是目前首选参考与质量比较基线；它们对资源加载、知识依据、教师参与、生成、验证和修订已有具体安排，应逐项理解后设计。独立课程体系同时要求补充跨层内容和修订关系。

详细流程已完整保留在 [四项执行与 HITL 分析](execution-contract-draft.md)、[数学教案创建分析](lesson-creation-execution-design.md)、[理解度检查分析](cfu-execution-design.md) 和 [学科差异分析](lesson-creation-subject-flows.md)；本文不替代它们。

## 模型内置知识与任务证据怎样协作

依据用户明确的克制设计原则，采用 [README](../../../README.md#设计与协作原则) 的“最小充分方案、充分利用推理与内置知识”。这是设计方向，未证明某个模型已经达到教学质量要求。Context 用于明确工作、补充模型无法凭自身取得的本次事实、提供可回取的材料与工具；不预先替模型列尽所有行动和错误情形。

| 信息或工作 | 使用方式 |
| --- | --- |
| 一般数学知识、求解、解释、类比与任务创作 | 主动使用模型内置知识和推理形成候选，按实际题目验算和检查。原创题及可检查的数学推导不要求逐句找到 KG 节点或外部出处 |
| 教学方法、表征选择、进程安排与错误预判 | 结合内置知识、适用 Skill、当前目标和已有证据推理设计；保留重要选择的简明理由。提出一种可能困难不等于观察到学生已有该困难 |
| 本次采用的标准、LC、图关系及具体课程内容 | 从本地来源或已经提供的有效内容取得；确认身份、版本和用途。已充分取得的内容可以复用，缺口或冲突才补查；模型提出的新联系以设计推断参与，不需要伪装成图中原生边 |
| 学校时间与资源、学习者状态、已有教师决定 | 使用本次真实输入。允许按能力约定采用的设计假设明确标注；模型内置知识不生成关于这所学校或这个学生的观测事实 |

检索应能说明当前要补什么信息：确定标准范围、核验引用、读取实际任务、取得相关关系或解决影响设计的未知。模型可以自主发起这些查询；不因某一步被命名为“研究阶段”就重复取齐无关数据。保持本项目已采用的来源要求与信息隔离，也不因模型自称知道就省略关键依据。此约定不要求每次调用读完整 KG、全部 Skills 或全部场景；按本次工作加载充分内容，其余材料可定位并在需要时回取。

交互同样先利用已有信息：输入和工具已能解决的问题由系统继续处理；仅对实质缺项、授权外取舍或该能力有目的的教师参与发问。实现先保留简洁模型循环和必要边界，发现具体不足后再比较额外阶段、检查调用或细粒度状态。详细取证方法见 [控制粒度研究](harness-control-granularity-research.md)。

## 用这些流程设计 Context 和 LLM 方法

以下是基于上述事实提出的设计问题与候选方向，尚未确定完整实现。

| 从教学工作出发的问题 | Context 与 LLM 设计需要回答什么 |
| --- | --- |
| 当前到底在完成什么教学工作？ | 明确能力、阶段、目标、交付范围与允许的行动；按工作选择相关规范，不将所有 Skill 合成通用提示 |
| 判断需要什么依据？ | 提供适用课程层级与 Narrative、目标和本地图关系、实际材料、相关学习证据、学校约束及真实人类决定；保留来源与版本 |
| 模型怎样把依据变成内容？ | 组织理解目标、查图、选任务、试做、比较、生成、检查与修订的行动循环；需要工具结果时实际调用，不用一次文字回答替代工作 |
| 下一步应接续什么？ | 保存已选目标、实际任务、材料、检查、未决问题与简明设计理由；生成和摘要都不能悄悄改变已确认的内容 |
| 谁在什么时点应看到哪些内容？ | 区分教师参与、学生任务、生成准备、隔离读题与解释验证；例如盲答者不先收到答案，教师亲做前不先收到模型的对应分析 |
| 上下文变了会怎样？ | 识别课程版本、任务、Learner Model 或人类决定的变化，检查影响后再决定复用、重查、重生成或请求具体取舍 |
| 怎样在产品中成立？ | 外部产品提供任务和有权限的上下文，承载真实交互；Harness 返回待答请求、版本化产物、检查与执行证据，供外部发布治理使用 |

Context 不能只是一份不断增长的聊天记录。工作所需的精确任务、约束和来源必须能够回取；容量不足时按相关范围装配，压缩后的摘要仍需指向原始依据。Context 的存储、装配、可见范围和更新方式要与各能力流程一起设计。

产品 Harness 的任务 Context 与当前开发会话分开：实际装配采用的规则、输入、工具结果及本任务已有状态，不自动继承开发者的对话或研究仓库。同一任务仍需延续实际工作。独立运行与资料可见范围分别落实；例如 [八年级原创比较实验](grade8-linear-functions-validation-design.md#原创隔离能保证什么不能保证什么) 复用本身的 Context 和资源控制，原创阶段不引入 IM 课程内容，冻结后比较阶段再读取。开发者接触过参考不等于产品运行已经接触，也不需要另建一套隔离基础设施。

知识内容的身份、框架版本、关系语义及来源／推断区别统一遵守 [知识使用约定](../../../docs/references/knowledge-consumption-contract.md)。LC／LVN 可以提供共用的建模结构，外部系统关联具体学生并依据证据形成个人状态。Context 按任务取用相关定义与个人状态，区分共同研究依据、个人观测及推断；知识技能掌握度不能代替所有学习因素的状态。

模型选择也按实际教学工作验证：课程进程、数学任务、教师对话、独立检查可能有不同要求，但目前不预设必须用多个模型或每一步一个 Agent。保留上游有依据的组织方式作为起点，再用质量、可靠性、延迟与成本证据比较候选。

## 整体课程方案与单元内课程设计的输入

2026-09-15 用户要求先明确两类任务的知识与 Context，再开始实际模型工作。以下是本次数学实验的输入内容候选，不是已固定的 API 字段、课程顺序或生成 Prompt。当前沿用“八年级全年蓝图＋线性函数完整单元”的讨论范围；实际单元边界、时间与学校条件仍须在实验任务中明确。

这里的运行时 Context 指模型本次实际取得的工作材料；外部提供的教学上下文、知识资料、任务规范、既有产物和执行结果分别是其中的组成部分。一般数学知识与推理可由模型自身提供；标准原文、图事实、学校事实和真实决定按相应来源取得，不让模型伪造。

### 两类任务共享什么

共享的是简明且适用的工作要求，不是相同的教学流程：

- **固定 CCSS。** 沿 README，全流程使用 CCSS；数学采用其内容与实践标准。Harness 固定框架身份、记录数据版本，知识查询仅返回 CCSS 标准及其相关组件和联系；框架选择不是教师输入或模型设计任务，州版同代码不混入 Context。
- **本次任务与完成条件。** 范围、受众、材料语言、所需产物，以及本轮交蓝图、关键课段原型还是完整单元；研究原型与最终教学交付分开。
- **数学教学质量要求。** 学生应有理解、求解、论证、表征和应用的实际机会；标准覆盖不能只靠标签，判断须能指向内容与证据。依据可采用独立的 [数学实践标准](https://www.thecorestandards.org/Math/Practice/) 和本项目已定能力目的，不从 IM 对应课程反推出设计答案。
- **事实与设计的区别。** 标准和图关系保留来源；学习条件、预判困难和教学安排中的假设注明地位；模拟学生回应不成为实际学习证据。
- **允许的行动与资源。** 模型知道有哪些知识查询、当前设计读取／保存、数学计算／图形、材料生成与检查能力，以及返回结果怎样解释。工具的实际执行由 Harness 承担；本轮不开放 IM 课程查询，不用提示词代替资源范围控制。
- **人类参与与修订范围。** 已有有效决定直接使用；在明确任务内继续工作，超出允许改变的范围或缺少关键真实条件时提出具体问题。能力自身需要真实参与时保留目的，不把每次工具调用变成审批。

这些要求由 Harness 维护和装配，不要求教师手工填写。API 密钥和运行环境凭证仅供调用客户端使用，不是教学 Context。公开质量标准可以给设计模型，比较材料、未公开测试答案和预设失败剧本不能提前给它。

教学规范与评价依据先盘点既有资源，再判断缺口。LC／LVN 已有研究支持的教学策略，原 Skills 已有工作规范和公开 rubric，LC 另有 Evaluators；它们与本地 KG 数据、当前可调用接口分别核实，见 [资源与接口边界](learning-commons-integration.md#browse插件与教学评价资源的边界2026-09-15)。本项目主要明确如何选择、装配和执行适用依据，只补实际未覆盖的要求，不预设需要重建一套教学法或评分体系。

### 两类任务分别要有什么

| 输入内容 | 整体课程方案设计 | 单元内课程设计 |
| --- | --- | --- |
| 任务职责 | 组织八年级的完整目标、单元职责、年内时间和前后衔接；重点关注目标单元的位置，但不围绕它删掉其他年级目标 | 依据本次采用的课程蓝图，把目标单元落实成课段、课时和可用材料；说明允许重新设计的空间 |
| 标准范围 | CCSS Mathematics 的全年内容标准原文、层级和数学实践要求，保留数据版本；不能只有线性函数的一个标准或全年的标题摘要 | 本单元承担的完整 CCSS 标准和细分目标；区分主教、作为已学基础使用、为后续准备、复习或评测的角色，不能只给一句目标转述 |
| 学习进阶与关联 | 年内目标间及有关前后年级的真实联系；用于判断哪些可整合、哪些有支持关系和跨单元衔接，不自动转成固定课程顺序 | 与单元关键理解、具体任务和邻接目标有关的路径、组件和方向；必要时回查同年级其他领域或有关前后年级，不限定只查线性函数关键词 |
| LC 的粒度 | 先取得全年目标视图，在拆分目标、合并主题或判断学习跨度时按需读 LC；不要求起步加载全库组件 | 对实际采用的目标充分展开相关 LC，用于判断任务和检查需要覆盖什么；不固定一组件一课／一题，也不沿用上游固定取若干条的数量作为本项目规则 |
| 既有课程与上层依据 | 新建时明确没有既有课程；修订时读取实际旧版、保留要求和修改目的，不要求调用方先提供单元顺序 | 读取整体设计的实际采用版本、目标分配、Narrative、进入与离开条件、时间预算、相关单元联系及尚未验证的假设；已有任务／表征若被明确采用，保留原内容 |
| 学校条件 | 全年可用数学教学时间、每课时长、考评或学期安排、班级组织、教师准备条件、资源与语言限制 | 本单元可用时间和节奏，实际可用打印、器材或软件，课堂／课后工作量、教师准备条件及本次材料语言；从整体约束继承，局部变化注明 |
| 学习者信息 | 公共课程基线所服务的群体、已有课程经历、必要的整体支持条件；有真实群体证据才使用，无需先有全体学生个体模型 | 与当前目标有关的班级／个体证据、作品、已有支持及其条件；证据不足时使用注明假设的通用设计，并提出怎样取得进入条件证据，不能把“应学过”写成“已掌握” |
| 设计与检查要求 | 目标分配完整、时间可行、各单元承担不同职责、前后连接有依据、复习与评价有位置，Narrative 能解释安排；不要求每个单元完整覆盖全年目标 | 数学任务和解法正确，表征意义一致，学习进程落实到学生工作，练习与证据支持目标，师生材料对应，支持不暗降目标；本次若只做关键课段则如实限定验收范围 |
| 延续工作所需内容 | 已形成的蓝图、目标分配、选择理由、时间估计、已查依据、真实决定、未决问题与下层回报 | 已形成的单元／课段设计、实际题目与图形、解法、草稿、生成材料、教师回应、检查及修订结果；不能只保留主题重新生成 |

全年标准的范围包括 [数系](https://www.thecorestandards.org/Math/Content/8/NS/)、[表达式与方程](https://www.thecorestandards.org/Math/Content/8/EE/)、[函数](https://www.thecorestandards.org/Math/Content/8/F/)、[几何](https://www.thecorestandards.org/Math/Content/8/G/) 和 [统计与概率](https://www.thecorestandards.org/Math/Content/8/SP/) 的实际要求。领域归属与标准顺序不是我们的单元划分；这组链接供后续准备独立标准资源，不表示已经形成可直接运行的完整资源包。

例如，线性函数单元若要使用斜率的某种解释，应核对其所需的数学依据及在自有课程中的承载位置；统计目标中的线性模型也可能构成后续联系。是否放在本单元、其他单元或只是作为未来用途，由设计及真实条件判断，不能由图邻接直接决定。这个例子用于说明查询需求，不规定实际教学顺序。

### 什么在开始时取得，什么按需读取

| 时点 | 整体课程方案设计 | 单元内课程设计 |
| --- | --- | --- |
| 开始设计前必须具备 | 本次任务、CCSS 的完整年级目标视图、相关质量要求、实际或明确标注的研究条件，以及知识查询入口；如为修订则有旧版和改动请求 | 本次单元任务、可定位的整体设计采用版本及相关交接内容、单元目标全文、继承的条件、适用教学与产物要求、知识和当前内容读取入口 |
| 随问题按需读取 | LC、有关进阶及具体前后年级标准、冲突处的详细定义或已有课程内容；补查要能说明解决什么判断 | 目标 LC、有关知识路径、邻接单元的实际说明或已有任务、相关学习作品、已经生成的课时和材料；需要核对正文时实际回取正文 |
| 执行中产生并延续 | 单元划分、顺序、时间分配、Narrative、目标分配和评价安排，以及支撑判断的实际任务探查 | 课段／课时结构、问题情境、实际题面、表征选择、解法、教师引导、学习检查、材料和修订 |

“开始前具备”指开始相应设计时取得，不代表每一项都必须放进第一条模型消息。可以先由 Harness 读取，也可以由模型使用已提供的工具取得；资料一旦足够就继续，避免为遵循预设阶段重复检索。全文较短的年级标准可直接装配，较大的资料先提供覆盖完整的索引并实际按需读取；不能以相关性检索只命中少数目标就声称已看全年。

**总体安排与具体任务是模型要生成的成果，不应被我们提前写成它的输入。** 调用方可以提供已有真实决定；没有决定的部分保留创作空间。每个模型行动无需读取整份历史，但必须取得本次判断依赖的现行内容、约束和依据。

### 整体设计怎样交给单元设计

交接以实际产物为基础，至少让单元设计者取得：

1. **当前采用哪份蓝图、哪一个单元。** 版本与适用范围明确；不只给“Unit 4，线性函数”。
2. **本单元承担什么。** 完整目标、在全年中的职责、开始前的条件、结束应达到的表现与后续用途。
3. **为什么这样安排。** 相关 Narrative、真实知识依据和课程自己的设计推断；未知或尚待试做的地方保留标记。
4. **什么必须保持、什么可自主设计。** 时间／资源／目标约束、已有真实决定；没有明确采用的课段顺序、课堂阶段、问题情境和具体任务由模型设计。
5. **哪些材料已经存在。** 有则传递精确内容或可读引用；只有蓝图的相关单元不伪装成已有完整教案。

单元返回实际内容、目标—任务—证据对应和具体检查发现。局部数学或表达问题在原范围内修复；若涉及年级目标分配、先备缺口或总时间，带着具体依据回报上层，并沿已有授权调整。允许先采用一份注明候选状态的蓝图开展任务试做，不新增“人类必须先批准每一层”的统一门槛；最终原创冻结是另一个时点。

### 已形成的候选产物与后续使用

1. [共同工作规范](../experiments/grade8-linear-functions/inputs/common.md)：固定 CCSS、学校研究条件、按需知识、实际数学工作、检查、真实参与和结束；不预设课程顺序或题目。
2. [整体课程方案任务书](../experiments/grade8-linear-functions/inputs/overall-task.md)：完整八年级蓝图及给目标单元的实际交接，线性函数以 8.F.B.4 定位关注范围，不强制排第四。
3. [单元内课程任务书](../experiments/grade8-linear-functions/inputs/unit-task.md)：接收真实上层版本，先形成单元骨架并展开连续三课；未生成上层产物前不编造交接，未完成全单元不宣称通过完整单元比较。
4. [评价与取用约定](../experiments/grade8-linear-functions/evaluation-and-adoption.md)：原流程及 39 条 rubric 的取用、实际检查办法、内容／运行／教师使用的证明范围；仅组织者与评阅者读取，不将其混合参考送入原创 Context。

本次运行已实际装配规则、完整标准与父产物，按需查询有限知识，并将生成后的具体问题作为新输入交回模型；独立读题运行没有教师答案。修订继承实际文件并保存新版本，仍要复查受影响内容，不能以模型自报“已修复”宣布完成。完整运行与 Agent Server 架构仍按既定路线在生产实现前补齐。

当前继续使用共同规范、当前任务和实际资源，检查与修订按其信息需要增加明确输入；没有先建设复杂配置层或把上述每行变成必填字段。开发文档不直接整篇送给原创模型；IM 隔离规则继续见 [实验方案](grade8-linear-functions-validation-design.md)。

### 首轮实测对修订 Context 的反馈（2026-09-15）

[实际修订和复查](../experiments/grade8-linear-functions/quality-review.md) 已表明，具体问题可以交回模型，由它核实、改文件并继续检查；同时出现模型虚报检查、检查器误报和视觉模型误读。后续接口应让检查绑定所读文件版本，区分实际证据、审阅推断和未确认问题，允许模型有依据地反驳。原始检查与后续裁定分别保存，不能用审阅者的语气强度决定是否改题。

本轮局部排版修订仍装配全年 71 个 CCSS 来源条目和全部父文件，造成重复输入；这是原型的已知不足。后续进行消耗优化实验时，应围绕真实修改范围提供问题、受影响文件、相关目标与学校约束，并保留回取上下层实际内容的能力。不能为了减少 token 丢失导致该问题的依赖，也不能只对较小 Context 的一次成功就宣称已证明普遍无损。当前优先收敛主执行中的信息责任与交接方式；局部消耗优化不抢占主线。

12／24 次调用均为实验上限，没有校准为生产预算。设计方向是让模型在授权内持续推进和修正，用资源消耗、实际产物进展及重复未解决问题判断是否需要停止或新运行；达到资源上限时保留成果、未决项及原状态。资源停止与教学质量不通过分别表达。按用户明确的 [质量与消耗推进顺序](validation-and-release-route.md#质量与消耗的推进顺序)，预算优化后置；当前先保证充分 Context 和质量，随正常任务积累不同复杂度的消耗。最小停止与完整恢复仍须验证，精细预算策略和停滞判断不作为前置专项，不因此新增一套按错误类型分支的状态机。

## 课程到课时的阶段输入与模型工作

以下针对新增数学课程能力展开候选装配方法，承接 [课程与课时的双向交接](curriculum-design-capability.md#课程与课时的双向交接)。这是执行结构票的设计输入，尚未选定运行状态模型。它不替代四项 Skills 各自完整规范，也不要求所有能力经过相同阶段。

| 当前工作 | 本阶段实际需要的 Context | LLM 与工具需要完成的工作 | 供后续回取的结果 |
| --- | --- | --- | --- |
| 理解本次设计任务 | 请求范围、年级／框架、已给目标、学校约束、相关学习者证据、现有课程及真实决定 | 区分已给事实、允许默认与关键未知；识别本次交付范围，必要时形成具体输入请求 | 本次采用的约束和版本、缺失条件、授权范围；未知学习状况不填成事实 |
| 建立目标与进程依据 | 目标原文、实际 LC、本地图路径与方向、适用课程背景；读取有关关系语义 | 查询并选择与任务相关的依据，解释为什么选用；将课程先后安排与图事实分开 | 带来源的依据、选择理由、进入条件假设、目标分配及未解决冲突 |
| 形成学习进程并试做关键任务 | 各层目标和 Narrative、分配到本课的职责、相邻课的实际依赖、已定表征与资源限制 | 比较有实质差别的安排；创作、实际求解关键任务，检查它是否能支持预期理解及证据；必要时回修上层 | 实际题面、解法／图示、目标—任务—证据关系、可行性发现、简明设计依据 |
| 展开课时与可用材料 | 当前项目适用的课时规范及完整相关参考、上层交接内容、已审阅草稿、实际任务和产物要求 | 沿数学教案流程完成教学设计、求解、教师引导和同源材料；实际调用所需工具并核查结果 | 同版课时内容、教师／学生材料、资源清单、检查对象和结果；不能只留下“已生成” |
| 检查单元并提出修订 | 完整目标分配、各课实际内容及证据、跨课依赖、学校约束、相应版本的检查与审阅 | 检查上层承诺在实际任务中的兑现；提出带反例的问题，判断局部修复或返回上层 | 受影响目标／任务／材料／决定、修改建议、可复用内容和必须重查内容 |
| 执行已明确的修改并交付 | 具体修改、适用授权、当前版本、影响范围、原内容及需重查的规则 | 修改相应内容；核对引用和叙述是否同步；重新执行受影响检查，必要时请求范围取舍 | 版本差异、来源延续、实际产物、检查与真实人类决定、尚未达到的交付条件 |

课程层可能只生成一个单元；此时年级 Context 包含该单元的已知位置、进入条件与后续需要，不能自动宣称已有完整年级设计。邻课摘要可帮助定位，但凡判断依赖、理解跨度或覆盖，必须能回取相关实际任务；课时正文不能在传递中被压缩成只剩标题。

### 把参考变成实际可装配的运行资源

后续规格需要为每种阶段明确以下内容，并通过实际调用检查其落实：

- **规则选择有依据。** 定位本项目已经采用的能力规则、学科规则和对应版本，保留完整上游参考供核查；尚未采用或已调整的上游条款标明地位。不能因为某文件在仓库里，或提示词说“遵循 Skills”，就当作模型已经读取。
- **输入能够复核。** 每次模型／工具工作记录实际装配的规则和内容版本、来源位置及用途。Narrative 等定位摘要不能代替作出当前判断所需的实际题面、图形和材料；容量不足时分段读取，不静默截掉必需信息。
- **已知内容接续执行。** 下一次调用取得当前实际设计和未决问题；不从主题重新生成。模型提议的新目标、图关系和审阅状态必须与来源事实、既定目标和真实人类决定分别保存。
- **数据更新有明确入口。** 外部 Learner Model、课程基线或知识快照更新后，判断本次任务是否采用、影响什么；记录采用的版本。运行中不能混用新旧数据后仍引用旧检查；个体调整保持适用对象与课程基线的区别。
- **实际工作与状态分开证明。** 模型给出内容和可检查的解释；工具返回证明执行过什么；后端核对版本、所需产物和真实事件，再决定能否继续。模型写一句“教师已确认”不能解除等待，模型自报“答案正确”也不能代替相应检查。

这些要求限定的是运行行为，不预设单模型、多模型或多 Agent 方案。先在各能力允许的行动范围内保留模型设计、查询和纠错的空间；只有必须由真实事件、工具结果或交付关系保证的边界交给程序控制。哪些教学判断需要独立检查、多少次迭代足够及何时停止，由执行和质量票通过具体任务验证。

### 同一内容对不同工作有不同可见范围

数学图形可进一步采用 [用途说明到精细产物的候选方法](math-visual-materials-design.md)：课程／课时提出教学用途和形式建议，关键图在试做阶段尽早生成，后续用原数学描述、实际图及具体反馈局部修订。精确图形的绘制与检查可单列模块，但不能丢失任务目的、师生可见信息和上层约束；这项划分尚待有限试验，不是已确定的生产接口。

| 工作 | 可见范围与必须保留的差别 |
| --- | --- |
| 原创课程设计 | 标准、LC、进阶及采用的通用设计原则；对应 IM 单元树和具体任务不作为自动生成模板。工具返回混合来源时按本次用途选择，并保留真实来源记录 |
| 固定版本后的 IM 比较 | 同时读取固定原创版本和可比参考内容；记录参考何时进入及改动理由，不能把已见参考的产出称为未接触参考的独立比较 |
| 课时生成和数学验算 | 可见本课目标、实际任务、已确认设计与解法；是否另起检查调用由任务决定，不把“多调用一次”当成独立证据 |
| 教师亲做与备课讨论 | 模型可先内部试做；教师正常路径先看到原任务，作答后再揭示对应分析。教师拒答、要求先示范或停止的源码例外须分别处理；不能编造教师贡献 |
| CFU 隔离读题 | 读取实际学生材料；不得携带教师答案、错误映射、可泄题的内部标签或此前生成对话。另一个调用若仍带着答案，不能称为隔离读题 |
| CFU 回应解释验证 | 读取实际题目、答案、错误映射和相关前后联系，核对某种错误是否真的产生指定回应及下一步是否合理；模拟回应不是已采集的学习证据 |

独立调用只能提供一种检查条件，不能消除同一模型可能共有的偏差。数学工具、模型检查和人类审阅需要分别报告证据范围；使用同一模型或不同模型是否更有效，仍须比较。

### 方法论研究补充的 Context 条件

[IM 方法论核查](im-design-methodology-transfer.md) 给出更细的教学依据：表征含义和使用史、临时支架与持续支持、讨论预案与实际作品、跨课练习机会，以及不同互动协议各自的信息与材料寿命。后续装配与状态设计应检查：

- 需要先前表征或学习机会时，能取到其实际内容及相应课时；只给前课标题不足以判断学习跨度。
- 调整支架时，知道支持来源、用途、适用对象和条件；不能按题序自动取消外部指定的持续支持。
- 教师预判的学生方法、模型模拟回应、真实学生作品与教师判断分别保存；预案获批不生成课堂事实。
- 采用需要私有信息、反复修订或跨课集体材料的互动方式时，分别记录可见信息、揭示条件、作品来源及延续范围；不把整个班级作品写成某个学生的掌握证据。

Harness 首先设计和交付相应教学内容及条件；外部产品未提供真实课堂或同伴事件时，不假装执行过它们。上述条件用于保留教学语义，不在此确定通用协议库或扩建课堂平台。

## 采用与验证原则

当前没有找到并验证更优的完整替代方案，因此按上游流程开展设计。每个重要改变记录：原步骤及目的、当前产品条件、候选改法、需要证明未退步或改善的行为。理由合理只支持提出候选，不等于替代效果已验证。

课程体系的新增能力另建跨层评价；四项既有能力则建立条件可比的上游执行基线，分别检查实际教学内容、交互、产物与修订。不能通过删除失败指标或只测最终文字，宣称达到或超过原 Skills。IM 内容对照与 Skills 执行能力对照分别记录。
