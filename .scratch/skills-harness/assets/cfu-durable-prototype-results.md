# CFU 持久执行：真实回应、故障恢复与服务接口实测

日期：2026-09-15。关联 [持久运行原型](../issues/09-cfu-runtime-prototype.md)、[主执行方案](main-execution-design.md)及[运行架构研究](../issues/11-agent-server-stack-research.md)。

**结论：在本次锁定版本和有限故障窗口中，已验证“保存具体请求—真实回应—跨进程恢复—实际产物检查”的控制机制。** 教学内容由固定模型返回，程序检查只验证材料完整性、版本及资源读取顺序；没有因此证明 CFU 教学质量或其他能力的人类交互已实现。

## 用什么回答了哪个问题

使用 [一次性探针](../prototypes/cfu-durable/README.md)，独立 SQLite checkpointer、业务事件库和实际文件。LangGraph `1.2.11`、SQLite checkpointer `3.1.1`、LangChain `1.4.0`／core `1.6.3`；Agent Server 开发版 `0.14.1`／inmem runtime `0.34.1`／SDK `0.4.4`；LangSmith SDK `0.12.4`。完整依赖见 [锁定清单](../prototypes/cfu-durable/requirements.prototype.lock)。

探针按 CFU 自身需要保存焦点、等待、构建、写出、检查和交接；构建节点复用 `create_agent`，固定模型实际调用算术工具并读取工具返回。没有调用 Gemini 或其他外部模型。标准从 [已冻结的 CCSS 8.F.B.4 原文](../prototypes/cfu-durable/standard-source.json)取得，没有新增课程／IM 检索；两个固定焦点和题面是运行样本，不是已执行完整 CFU Skill 或已研究确认的错误模式。

这次问题是持久化，故直接运行独立数据库和进程探针；没有再建一个只能模拟恢复的浏览器状态机。每个 CLI 操作输出当前完整相关状态，原始记录可回看。

## 一条真实回应怎样经过故障恢复

先保存 `human_review:focus:1` 的具体内容：“根据两组对应值求变化率、解释单位，并区分 Δy/Δx 与 y/x”，附理由、另一可选焦点及快照身份。启动进程退出，图停在 `await_focus`。

用户实际回答 **“采用上述变化率焦点”**。记录原文、原问题、交互事件身份和所指快照后，故意使进程以退出码 86 终止，图尚未收到恢复命令。新进程从业务记录取得这条已保存决定，再调用 LangGraph 的恢复入口；随后生成、保存并核对两份固定材料。第三个进程再次提交同一事件，返回 duplicate，未增加生成或写入。

| 实际观察 | 结果 |
| --- | --- |
| 采纳的人类事件 | 1 次；原文与展示快照保留 |
| 提议生成／进入等待节点 | 提议 1 次；等待节点 2 次，符合恢复从节点入口重跑 |
| 构建与模型／工具 | 构建 1 次；固定模型调用 2 次，算术工具 1 次 |
| 文件与候选交接 | 实际创建 2 份文件，候选提交 1 次 |
| 重送同一回应 | 所有上述计数保持不变 |

证据：[原始请求](../prototypes/cfu-durable/real-request.json)、[真实回应](../prototypes/cfu-durable/real-reply.json)、[退出后状态与两次恢复操作](../prototypes/cfu-durable/runs/real-review/real-recovery.json)。实际交互经 Codex 问答工具与开发桥接进入，本轮参与者是原型评阅人；不是生产 Web 身份认证、合作教师课堂试用或任意自然语言理解评测。所选选项明确映射为 `rate`，没有让模型猜测授权。

## 固定事件的故障探针

[最终运行记录](../prototypes/cfu-durable/runs/20260915T032753757782Z-faults/results.json) 保存每条命令、进程、返回值、状态及判据。13 项均通过；此前一轮同样通过，随后添加工作路径限制并复跑，不能当作 26 个独立场景或统计成功率。

| 验证内容 | 有证据支持的结果 |
| --- | --- |
| 等待后换进程、无回应就恢复、明确改焦点 | 同一提议可回读；无有效事件拒绝继续；改成初始值后直接构建相应材料，不重复确认 |
| 相同事件重送、同身份携带不同内容、两个进程同时重送 | 返回已有结果或明确冲突；CLI 采用任务级文件锁，两个进程只构建一次。不是 Server 多任务／多租户并发证明 |
| 回应保存后立刻硬退出 | 原决定仍在，恢复同一动作，未要求重答 |
| 第一份／第二份文件写出后、图记录未提交时硬退出 | 完成清单仍缺时，验证资源保持不可读；恢复核对并复用实际文件，固定模型不重调，两份文件合计各创建一次 |
| 已检查文件丢失或被改写 | 在读取完整验证资源前即拒绝；交接也被阻止。恢复相同字节后可使用仍对应的原检查 |
| 更新文件及清单但沿用旧检查 | 交接拒绝，不能只因路径存在就使用旧通过记录 |
| 新提议替代旧提议、取消后尝试提交旧结果 | 旧版回答不被采纳；取消后的候选不成为交付，重新恢复亦被拒绝 |
| 已有本次有效焦点、未知行为版本 | 前者保留事件来源并跳过中断；后者明确拒绝。后者仅为版本校验，非破坏性部署迁移验证 |

故障为实际 `os._exit(86)`，绕过正常异常清理；SQLite 使用同步 checkpoint。没有模拟数据库已经成功写入，也没有靠内存保留 Python 栈。但这不是机器断电、磁盘损坏或远程对象存储故障验证。副作用计数来自受控写入位置的记录，不推导任意外部 API 恰好执行一次。

## Agent Server 与 LangSmith 分别测到了哪一层

**Agent Server：实际开发服务的 API。** 在 `127.0.0.1:62915` 启动 `langgraph dev`，经 SDK 创建 assistant／thread，调用流式 run 到达焦点等待；正常终止服务后，在相同目录启动新进程，原 thread 与提议仍可取得。以固定事件明确改向初始值，调用 `command.resume` 后取得完成候选及两份材料。记录保存了两次 SSE、前后状态与源代码指纹；重启之间仅增加输入路径限制，保持节点、state 和中断顺序兼容。[服务实测](../prototypes/cfu-durable/server-probe.json)、[当次 OpenAPI](../prototypes/cfu-durable/agent-server-openapi.json)

这支持通过现成服务承载调用与等待。它是 **dev 的本地持久化、正常服务退出及一次兼容改动**；没有测试 PostgreSQL／Redis 生产拓扑、worker 硬崩溃恢复、破坏性升级或跨学校权限。服务检查信息显示 `langsmith=false`，未连接 LangSmith 云服务。

**LangSmith：实际 SDK 的本地发送与失败行为。** `LangChainTracer` 配置真实 LangSmith Client，但目标是本机一次性 HTTP 记录器，不是 LangSmith 后端。生成 14 个相关 runs，包含 chain／llm／tool，按任务、thread 和请求快照关联；应用结果另保存实际两份材料指纹。隐藏 inputs／outputs，并对白名单 metadata 之外内容过滤后，发送负载中没有预置私密标记。记录器改为 503，SDK 确实报错，业务产物和完成记录仍保存。两种条件合计 56 次 POST／PATCH。[SDK 发送证据](../prototypes/cfu-durable/runs/20260915T032913870963Z-trace/sdk-transport.json)

这是 SDK 集成、选定字段处理与失败解耦的证据；不证明 LangSmith 云端存储、界面、数据集／评测、保留策略或全面脱敏。首次记录把请求指纹标作 `artifact_version`，已改为 `request_snapshot` 并重跑；产物指纹与请求指纹保持不同语义，旧记录保留。

## 对实现方案的影响

1. **等待前保存实际对象，恢复使用保存的决定。** 请求必须有稳定身份和快照；业务回应先可靠记录。恢复调度不确定时可重试同一动作，不能重解读成另一选择或要求教师重答。
2. **分开保存有价值的模型结果与外部写入。** 已完成构建后写文件失败，应补齐／核对产物。对产生外部效果但尚未记录完成的窗口，仍需稳定操作身份和结果核对，不能只依赖 checkpoint。
3. **检查关联实际字节和规则版本。** 材料清单齐备后开放 CFU 自有验证资源；交接前重新核对所用检查对应内容。读取顺序已验证，真正的两道教学检查仍须实现及评价。
4. **共用运行服务，不统一教学目的。** `create_agent` 可复用为工作段内的模型／工具循环；`interrupt` 可承载焦点与回应。其他能力何时等、回应代表什么，继续由各自流程决定。
5. **观察记录帮助定位，业务记录承担恢复。** SDK 不可用不应让已保存的决定或产物消失；请求、产物和检查各自保留版本，再关联 traces。生产发送与保留范围仍按外部政策配置。

本次已回答这张运行原型票的有限控制问题，停止扩展探针。接下来将这些事实交给 [调用接口](../issues/02-execution-interface.md)收敛操作结果、版本条件及恢复职责；生产部署与各能力质量按对应验证继续推进。无需再增加一轮函数图精修或把所有故障场景变成教师选项。
