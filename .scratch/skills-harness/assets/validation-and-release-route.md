# 从架构可行到教学交付的验证路线

日期：2026-09-15。采用范围见 [质量和可靠性验证](../issues/05-capability-validation.md)。本文将既有输入、评测约定和实际失败转成交付门槛；不修改原实验评分，不表示材料已通过。项目目标和参考路线仍以 [README](../../../README.md) 为准。

## 当前可以下什么结论

现有证据支持继续采用充分 Context 下的模型／工具循环，并以持久状态、真实事件、版本化材料和检查修订承载教学工作。尚未发现必须推翻该架构的反证；也没有完成它与 Skills 的效果对照。技术上值得实现、内容在当前样本中有所改善、已经达到教学质量要求，是三个不同判断。

| 问题 | 当前实际证据 | 尚不能推出的结论 |
| --- | --- | --- |
| 能否从全年方案交接到实际课时并修订 | Gemini 生成全年蓝图、连续三课并按问题两轮修订 | 整个单元和整年实际材料都合格 |
| 是否能发现并修复缺陷 | 解析错误有实际减少，图形与文本部分改善；也有漏检、视觉误报和错误自报 | 单一模型 judge 足以判断内容，或所有失败已解决 |
| 跨层修订是否可靠 | 18→14 的布局与时间同步有记录 | 尚未展开的后半单元能在压缩时间内教完；无证据的掌握度保证成立 |
| 真实参与能否持久恢复 | 一次真实原型焦点选择、13 项固定事件控制、dev 重启 | 五项能力的真实自然语言交互、生产服务和教师使用均通过 |
| 是否已接入观察平台 | LangSmith SDK 本地发送与 503 解耦；用户已提供 Key 配置 | 云端／自托管服务、数据集和平台评测已验证 |

具体来源：[质量裁定](../experiments/grade8-linear-functions/quality-review.md)、[运行记录](../experiments/grade8-linear-functions/runtime-notes.md)、[持久探针](cfu-durable-prototype-results.md)。旧稿、失败和源码快照继续保留。

## 首个贯通对象与结束条件

数学首阶段采用用户提出的八年级线性函数方向：先形成包含全年 CCSS 内容及实践目标的蓝图，再落实其中相关单元的课段、全部课时、师生材料和评测。单元位置、课段、课时数由自有设计及约束决定；“Unit 4”不成为复制 IM 的结构要求。已有研究中的 180×50 分钟、班级条件及 18／14 课时都保留研究身份，实施时固定当次任务条件，不当作学校实情或生产默认。

连续三课是首个实现连通切片，**完整单元才是本轮课程能力的交付验证对象**。完整单元原稿冻结前不读取对应 IM；不能先比较三课，再带着参考答案补完所谓原创全单元。

| 交接点 | 必须取得的证据 | 通过后允许做什么 |
| --- | --- | --- |
| 规格交接 | 能力／Context／接口／工具／HITL／服务责任明确，既有原型边界和失败已记录 | 开始实施；不发布教学质量声明 |
| 首个运行切片 | 真实模型和原生循环连通、实际课程版本交接、一个确有目的的真实待答／恢复、实际材料及检查反馈，异常能保留结果 | 扩展覆盖完整单元；不把三课算作全单元 |
| 完整单元候选 | 全部请求内容和所需载体实际齐备；目标—任务—证据可逐项回查；数学、学校条件、跨层与受众检查完成 | 冻结原创候选并进入对照、专家校准；未解决阻断项仍阻止“可教学”声明 |
| 四项能力交付 | 各自有完整运行资源、实际产出、正常参与与必要例外的验证；达到下述比较门槛 | 仅对验证过的能力、条件和模型声明能力范围 |
| 产品接入／试用 | 持久运行、访问隔离、取消／重送、版本与追溯成立；教师能在目标使用条件下完成实际工作 | 由外部系统决定受控试用／发布；课堂学习效果另行取证 |

不要求 wayfinder 先把这些产品门槛全部实现。当前规划的问题是决定怎样做和怎样判断，所需的小型运行证据已取得；继续完整生成、修复和平台部署归入实现及验证阶段，不能无限扩张为规划原型。

## 评价对象与方法

复用生成前的 [E1–E10 与 39 条教案 rubric 取用](../experiments/grade8-linear-functions/evaluation-and-adoption.md)；这些条款已有完整映射，未经过教师校准。其他能力从自己的原 rubric 形成取用清单，不能把 creation 的 39 条当全部 Skills 评分。课程能力补充目标分配、进程及跨层检查，不另造一份取代已有研究的通用教学总分。

| 评价面 | 检查什么 | 使用证据 |
| --- | --- | --- |
| 内容与学习机会 | 全年／单元完整范围、每课实际职责、数学正确、表征、学生推理、练习和评测对应 | 逐题实际内容与解法、来源、目标映射；计算和独立读题互相校核 |
| 材料可用 | 真实图件、语言和作答空间、师生一致性、所需资源、时间和准备负担 | 实际渲染和文件；内容估算与教师使用观察分别记录 |
| 修订 | 问题消除、未引入新缺陷、上层／后续内容同步、个人支持不改公共基线 | 新旧材料差异、受影响范围与重查；模型修订自述不独立计证 |
| HITL | 正确等待、有内容的展示、有效原始回应、已有决定复用、条件／否定／改意和退出 | 真实请求／回执／采纳／执行记录；固定事件只评控制 |
| 运行 | 保存、重送、调度、故障、预算、取消、版本兼容与访问范围 | API 和实际持久数据、故障注入及副作用观察，trace 作为补充 |

数学实质错误、关键学习机会缺失、必要材料不可用、伪造人类／来源或受众泄题，各按受影响范围阻止对应交付。正确的排版、文风或总分不能抵消。没有做检查记未评估，条件不适用需理由；缺失整课不能解释为不适用。

模型检查发生分歧时保存具体对象和反例，允许生成模型核实并反驳误报；由相应计算、原文或人工评阅裁定。不能把一次视觉模型误读作为修改正确数学内容的命令。修复在授权及明确资源限制内继续，有进展的修订不以节省调用为由提前截断；停止时保留未解决问题，不放松标准过关。

## 质量与消耗的推进顺序

按用户于 2026-09-15 明确的优先级及 [README 原则](../../../README.md#设计与协作原则)，**先做出高质量结果，随任务摸清消耗，再逐步优化预算。** 这适用于后续规格、实现与验证，不增加一轮 Wayfinder 成本实验。

1. **先完成质量工作。** 为实际设计、查证、材料、检查和修订提供充分资源，按本能力的完成条件判断结果。当前不设置降低 token、调用数或费用的验收目标；Context 压缩、廉价模型替换、缓存和自动预算分配不作为首版前置机制。
2. **在正常任务中积累消耗基线。** 记录能力、实际范围、影响复杂度的条件、模型与配置、质量结果及可取得的输入／输出 token、调用与重试、工具使用、修订轮次和耗时。模型／工具活动时间与人类等待分开，任务跨恢复累计。费用按可核实的使用量和计价依据计算，缺失值记未知。保留失败、触限及未完成任务，不能只统计成功样本。先区分单课、完整单元、跨层修订等实际工作，不预建复杂度评分器，也不强行合并不同能力。
3. **样本足够支撑判断后逐项优化。** 找出实际高消耗环节，每次检验一项改动，比较同类任务的质量、可靠性和资源消耗。达到质量条件的总消耗包含检查、修复和恢复；少生成内容或少做检查不能记作同等质量下的节省。保留原配置和结果，质量退步时撤回改动。

当前仍实现最小运行保障：可配置的防失控上限、明确资源限制、取消、停止原因、成果保存及续作。上限根据当次任务范围配置，尚未校准时明确其探索性质；不把 12／24 次沿用为生产常量，不把资源用完判为教学能力不足。更精细的预算预测和停滞判断随实测改进。

为隔离某项机制效果而开展的正式对照，应事先说明并控制资源条件；若触限，分别报告截断和质量结果。相同预算的对照条件只约束该实验，不成为所有质量探索任务的统一额度。

## Skills 与 IM 分别怎样比较

**Skills 比较的是教学执行能力。** 固定上游版本、实际输入、所用资源、模型和工具条件，逐项比较保留教学目的的结果和交互。原始规则成绩与本项目采用规则成绩分别报告；不能删掉上游失败条款后宣称超过它。完整原 Skill 所需资料若没有提供，该基线明确记为未复现，不能偷偷给弱化基线。

为判断 Harness 改动的效果，优先在相同模型及可比资料／工具下执行固定规则参考和本项目流程；宿主适配改动有清单。若另用原宿主／原推荐模型运行，作为整体体验对照，不把模型、工具、资料差异都归因为 Harness。新增课程体系没有同名 Skill 基线，以本项目课程判据评价。

**IM 比较的是冻结后的课程内容。** 原创 A 的全年相关蓝图、完整单元及资源输入记录先冻结，再选目标、先备、时间、资源和评测范围可比的参考 R。保持标准文字、真实题目和必要上下文，移除仅揭示作者身份的包装，以随机顺序交给不知道标签映射的评阅者；映射由组织者保管。结构可能泄露来源，模型预训练亦不可排除，因此如实称输入隔离和匿名评阅，不承诺严格双盲。

评阅者先完成独立判断再汇总讨论；不能让后来的评阅者提前看见别人评论。用同一评价依据比较 A／R，形成有理由的改进 B，保留三者身份及未采纳建议。若范围不同，逐项说明可比与不可比部分，不把更像 IM 当作更好。

“达到并争取超过 Skills”需要经数学教育评阅者校准的评价，以及覆盖相关任务条件的多次运行；当前无此证据，保持未证明。首个完整单元是针对该范围的交付审查，不是统计上的普遍优越性证明。需要广泛比较结论时，在看到最终比较结果前，依据试运行方差和希望识别的差异固定样本、重复次数及非劣界限；不现在随意拍定次数或用看完成绩后的门槛解释通过。

## 各能力最不能遗漏的判别

| 能力 | 必须同时包含的情况 |
| --- | --- |
| 课程体系 | 全年完整视图→单元实际内容；跨层课时改变与一个不应牵动基线的局部支持改变；代表任务通过与全单元未完分别处理 |
| 课时创建 | 直接完整包；先看草稿后仅修改／修改后直接生成；真实内容延续和最终材料检查 |
| 适配 | 原课和目标保持；相关个体证据引起具体支持变化；局部与整套接受；明确只生成供后审与正常协作分开 |
| 教师备课 | 真实原任务、教师自己产生 near-miss、贡献进入便签；先问概念、先示范、拒答、短时、结束和取消按各自条件处理 |
| CFU | 已有有效焦点与尚未选择；明确改向；实际材料后的两道验证；错答解释与答对但推理有缺口的情况 |

这些用于设计取样和反例，不变成教师菜单或每项一个专用生产节点。自然语言样本保留否定、附带条件、简短回答和新意图，增加未用于调整提示的改写；不只测试固定选项映射，也不要求现阶段按所有场景各写一个测试函数。

## LangSmith 与运行验证

LangSmith 关联真实模型／工具、Context 清单、检查、修订和消耗；固定数据集保存有来源的案例及裁定，用于比较执行器改动。生成中的即时检查仍通过 Harness 返回模型修复。专家标注是评价输入，不自动成为教师决定或发布动作；online 空闲触发也不是完成条件。

已提供 Key，后续接入用独立合成样本验证真实服务连通、关联和读取，再按实际数据范围配置发送；不批量上传历史真实回应和材料来证明可用。固定案例先采用已有有效修复、未解决项和 judge 误报，参考标签不进入生成 Context。平台本身不能证明评价可靠。

生产服务验收沿已有三个故障窗口，补齐当前没测的原文保存到语义采纳、采纳到 Server 自动调度、worker 硬退出、数据库与产物分离、同课程多任务提交、等待跨版本、流断连和权限撤销。冻结部署版本后核对许可、PostgreSQL／Redis、备份恢复、健康检查、并发及活动时间／等待时间。容量数字由目标工作量和负载实测决定，不能从 dev 的一次成功编造 SLA。

上述验证分别进入实现票并明确负责人及通过证据；失败足以否定 Context、控制粒度或提交机制时回到相应架构决定调整。数学图形精修、多模型效果比较和大范围优化按实际依赖安排，不因被提及就抢占当前交付链。
