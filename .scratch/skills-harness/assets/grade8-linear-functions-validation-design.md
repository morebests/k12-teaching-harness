# 八年级线性函数：独立课程设计与后置比较的讨论方案

日期：2026-09-15。本文保留根据用户建议展开的实验方案；后续已进行全年蓝图、三课生成及反馈修订，实际条件与结果见 [实测入口](../experiments/grade8-linear-functions/README.md)。完整单元和冻结后 IM 对照尚未完成。所属问题：[如何验证独立课程与教学设计的质量和可靠性](../issues/05-capability-validation.md)。项目长期目标与原则仍以 [README](../../../README.md) 为准。

## 要回答的问题

在不向原创执行环境提供 IM 课程结构、内容或派生设计资料的条件下，Harness 能否使用独立标准、适用的本地知识和模型能力，形成有教学依据的年级课程蓝图，将其中的线性函数单元落实为可教学材料，并在真实内容发生变化时保持两层一致？完成后与 IM 可比内容比较，找出实际差距。

这是教学能力与执行机制的验证，不是让当前规划会话直接写一套课程再以此证明未来 Harness 有效。必须运行实际候选模型循环，保存输入、产物、工具结果、人类输入与修订；人工代写和人工修补分别记录。

用户的“Unit 4”暂为目标标记，未核对任何 IM 版次的单元编号。不向原创模型发送“模仿／对标 IM Unit 4”的任务；若指自有课程第四单元，应由自有年级设计说明位置与前三单元提供的条件。不能凭编号认定两个单元可比。

## 两层设计与各自完成条件

| 层次 | 建议范围 | 必须得到的实际结果 |
| --- | --- | --- |
| 整体课程方案 | 八年级全年蓝图，并说明有关的前后年级衔接；本轮不展开其他单元的全部材料 | 独立目标分配、各单元职责与预计时间、知识与理解如何发展、线性函数单元的进入条件与后续用途、总体评价安排及 Narrative |
| 单元内课程 | 线性函数完整单元，而非几节示范课 | 单元目标与结束证据、Section／Lesson 的职责、实际题面与图形、解法、教师引导、学生材料、练习与检查、支持安排和设计理由 |

全年蓝图要从采用的年级标准形成完整覆盖视图，不能仅围绕线性函数编几个前后单元就称为全年体系。它的详细教学可行性尚未全部验证。每个目标须有承担位置，线性函数的先备不能只写“之前学过”。真实学习情况未知时，进入条件及诊断预期标为研究假设。

两层往返修订：课时创作及试做若暴露前提不足、理解跨度过大、任务不支撑目标或时间冲突，允许修改课段、单元及相关年级安排。先设计代表性的关键任务有助于尽早发现问题，但完整单元交付仍需补齐其余课时及材料。

数学范围先按独立官方标准核查，证据见 [独立标准核查](grade8-linear-functions-standards.md)。核心、先备及邻接内容分别声明；线性函数、解线性方程和方程组不能只因词语相近就合并。标准不是课程顺序，当前文件也不提供具体的自有教学顺序。

两类任务分别加载的知识、条件、教学要求及上层交接，统一展开在 [整体课程方案与单元内课程设计的输入](context-and-llm-design.md#整体课程方案与单元内课程设计的输入)。用户要求先讨论清楚这些内容，再实际调用模型；API 凭证就绪不代表输入准备完成。

## 从任务到候选运行方案

1. **固定实验任务。** 标准框架沿 README 固定为 CCSS Mathematics，记录数据版本；声明核心目标、已有学习条件、学校时间与资源、产物范围、模型及预算。没有目标学校，条件用清楚标注的研究设定；不从 IM 的课数、活动或顺序倒推输入。
2. **准备隔离的设计资源。** 只交付允许读取的标准、来源可核对的知识、适用的非 IM 教学执行要求、研究设定和真实决定。把资料版本与选择依据留在清单里；当前仓库的整套研究资料不能直接作为原创模型 Context。
3. **让模型设计并落实。** 从一个简洁模型／工具循环起步，按需查询、提出安排、创作任务、求解与检查、生成材料并修订。可以先检验关键课段，再完成全单元。不把本节工作步骤规定为固定节点，不强制逐步审批。
4. **检查上下层一致。** 核对实际任务是否兑现目标与 Narrative、证据能否区分目标理解、练习是否提供学习机会、材料与解法是否一致。独立读题和计算检查须取得实际结果；模型自报合格不算外部验证。
5. **做一次跨层修订与一次个体支持变化。** 前者例如减少教学时间但保持目标，由模型尝试合理修复，必要时提出真实取舍；不预置“先删某课再等待”。后者用注明模拟来源的学习证据，检查支持是否实际改变且不误改公共课程。二者分别验证不同责任，不扩展成大量场景分支。
6. **固定原创版本。** 保存修订前后、采用约束、实际全部材料、检查、资源清单、运行记录和内容指纹。选择预先约定的版本作为主要比较对象，禁止看完 IM 后回写原创基线。

教师交互只围绕会改变设计的缺项、授权外取舍和能力自身的实质参与。已有条件直接使用。教师备课的真实贡献与模拟回应分开，缺少真实教师时先报告机制可行性，不能写成教师试用通过。学习者输入仅为消费测试，不建设 Learner Model，不以模型模拟证明学生学会。

完整单元用于内容比较；wayfinder 的小型原型可先检查其中影响架构选择的关键工作。若本轮只完成关键课段，结论必须限于该范围，完整单元比较仍是未完成工作，不能以局部成功替代。

### 小型实测与项目实现的分界（2026-09-15）

用户追问完整实测是否已接近项目开发完成。建议 wayfinder 下一轮先验证“实际 Context／知识工具 → 课程结构候选 → 连贯关键课段的真实任务与材料 → 检查及一次跨层修订”的最小执行链，并验证其中必要的人类等待。它会产生真实候选代码，但只用于回答模型、Context 和控制机制是否可行；不同时实现五项能力全部路径、整个服务架构或广泛教学质量验证。

全年蓝图、线性函数完整单元和后置 IM 比较仍是贯通目标。先解开会影响架构的未知；路线清楚后进入规格与实现，逐步补齐完整单元及能力。原创单元未完成并冻结前，继续不读对应 IM 内容。若将五项能力、完整单元生成与修订、可靠恢复及后端接入都实现并验证，就已属于 MVP 开发，不能继续笼统称为 wayfinder 小型原型；代码是否继承由实现评审判断。

首轮模型按用户偏好使用 Gemini `gemini-3.8-flash`；官方事实、实际 LangChain 接入及运行边界见 [质量验证票](../issues/05-capability-validation.md)。不预建多模型调度，以实际数学内容、工具往返、Context 延续和修订表现判断是否够用。

## 原创隔离：能保证什么，不能保证什么

本次更准确的名称是“参考隔离的独立设计与匿名评阅”。设计者不知道参考材料，与评阅者不知道材料身份，是两个不同要求。IM 原作者无法参与对称盲法，LLM 预训练中的 IM 暴露也无法保证不存在，不宣称严格双盲或知识零暴露。

原创工作由本项目 Harness 的实际运行承担，其任务 Context 与状态由 Harness 装配和维护，本来就不应自动继承当前开发会话或整个研究仓库。开发者读过 IM 不等于产品模型已收到这些资料；无需为此另外建设一套“隔离 Harness”或把换一个开发 Agent 当成实验步骤。同一原创任务内部仍正常延续草稿、工具结果和修订状态，不因参考隔离而每次清空 Context。

本实验在已有运行边界上明确资源配置：原创运行的提示、教学规则、检索结果和可回取材料不引入 IM 课程设计信息；冻结后比较运行才取得参考。运行独立并不会自动筛除数据源中的 IM 内容，因此仍需核查实际装配与查询结果。当前开发会话负责规划和实现，不直接代写原创课程或冒充盲评员。预训练暴露只作为比较结论的限制记录，不作为阻碍实验或新增基础设施的前置问题。

本文件供实验组织者讨论方法和边界，不直接作为原创运行的提示包。组织者不先写好课段顺序、题目或教学路径再交给隔离模型；独立任务与评分规则的要求须能从目标、实际条件或一般执行责任说明依据，不能含从 IM 抽出的设计答案。

| 角色 | 可以取得什么 | 信息边界 |
| --- | --- | --- |
| 原创执行环境 | 独立任务、批准的资源、模型一般数学知识和实际工作结果 | 工具端限制到批准资源；不挂载混合研究、IM 数据、历史会话和共享检索缓存，不开放任意浏览或文件读取 |
| 参考整理者 | 原创冻结后取得 IM 指定版次及相关材料，按既定标准建立对照范围 | 不参加冻结前的原创提示、内容修订或教师反馈；资料完整性和不可比项如实记录 |
| 匿名评阅者 | 来源标识已隐藏的材料、共同任务条件、事先冻结的评分标准 | 不见作者／系统名、期望优胜者、生成历史和参考整理者的倾向性分析；实际数学内容不能为了隐去风格而被改写 |
| 实验组织者 | 来源、版本、身份映射及隔离日志 | 可以知道身份，但不冒充盲评员；在评分冻结后才揭示身份并组织改进 |

这是一组实验职责，不要求产品中建设四类常驻 Agent 或四套服务。优先复用 Harness 自身的 Context 装配、资源访问范围、任务状态和记录能力；本次只配置原创与比较各自可取得的资料，冻结产物并另行匿名评阅。信息边界须在工具返回与资源访问时落实，不能只写一句“不要看 IM”。

### 两个容易漏掉的入口

**本地 Learning Commons 不自动等于无 IM 信息。** 原创侧仅使用来源可核对的独立标准、组件与适用关系；排除 IM 的课程层级、课程依赖、课程对齐、Narrative、任务及其衍生描述。误解、学习进阶和其他记录也要按实际来源核查，不能只按实体类型放行。来源混合或不能确认时，本次隔离实验暂不用该记录，记录影响；不是重做数据本地化，也不是生产 Harness 永久禁用这些知识。去掉 IM 名称但保留其结构或内容仍构成泄漏。

**原 Skills 的数学流程存在 IM 入口。** [知识查询原文](../../../k12-teacher-skills/plugin/skills/k12-lesson-plan-creation/references/learning-commons-kg.md) 明确要求查询 IM 课时并取活动顺序等，清理名称不等于参考隔离。此次原创实验需采用有记录的资源与规则适配：保留目标、实际任务、求解、教师参与、同源材料及检查的教学目的；不把 IM 特有课程结构或已有 IM 方法论摘要喂给原创模型。能由独立标准或一般执行责任支持的要求，单独说明依据；不把来源洗成“通用原则”。原源码和详细分析继续完整保留。

四项 Skills 的固定上游基线在独立实验之外保留；使用完整上游规则的比较在原创冻结后进行，标注资源差别。这一严格隔离条件下的改造版本不能冒称原封不动的 Skills 基线。

## 完成后的比较与改进

先固定评分维度、完整性要求、参考版次选择规则和匹配方法；原创冻结后才读取 IM。按目标与前提匹配，不按 Unit／Lesson 编号或课名匹配。若内容散布在数个单元，保留原有邻接背景，并报告范围差异，不能拼成一份 IM 原本不存在的“同款单元”。不能按看起来谁更好挑选参考版次或片段。

两项比较分别回答：

- **体系与单元设计质量：** 目标覆盖是否合理，先备与后续是否连贯，理解进程、任务和评测能否互相支撑。原创只有全年蓝图时，只比较对应设计层面的证据，不声称全年教学质量优于 IM。
- **实际教学材料质量：** 数学正确、表征意义一致、推理任务真实、解释与学习证据充分、支持保留目标、师生材料可用、教师准备负担与时间资源要求合理。没有看见的材料记“证据缺失”，不推定不具备该能力。

数学实质错误、核心目标没有学习机会、关键产物缺失等单列，不让文风和排版高分抵消。先各自按共同标准独立评阅，再做匿名成对比较；交换展示顺序，记录具体题面依据、分歧和评阅者是否识别来源。尽量由至少两位未参与设计的数学教育评阅者独立判断；尚无合适人选时，模型评分仅作初筛，不宣称教师校准或教育效果已证实。

课时、先备或资源不同就分别报告，不能给未使用同一条件的成熟教材制造一个虚假的实验对照。现有 IM 内容的生成耗时与模型运行耗时不具备对等含义；Harness 的时间、费用、修订成本另评。只比较教学内容不能证明 Harness 达到 Skills 的真实交互和执行能力，两条证据线分别保留。

建议版本关系：原创初稿 A0 → 在隔离条件下检查与修订后的 A1（冻结）→ IM 参考 R（此时才进入）→ 匿名评分（冻结）→ 揭示来源与分析 → 改进版 B。B 明示参考影响，不再作为盲原创成绩。针对比较中暴露的问题改进 Harness 后，还需用未参与调优的任务验证，不能在同一单元反复修补后宣称普遍提升；一个单元也不代表所有数学分支。

## 当前讨论需收敛的边界

- “整体方案”建议包含八年级全年蓝图及必要前后年级衔接，而不是完整 K–12，也不只是一段抽象教学理念。
- “Unit 4”建议作为内部工作标记；是否最终排第四由独立课程设计及真实学校约束决定。若用户指定必须第四，作为外部约束记录，不能借此回查 IM。
- 核心标准、已有学习条件和时间／资源预算应在实际设计前固定；没有真实学校输入时采用明确的研究设定，教师负担评价与课堂效果仍另取证。

本文是讨论方案，不改变 README 的已定产品范围，也不代表正式接口、课程顺序、模型选择或全部评测门槛已被采用。
