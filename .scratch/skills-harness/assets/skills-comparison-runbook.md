# 上游 Skills 真实运行与同条件比较方法

日期：2026-09-16。本文核对固定上游源码，回答怎样取得真实 Skill 产物、怎样与本项目比较。当前只完成只读研究与执行准备，没有运行生成模型、生成参考教案或声称已完成 A/B。实验所用八年级、`8.F.B.4`、50 分钟、28 人是已有合成条件，不是新的学校事实、全年日历或正式课程层级决定。

## 先明确比较对象

上游固定版本为 `281eb8d41fe2837d911541c9bbb870b58add804c`，插件声明版本 `0.9.0`。实际只有四项 Skill：教案创建、已有课适配、教师备课、数学理解度检查。没有独立的全年课程、单元或 Section 生成 Skill。创建 Skill 的触发描述虽包含 `unit plan`，但正文交付约定仍是一次课的教案、学生材料和观察模板，不能据触发词把它当成全年课程体系生成器。[上游 README](../../../k12-teacher-skills/README.md)、[插件清单](../../../k12-teacher-skills/plugin/.claude-plugin/plugin.json)、[教案创建主规范](../../../k12-teacher-skills/plugin/skills/k12-lesson-plan-creation/SKILL.md)

当前产品请求只支持 `capability="curriculum_design"`、`scope="section"`，实际源对象也只有 Section。即使其中写了若干具体题目、解法和课堂分钟，它仍不能自动算作已实现的 Lesson 全套生成能力。[当前契约](../../../src/teaching_harness/contracts.py:84)

因此，当前三课段报告与上游一课教案包可以做**缺项和用途对照**，不能做同任务质量 A/B。也不能把三课段报告截出一课，再手工补齐学生页后称为产品自身产出。正式一课能力由 [单课材料实现票](../../math-harness-delivery/issues/03-continuous-lessons-and-materials.md) 承接，随后才满足 [创建对照票](../../math-harness-delivery/issues/11-skills-comparison.md) 的依赖。

## 原版教案创建究竟要交付什么

### 实际执行链

1. 读取主 Skill 和完整数学参考，识别年级、目标、课程信号与课堂条件。
2. 必要澄清与“直接完整包／先看草稿”的选择一起处理。明确给定的本次选择可作为实验输入，不能伪造后续教师回应。
3. 按实际连接条件取得知识；已连接时，草稿和完整包都要经过规定查询。
4. 设计整课：实际题目、解题核对、讨论、误解及应对、学生表现、时间、退出题和材料安排。
5. 完整包路径读取 `output.md`，写同一份 `lesson.json`，调用原渲染命令，核对每份实际文件。草稿路径先在聊天展示可审阅的实际任务，等真实放行后才制作材料。
6. 交付整套 Word 文档和必需附件，邀请具体修改；修改回到共同源内容并重新生成全部受影响文档。

这里是对固定原版的复核，不是要求本产品永远复制其每项交互。[主 Skill 的步骤 0–5](../../../k12-teacher-skills/plugin/skills/k12-lesson-plan-creation/SKILL.md)、[已有详细流程](lesson-creation-execution-design.md)

### 产物与内容清单

| 对象 | 原版要求 | 第一轮实际检查 |
| --- | --- | --- |
| 教师教案 | 年级、标准原文、分钟、材料、Big Idea、可观察目标、先备、词汇、困难与教师动作、教学过程、设计说明 | 读完整教案，实际求解全部题目，核对每个阶段的学生工作量 |
| 学生材料 | 学生真实要读、做、写的题面、数据、表征与作答空间；教师答案和观察提示不混入 | 独立打开学生文档，检查能否只凭学生页完成任务 |
| 教师观察模板 | 目标相关的可观察行为、困难、记录空间和退出题分拣标准 | 不能只有一张泛化空表或课堂阶段名称 |
| 必需附件 | 本课依赖的卡片、模板等随包提供；形态特殊时可另用适当格式 | 教案说要用的材料必须实际存在或有明确可用来源 |
| 可编辑源与内部预览 | 一个 `shared` 内容注册表加 `documents[]`，每份文档由共同源生成；DOCX 是教师交付物，HTML 和 JSON 是工作文件 | 同时保存源、Word、预览和文件指纹，检查师生题面与数值一致 |
| 对话与修订证据 | 初始选择、实际草稿、回应、交付消息、具体修改与重生成 | 没发生的草稿协作不记为通过，生成后的修改邀请也不等于已取得教师满意 |

学生材料只在确属全程口头或教师主导、不需要学生纸张时允许省略；本次线性函数书面任务应检查真实学生页。原版要求至少一项有教学理由的视觉支架，常用表格、数轴或待填表；不能由“有图形”一项替代任务与表征的数学检查。[数学参考](../../../k12-teacher-skills/plugin/skills/k12-lesson-plan-creation/references/math.md)、[输出规范](../../../k12-teacher-skills/plugin/skills/k12-lesson-plan-creation/references/output.md)

原文还明确：通用渲染器不能直接绘制任意图片，默认 Schema 提供表格、数轴等块。因此不能要求原版必然产出与当前 Harness 相同的 SVG，再用文件格式差异代替教学判断。若任务依赖坐标图，要检查它怎样交付可用图形、来源或附件，不能接受教案里的空口指令；若新增图件工具，记入宿主适配清单。[输出规范的 Schema 与补充产物](../../../k12-teacher-skills/plugin/skills/k12-lesson-plan-creation/references/output.md:166)

## 怎样真正运行原 Skill

### 宿主与依赖

Skill 是指令、资源和渲染脚本的组合，不是一个执行 `SKILL.md` 就会自行启动模型的程序。上游 README 给出两种入口：Claude for Teachers 的内置技能；其他宿主手动加载插件或技能，以 Claude Code 为例。为了固定源码，本次应使用本地固定子模块，而非把持续更新的在线内置版本当成同一基线。[上游安装说明](../../../k12-teacher-skills/README.md)

下面是**后续执行者可用的安装命令说明，本轮没有执行**：

```bash
claude plugin marketplace add /Users/libo/Mathematics/k12-teaching-harness/k12-teacher-skills
claude plugin install k12-education@k12-teacher-skills
```

随后在独立输出目录和新会话中显式运行 `k12-lesson-plan-creation`，给它共同任务书，并保存实际加载来源、宿主和模型的精确版本。不要把开发仓库的整段历史、之前 Gemini 课段、参考答案或评分反馈加入生成会话。Claude for Teachers 可作为另一种整套产品体验样本，但若无法取得其内置 Skill 版本和隐藏宿主条件，就不能称为固定子模块的精确复现。

若先看上游自带的**无 KG 分支**产物，可在确认该独立宿主没有开放 KG 工具后发送以下请求。这里仅提供操作文本，本轮未执行：

```text
使用 k12-lesson-plan-creation。
加载固定技能：/Users/libo/Mathematics/k12-teaching-harness/k12-teacher-skills/plugin/skills/k12-lesson-plan-creation/SKILL.md，并完整遵循适用参考与原渲染流程。
读取共同任务书：/Users/libo/Mathematics/k12-teaching-harness/.scratch/math-harness-delivery/comparisons/lesson-creation-01/brief.md。
只将“给生成方的任务”作为教学输入；“执行者记录”不是答案或评分反馈。
本次宿主未连接知识图谱，请采用原 Skill 的无 KG 分支，在教案中保留规定说明。
直接生成完整包，实际检查全部交付文件；保留源文件、修订及运行记录。
输出放在本次新建的独立目录，不读取旧 Section、其他生成方的材料或目标 IM。
```

完整连接版本不能照抄这段无 KG 条件，须先核对下文工具与参考时序；如果采用 Gemini 适配宿主，也须在运行身份中写明适配版本。

| 依赖 | 原版需要什么 | 当前核查结果 |
| --- | --- | --- |
| 模型宿主 | 能读 Skill 资源、调用工具、写文件、执行脚本、保持多轮对话 | 仓库只提供技能；未提供独立模型 runner，也未固定 Claude 模型名称 |
| 文档执行 | Bash、Python 3、`python-docx` | 原 `render_all.sh` 在缺少 `docx` 时尝试安装 `python-docx==1.1.2`；安装失败只留 HTML 并返回失败，不能把这记为完整 Word 交付 |
| 图件与材料访问 | 本任务所需的真实文件／资源能力 | 原块格式本身不涵盖任意图片；需按具体任务核对，不能只看提示中有工具名 |
| 知识连接 | 完整连接分支所需工具和真实数据 | 当前会话只发现标准、组件、进阶三个 LC 工具；尚未发现误解、课程课时、课时材料三个必需工具 |
| 人类交互 | 实际操作者对草稿、取舍和修改作出回应 | 合成回应脚本可测控制路径，但必须标为合成，不能算教师试用 |
| 评价 | 另行提供 judge／人工评阅、文件读取与保存 | `evals/` 没有现成 runner、模型接口、案例数据集或完整自动评分命令 |

依赖证据：[原渲染入口](../../../k12-teacher-skills/plugin/skills/k12-lesson-plan-creation/scripts/render_all.sh)、[上游 evals 说明](../../../k12-teacher-skills/evals/README.md)。当前会话工具盘点只是 2026-09-16 的可调用范围，不能据此断言 LC 数据源中不存在相应数据。上游 [`plugin/.mcp.json`](../../../k12-teacher-skills/plugin/.mcp.json) 也未配置 LC，安装教学插件不等于已经连上 LC。

原版制作完 `lesson.json` 后，实际执行入口是：

```bash
bash /Users/libo/Mathematics/k12-teaching-harness/k12-teacher-skills/plugin/skills/k12-lesson-plan-creation/scripts/render_all.sh /绝对路径/lesson.json /绝对路径/本次输出目录
```

此命令负责排版已有内容，不会生成教案。运行前应准备依赖；运行后仍须回读文档、查看分页和图表，并保存生成失败。独立执行时应检查是否继承了上游 `OUTPUT_DIR` 环境变量，以免原脚本把输出额外复制到其他任务目录；不需要读取或记录任何密钥。

### 三种知识条件必须分别命名

1. **固定原版、完整 LC 连接。** 数学路径先解析标准，再查前驱、组件、误解和 IM 课时，随后取该课时的 lesson／activity 材料。SMP 可从模型知识选择。当前只有标准／组件／进阶三个能力，不能声称完整复现。
2. **固定原版、无 KG 分支。** 这是上游自带退路；使用模型知识并在教案加入无 KG 说明。应在工具确实不开放的独立宿主运行，不能一边提供部分 LC 工具，一边偷偷跳过其余规定查询。结论仅覆盖“无 KG 原版”。
3. **固定规则、受限或映射后的工具。** 若用本地 HTTP 补齐旧工具，须记录身份映射、查询语义、真实源数据与版本；若禁止 IM、删掉工具或改成预装知识，须称为受限适配版本。不能把它的失败算作完整原版失败。

以上依据：[原数学 KG 调用序列](../../../k12-teacher-skills/plugin/skills/k12-lesson-plan-creation/references/learning-commons-kg.md:25)。是否能够补齐本地误解与课时材料数据，本次未验证；不得先写成已经可用。

## 两类比较能证明什么

| 比较 | 固定条件 | 能说明什么 | 不能说明什么 |
| --- | --- | --- | --- |
| 固定原 Skill＋Claude 宿主，与本产品＋Gemini | 同一任务书、相同目标与课堂条件，完整记录工具／资料／交互差异 | 两套具体系统在该条件下交付了什么、哪里缺失、使用体验差在哪里 | 差异全部由 Harness 编排引起；也不能只因一个样本较好就宣称普遍更强 |
| 固定原 Skill 教学规则＋Gemini 适配宿主，与本产品＋同一 Gemini | 精确模型版本、参数、相同知识范围、可比工具和相同任务／回应条件；适配改动列表可审阅 | 更接近比较规则装配、工具和流程组织的影响 | Gemini 运行等同原 Claude 体验；宿主适配没有影响；没有正式 Lesson 端点也已完成产品 A/B |

同模型版本需要实际的 Skill 执行宿主：加载原资源、实现规定工具、提供文件和渲染能力、保留其交互与修订。不能把原 Skill 总结成短提示，再调用一次 Gemini 就声称“原版已跑”；也不能把现有 Section 端点换一个提示词，冒称新增 Lesson 生产能力。[既定验证路线](validation-and-release-route.md#skills-与-im-分别怎样比较)

资源条件必须先记录。当前项目明确不设默认累计 token 预算；本轮先充分完成材料和必要修订，记录实际消耗。不为使一方看起来便宜而提前截断。需要研究等预算效果时，另行定义实验并同时报告被截断的任务。[README 的质量与消耗原则](../../../README.md#设计与协作原则)

## 共同输入至少包含什么

共同任务书应独立于任一方现有答案。本轮由主核查准备单课 brief，标为**外部提供的合成单课实验任务**，不补造正式 Grade／Unit／Section 上层。

| 字段 | 本轮应明确的内容 |
| --- | --- |
| 任务身份 | 实验 ID、版本、来源为 synthetic；任务是单课新建，不是三课段设计或改写原课 |
| 标准与本课范围 | CCSS Mathematics、八年级、`8.F.B.4`、真实标准原文；具体本课目标与未承诺覆盖的范围必须写明 |
| 时间与班级 | 50 分钟、28 人均为合成约束；是否包含发材料和转换时间 |
| 先备 | 已有能力只能来自任务书；不把图中的前驱自动当成28名学生已掌握的证据 |
| 课堂资源 | 可用设备、纸张、打印与作答方式；未给信息允许注明假设，不编造学校库存 |
| 学习者条件 | 给定的阅读、语言或支持需要及来源；没有诊断信息就保持未知 |
| 课程关系 | 本次没有已批准的正式上层课程；不要写“已在第几个单元验证过”；未指定 IM 不等于原版内部不查询 IM |
| 交付与语言 | 同一语言要求、完整可用教案与师生材料、观察与退出检查；原版交付格式和本产品格式差异单列 |
| 本次选择 | 完整包／草稿路径的实际选择与来源；只提供当前有效决定，不预写未来“满意” |
| 知识条件 | 完整连接、无 KG 或受限适配版本，源快照、可用工具、允许与禁止资料 |
| 评价条件 | 生成前固定 rubric 版本和适用范围；不把后续答案、评分解释或另一方产物送入生成上下文 |

原数学 Skill 要求单课覆盖目标标准的结构情形，而本项目允许通过课程层级分配目标。因此若共同 brief 只覆盖 `8.F.B.4` 的一部分，必须在结果中同时保留原规则覆盖判定和本课目标判定，不能把两者混成一个分数，或事后删掉对本产品不利的条款。[数学 Problem set 要求](../../../k12-teacher-skills/plugin/skills/k12-lesson-plan-creation/references/math.md:49)、[既有规则取用](../experiments/grade8-linear-functions/evaluation-and-adoption.md)

## 第一轮怎么执行与结束

### 当前可以立即完成的准备

1. 冻结共同 brief、上游 commit、原 rubric、能力／依赖清单和比较名称；保留当前 Section 样本身份。
2. 为每条执行臂准备独立会话和产物目录，确保产品生成端读取不到原版输出或 IM 资料；记录模型精确名称与运行配置，密钥只由宿主使用。
3. 核实完整知识路径是否可用及是否符合下文 IM 时序。不足时明确选定无 KG 或受限版本；不能混用名称。
4. 在当前 Lesson 产品能力未交付时，可以准备或按已授权条件运行上游样本，取得基线产物；报告写“上游样本／执行方法试运行”，产品对应臂写“尚未实现／未运行”。这时不生成胜负排名。

### 有可比 Lesson 执行端之后

5. 各臂读取同一 brief，使用约定的直接完整包路径。若上游仍提出选择，保存真实操作者回应；若使用预先脚本，标明它是实验输入，不是真实教师试用。第一轮不自动扩展成全部草稿、适配和备课流程。
6. 保存原始对话、工具请求与结果、每次实际产物、修订和模型用量；文件渲染失败或未完成也保存，不只挑选成功结果。
7. 冻结生成产物，然后由独立评价者打开完整教师、学生、观察材料，按 `shared.csv` 的 33 条与 `math.csv` 的 6 条逐项检查。对话行为依据真实聊天判断，材料要求必须在文件中存在。条件不适用依原 rubric 规则处理；缺一整份材料不能改记不适用。
8. 另列本项目采用规则的结果、数学实质错误、课堂工作量、受众泄题和图件可用性。每项结论给实际题目、页码／对象及理由；总分不能抵消严重缺陷。
9. 匿名材料包用于独立评阅；保留身份映射、分歧、误报及人工裁定。一个案例只形成差距清单和试运行结论，多次复现和数学教育评阅校准之后才讨论稳定能力。

评分方法依据：[上游 evals README](../../../k12-teacher-skills/evals/README.md)、[shared rubric](../../../k12-teacher-skills/evals/k12-lesson-plan-creation/rubrics/shared.csv)、[math rubric](../../../k12-teacher-skills/evals/k12-lesson-plan-creation/rubrics/math.csv)。`evals/` 是评分资源，不是已运行的评测系统；要另行实现调用或交给现有 judge。模型评价、程序计算和人工评阅分别标记，不能由一次模型自评代替独立验收。

## IM 参考的输入隔离与当前时序

原版数学完整连接流程**即使教师未确认使用 IM，也会取得相应 IM 课时／活动材料**，只是去掉对外的专属名称并禁止原文复制。故不能把“产出未出现 IM 名称”当成没有参考污染。[原 KG 数学步骤 5](../../../k12-teacher-skills/plugin/skills/k12-lesson-plan-creation/references/learning-commons-kg.md:44)

现行 [创建对照票](../../math-harness-delivery/issues/11-skills-comparison.md) 和 [四项对照票](../../math-harness-delivery/issues/19-four-capability-comparison.md) 更进一步规定：完整原创 A 冻结前，不运行需要目标 IM 材料的案例。因此，当前 `8.F.B.4` 完整连接原版需要按这条时序处理；仅另开隔离目录并不足以撤销已定条件。本轮先准备共同 brief 和执行方法，不擅自改变该决定。

可区分的后续路径是：

- 在既定时序允许后，运行目标的完整连接基线，并保持其生成上下文、输出和评阅与原创分离。
- 使用上游自带无 KG 分支作明确标注的无 KG 样本，或选择不涉及目标参考、又能完整满足上游要求的其他案例；不能把该结果冒称完整连接目标案例。
- 若用户明确改变参考顺序，先记录这项范围调整和受影响的原创声明；此后不再把已经看过目标参考的产物称为此前隔离条件下的原创。

原 Skill 的通用教学方法与“某个目标 IM 单元／课时的具体内容”不是同一东西；可保留前者作为开发基线，但不能将具体参考题目、活动顺序或参考产物回灌到仍宣称输入隔离的课程生成中。

## 其余三项 Skill 各自怎样比较

| 能力 | 公平的共同输入 | 要比较的实际对象 | 不能拿什么替代 |
| --- | --- | --- | --- |

## 当前诚实的交付口径

当前已有 Section 实现和样本，上游完整 Lesson 基线尚未在本轮运行，产品正式 Lesson 全套能力尚未交付。可以展示上游要求、现有产物缺项、共同实验任务书和真实执行前置条件；不能说已经比较过 Skill 实际效果，也不能把 Section 中出现 Lesson 细节视为双方可比的充分条件。

本报告新增的是可执行的方法与缺口清单。实际基线产物、可重复命令的运行记录、同条件 A/B、真实教师参与和统计性结论，均须在分别发生后补证。
