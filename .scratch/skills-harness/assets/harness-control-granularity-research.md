# 强模型下的 Harness 控制粒度：依据与待验证判断

日期：2026-09-14。性质：一手资料研究；不是生产架构规格，也不是本项目模型实验结果。

本次问题是：课程修订原型把情况分得很细，这些区别应留在评测案例中，还是应成为运行时分支？讨论承接 [README](../../../README.md) 的独立数学课程与教学设计目标，不重新讨论是否需要 Harness。已有流程参考继续保留，具体执行粒度接受效果检验。

## 一手资料核查

以下六项均于本日打开原文。工程博客反映作者及团队在相应任务中的经验；框架文档说明能力和机制，两者都不能证明本项目已经达到教学质量要求。LangGraph 使用本日在线文档，尚未锁定本项目依赖版本或运行服务器实验。

### S1：简单结构是起点，增加复杂性需要收益依据

**来源事实：**Anthropic 将预定代码路径与模型动态选择行动分别称为 workflow 和 agent；建议从能满足任务的简单方案开始，只在复杂性确实改善结果时增加。开放任务可采用模型依据工具反馈持续行动的循环，配合停止条件。固定分解则适合能清晰拆成固定子任务的工作。[Building effective agents，2024-12-19](https://www.anthropic.com/engineering/building-effective-agents)

**适用限制：**这是跨行业工程经验，不是教学任务的对照试验。原页现已注明工具生态发生变化；本文只采用结构取舍原则，不沿用其中的框架或型号建议。

**本项目可检验的推论：**应让较简单的模型与工具循环参加比较，不能仅因能够列举失败情形，就认定每种情形需要独立处理器。

### S2：应减少脆弱的情形枚举，保留足够的任务信息

**来源事实：**Anthropic 建议先用强模型测试最小但充分的提示，再依据失败补充指令；明确反对向提示塞入冗长边缘案例清单，建议使用有代表性的多样例子。它同时警惕过细的条件逻辑与过于空泛的指导，并将按需读取资源视为可选方法。[Effective context engineering for AI agents，2025-09-29](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)

**适用限制：**“最小”不等于截短教学规则或只传摘要。该文没有证明任何固定 Context 长度、案例数量或自主程度适合本项目。

**本项目可检验的推论：**原 Skill 的教学目的、真实内容和必要资源应充分可读；原型的全部按钮和反例不应自动变成每次调用必读的分支手册。

### S3：模型升级后，部分执行支架确实可能失去作用

**来源事实：**Anthropic 的应用开发实验随模型改进去除了先前使用的会话重置、sprint 分解，并减少评估频率；仍保留有帮助的规划和检查。作者报告，曾一次大量删改而无法判断各部分作用，随后改为逐项移除、观察最终结果。[Harness design for long-running application development，2026-03-24](https://www.anthropic.com/engineering/harness-design-long-running-apps)

**适用限制：**这是应用开发案例，不是等预算、固定任务范围的教学比较；不能借其结果断言课程规划、数学检查或 HITL 可直接省去。

**本项目可检验的推论：**“该控制补偿了模型什么不足”应成为可反驳的假设；更换模型或 Context 后需要重测。逐项增减比整套重写更容易定位收益，也避免误删仍有价值的原 Skill 机制。

### S4：评测应容纳多条有效路径，并检查过度触发

**来源事实：**Anthropic 区分执行记录与真实最终状态，建议多次尝试；反对把特定工具调用顺序普遍当作成功条件，因为模型可能找到其他有效解法。案例集应同时包含某行为应发生和不应发生的情况；模型评分需要与专家判断校准。[Demystifying evals for AI agents，2026-01-09](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)

**适用限制：**产物导向不取消任务本身具有意义的过程条件，例如真实教师亲做、等待真实回应与信息隔离。合成用户也不能证明真实教师的使用体验。

**本项目可检验的推论：**“不先删课、直接设计出符合约束的方案”应允许成功；“所有修改都要求教师批准”应计入不必要打断，而不能因等待次数多就判为可靠。教师亲做等条件按原教学目的单独评价。

### S5：选用 LangGraph 不要求把每个场景编成节点

**来源事实：**LangGraph 的官方指南同时展示预定 workflow 与动态 agent；后者由模型确定过程和工具使用。指南为两类结构提供持久化、流式输出和调试等支持，并展示模型与工具交替执行的基本 agent loop。[Workflows and agents，本日在线版](https://docs.langchain.com/oss/python/langgraph/workflows-agents)

**适用限制：**示例说明可实现性，不给出本项目最优节点数，也未证明多 Agent、固定阶段或自主循环哪种教学效果最好。

**本项目可检验的推论：**既定技术方向与简单模型循环兼容。“用了 LangGraph”不能作为增设删课、改图、移任务等专属节点的理由。

### S6：运行承载具有独立职责，并已有框架实现可复用

**来源事实：**LangGraph checkpointer 在 super-step 边界保存线程状态，以支持恢复、人类介入和故障容忍。文档说明 Agent Server 承担 checkpoint 基础设施；还列出同步、异步与退出时持久化的性能和恢复取舍。Replay 会重执行指定 checkpoint 后的节点，包括模型调用和 API 请求。[Checkpointers，本日在线版](https://docs.langchain.com/oss/python/langgraph/checkpointers)

**适用限制：**保存图状态不自动定义课程内容版本、教师决定的语义或外部产物的提交规则。具体部署和故障行为仍需技术专项及原型验证。原 `durable-execution` 文档地址本日跳转至 `persistence`，其导航现指向本页；实施时应重新核对版本。

**本项目可检验的推论：**模型自主选择教学动作，与程序保存真实状态并不矛盾。应先复用运行时能力，再确定应用必须补充的领域记录；不能把“需要恢复”推导为每种教学场景都必须自建状态机。

## 本次外部研究能支持到哪里

六项资料共同支持一种设计方法：保留具体任务和充分 Context，先比较简单实现；额外的路由、阶段分解、检查调用与修订规则，应说明其解决的实际失败及增量收益。它们没有证明当前强模型已能可靠完成本项目，也没有证明原型中的每项区分都必需。

因此应把“模型能否理解和修订教学内容”“程序是否忠实保存和执行真实事件”“更细控制是否值得其成本”分开取证。现有页面只可提供有限状态案例，真实模型在自然语言任务上的效果仍需另外验证。本地代码审查、候选比较与实验判据在下文补充；不以这些来源替代实验。

## 本地审查：哪些结论需要收回或收窄

**目前有过度设计风险，还没有证据证明当前控制粒度必要。** 这不是推翻 Harness 的目标，而是检验实现手段。复杂性也可能降低质量：模型为通过阶段门槛形成形式化材料、多个检查互相重复、局部修复被迫绕远路、过度等待教师，以及程序按预设错误分类漏掉未见过的问题。以上是需要验证的风险，不是已观察到的产品故障。

1. **原结构比较不充分。** [执行结构分析](execution-structure-design.md#先比较执行方式) 原先将简单方案描述为“一个长程 Agent＋一份长历史”，未比较同样具备充分规则、按需 Context、工具及必要运行承载的简洁 Agent 循环。已补入这一候选。仅排除无限聊天和逐条节点，不能证明中间方案最适合本项目。
2. **原型验证的是人为规则的一致执行。** [HTML](../prototypes/curriculum-state.prototype.html) 的 `findings()` 预设教学发现，`signatures()` 手工声明哪些字段影响哪些检查，`patches` 预设修改。11 场景／65 步没有模型调用，不能估计错误率、漏查率、修订能力或干预收益。原型里修正过的状态逻辑问题是真实代码问题，但不能反推模型需要更多教学分支。运行范围见 [原型记录](curriculum-state-prototype-notes.md)。
3. **检查适用性要求不等于精细缓存算法。** 当前版的实际内容需要适用的检查；但可以先以课时、材料包及有关上下游为范围重查，再根据成本证明是否值得追踪更细依赖。重查不等于重生成，也不等于使未变化范围的真实决定自动失效。仅凭模型说“无影响”不能复用检查，程序列出了依赖也不能证明依赖完整。
4. **多人事件语义不等于自建学校审批引擎。** [HITL 设计](hitl-design.md#旧版改意和并发) 要求保留冲突、遵守外部权限，未要求本仓库设计整套组织审批规则。候选可消费外部可核验的决定及其依据；规则缺失则返回具体缺项。不能默默把多人需求改成单人，也不应从甲乙演示推导出通用会签产品。

目前没有生产实现，因此这里纠正的是设计推论和后续取证顺序，没有删除已经证明有效的实现。原 Skills 的细致规范与流程分析继续完整保留；**保留教学步骤，不代表要用程序逐步强制调度它们。**

## 场景、教学规则和运行控制分别放在哪里

| 当前例子或责任 | 较简单的候选实现 | 何时值得增加控制 |
| --- | --- | --- |
| 压缩课时、描轮廓代替构造、改变练习数域 | 由本能力规则说明需保留的目标和认知要求；给模型实际任务、知识关系与约束，让其查证、设计和修订。例子留作评测，不建同名处理器 | 真实样本反复出现同类缺陷，且改进资源、工具或指令仍不能解决时，比较专门检查是否有效 |
| “只改给我看”与“改好直接生成” | 模型结合原请求解释自然语言；程序读取真实输入、目标对象和已有授权，执行允许动作 | 对歧义和误执行分别测量，不能把所有短回复都转成确认，也不能仅靠模型声称已获授权 |
| 教师亲做、草稿放行、CFU 焦点及隔离读题 | 按各能力保留有教学目的的参与与信息边界；模型负责内容和对话，程序承载真实等待与可见范围 | 这些目的本身已有源码与采用依据；是否还要更多节点、检查者或重复审阅，另行比较 |
| 版本、真实事件、取消、重复提交、预算及交付记录 | 优先复用既定框架的存储和运行能力，补足本项目对象及作用范围；执行端验证真实结果 | 不能因模型更强省略这些职责，但具体存储粒度、幂等机制和恢复实现需运行专项证明，不能照搬浏览器 reducer |
| 精细检查复用、自动传播全部语义依赖、多人意见累计 | 先比较较大但有界的重查范围，沿外部决定规则处理人类输入；保留真实证据和原始内容 | 成本、延迟或用户负担确实成为瓶颈，并能证明细化不会增加漏查／误用时再实现 |

第三行的源码例子：教案创建 [Step 4](../../../k12-teacher-skills/plugin/skills/k12-lesson-plan-creation/SKILL.md) 区分草稿与整套，数学 [构建与验算](../../../k12-teacher-skills/plugin/skills/k12-lesson-plan-creation/references/math.md) 指导模型完成实际教学工作；[prep 主规范](../../../k12-teacher-skills/plugin/skills/k12-lesson-prep/SKILL.md) 要求真实任务及教师先尝试。这些规范不能用“模型能力强”直接删除。具体产品采用仍按 [执行决定](../issues/03-execution-structure.md) 和 [HITL 决定](../issues/07-hitl-protocol.md)，原规范的固定 IM 形式不因此恢复为产品要求。

程序和模型之间也不是按“简单／困难”划分：模型可以判断是否可能丢失学习机会，执行端却无法仅凭 JSON 合法证明判断正确；模型可以理解加时授权，实际提交和权限仍由可信系统提供。教育判断需要内容证据，运行事实需要真实记录。

## 用一次有限比较判断，而不是继续扩充场景台

以下是交给 [能力验证](../issues/05-capability-validation.md) 的候选实验，不是已完成结果，也不要求先建整套生产服务。保持单元贯通方向；先用同一批真实课程及自然语言修改做窄比较，再检验优胜机制在完整单元生成中的表现。局部修订成绩不能单独证明课程体系设计能力。

**按用户后续明确的克制原则推进：**先运行 S，观察其在充分 Context、工具与必要保障下的实际表现。只有出现具体缺口，或明确义务需要更强机制，才投入对应的 G 控制或单项增减并做同条件比较；不为比较本身先建设两套完整架构。内置知识、检索与本次事实的分工见 [Context 设计](context-and-llm-design.md#模型内置知识与任务证据怎样协作)。以下列出的是可比较的变量，不是要求全部实现的清单。

| 变体 | 改变什么 | 共同保留什么 |
| --- | --- | --- |
| S：最少程序控制 | 教学工作顺序主要由相同能力规范指导模型；模型在有界工具循环中选择读、设计、试做、检查与回修 | 必要的真实事件／权限保护、信息隔离、内容快照、实际检查与交付证据、预算和停止；充分适用规则与资源 |
| G：候选粗阶段控制 | 将选定的工作交接由指令要求变成程序要求，例如先保存关键任务试做证据，再展开更多课时；可在阶段内自主行动 | 与 S 相同的教学目的、内容、工具、必要保护与验收标准；不能靠增加教学要求或删除失败指标制造优势 |
| 单项增减 | 只对 S／G 已观察到的具体问题增加或移除一项，例如检查频率、独立检查调用或检查复用 | 其他条件尽量固定，记录额外成本与新失败；不先实现全部精细分支 |

S 与 G 都可以使用 LangGraph；比较的是控制程度，不是框架品牌。若现有粗阶段最终只包含不可省的信息与真实事件边界，S 与 G 可以收敛为同一实现，不为了比较再造两套架构。此处 S／G 命名与项目原创 A／参考 R／修订 B 的 IM 对照无关。

**输入与公平性：**固定具体模型版本和配置、适用规范、初始课程、知识快照、学校及学习者条件、工具权限、交付范围和预算上限。不同接入类别分别比较，不能用更强模型的 S 与更弱模型的 G 判断控制收益。Context 的可用信息相同；若主动分段装配就是待测变量，记录分段差异与实际读取内容。每个任务重复运行，隔离前次产物和评价答案。先用少量代表任务发现大问题，再按观察到的差异和波动扩样；未确定统计能力前，不凭几个成功样本宣布等效。

**同一需求要容纳多条成功路径：**把真实请求“压缩课时、保留目标”交给模型，不给“删课与容量”场景名、不强迫先删除唯一构造机会。模型能一次设计合理方案应判成功；缺少目标对应任务或伪造时间依据仍应判失败。原型给定的 20＋10 分钟不能证明所有合并方案不可能。若需要验证检查器识别已知错误，可以另给受控缺陷材料；该结果只说明检测能力，不说明模型自然生成这种错误的概率。

取样同时包含需要干预与无需干预的近似情形，例如真正改变任务要求与只改版式、目标内可修复与确需超出授权、尚缺决定与已明确“修改后生成”。留出不同措辞与未用于设计规则的数学任务；不强行用几何规则评判分数任务。事件重传、取消和迟到结果另做故障注入；这些运行样本不混进模型教学质量分数。

**评价与去留：**依 [上游评测说明](../../../k12-teacher-skills/evals/README.md) 和本项目采用范围，评实际数学任务、解法、认知要求、目标—学习机会—证据对应、材料可用性及修订保真；过程只评价有实际目的的要求，不要求走原型按钮顺序。同步记录错误遗漏、误报、不必要的人类等待、完成及修复情况、费用、延迟和新增维护负担。模型评分需用教育评阅者校准；暂缺真实教师时仅报告代理指标，不宣称改善教师负担或学习效果。

每一项额外控制至少留下：它要解决的失败及证据、较简单的替代、增量改善、额外成本及误阻塞、何时重测或移除。先修复 Context、工具或评分本身的缺陷，再把问题归因于模型能力。若效果相当则选更简单的；若差异尚不清楚，则保留不确定性，不给复杂方案默认通行。不能用“少等待”抵消必要教师贡献的丢失，也不能用平均总分掩盖关键数学错误或无授权执行。具体阈值在看比较结果前按风险确定，不事后挑选。

这里的证据也包括明确的产品义务和运行机制：取消后不得自行重启、真实回应不能由模型伪造，不需要先在学校发生事故才值得保护。要检验的是以多简单的机制兑现这些义务，而不是只按罕见事件出现次数决定是否保留。

## 当前推进结论

本次已完成源码与一手资料论证：**应保留细致的教学理解和有代表性的评测，避免预先细化成场景驱动的执行代码；新增控制承担证明增量价值的责任。** 当前需要的是让强模型在充分 Context 和必要运行保障下实际执行，再判断哪里必须加程序约束。
